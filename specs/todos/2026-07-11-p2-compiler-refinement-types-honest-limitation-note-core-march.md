The `t77` witness stays valid because it uses an *unrefined* callback type `f : Int -> Int` with an unrefined `x`, so nothing at the call site states the requirement — catching that needs either contravariant subtyping at the pass site or inferring `apply`'s own requirement from its body, both still open. This was already documented in `specs/lang/refinement-types.md`'s "Limitations" section before this slice; the slice's contribution is making it a mechanically-checked corpus fact (so a future change that silently narrows or widens this boundary shows up as a corpus regression) rather than only a prose claim. No runtime check is promised for ANY refinement (core-march-types.md §2.14's erasure rule), so an unverified indirect call is merely *unverified*, never *unsafe* — this is a completeness gap in the static analysis, not a soundness hole.
