`[P3]` Cluster record types still hold raw `Int` descriptors (2026-11-13; forgery closed 2026-11-13, migration open)

Ocap phase 2b, Task 9. The cluster plumbing (`NetKernel`, `ClusterConn`, `SessionNode`, `PeerRegistry`, `ClusterNode`, `NodeQueue`) is `@[stdlib_internal]`, but its record types still carry raw fds: `PeerRegistry.Peer { fd, data_fd }`, `ClusterNode.CnLink { cfd, dfd }`, `CnHalf { cfd, dfd }`, `NodeQueue.WriterState { fd }`, `SessionNode.Link { data_fd, control_fd }`.

This file used to say "user code cannot call it with a descriptor". That was false: a user module holding only `IO.Mut` built a `Peer` literal around a guessed fd and passed it to the public `SwimDriver.dispatch`, `DistLink.resend_pending` or `Node.send`, which wrote to a socket the program held; and it could `spawn(NodeQueue__Writer)` (or reconfigure the writer of `NodeQueue.start_local`) with `Configure(fd, ..)`. Both were closed by the phase 2b final review fix (C1, 2026-11-13; specs/progress/2026-11-13-cluster-records-unforgeable.md): `Peer`'s two fds are `PeerRegistry.Fd`, an opaque type only the stdlib can make (`PeerRegistry.make`, `raw_fd`, `raw_data_fd` are `@[stdlib_internal]`), and the actors whose messages carry raw fds (`NodeQueue.Writer`, `ClusterNode.CtlWriter`, `ClusterNode.ClusterNodeActor`) are `@[stdlib_internal]`, so user code can neither spawn them nor build their messages. `CnLink`/`CnHalf`/`WriterState`/`SessionNode.Link` reach I/O only through those actors and private functions; the public `ClusterNode.core_*` functions taking a `cfd`/`dfd` are pure state transitions whose effects only the internal actor performs.

What remains is the migration itself: the descriptors are still `Int`s inside the stdlib, and the records are not in the handle-unsendable list.

Expected: the fields hold `Socket` handles (adopted at the open), so a leaked record is not a descriptor and a cluster record cannot be forged with an arbitrary fd. This needs the cluster read/write loops moved from `NetKernel.*(fd, ...)` to `Socket` calls, or an opaque `Peer`.
