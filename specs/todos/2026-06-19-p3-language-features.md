# `[P3]` Language Features

- [ ] **External function interface (C-first ABI) — remaining gaps.** The 9-phase C-first FFI (ABI core, string/Option/Result marshalling, `resource`/`consume`, interpreter dlopen path, forge `[ffi]` build integration, `blocking fn`, `gen-c` codegen, record/variant/Option/Result/List codecs, native→March upcalls, the Rust `march` crate layer) is DONE — see `specs/2026-06-19-c-ffi-abi-design.md`, `specs/c-ffi-rust-layer.md`, and `specs/c-ffi-gaps.md` for the full history. Still open: `forge ffi import` (C header → extern block, needs libclang), recursive/generic types in generated codecs (currently passthrough), multi-lib `[[ffi]]` (array-of-tables, blocked on a TOML parser limitation — also blocks `[[ffi.rust]]` and Rust crate publishing beyond path-only), and an OCaml FFI layer analogous to the Rust one (designed-for but not built).
- [ ] **MCP server for March** — An MCP (Model Context Protocol) server that exposes March's type checker and compiler as tools for LLM agents. Post-LSP, pre-1.0. Would expose: typecheck a snippet, get type at position, search by type signature, expand typed holes.
- [ ] **Fixed-width SIMD vector types (`f32x4`, `f32x8`, `i32x4`, `i32x8`)** — part of the original SIMD/vectorization feature request but explicitly a separate, later increment from the `@[vectorize]`/`@[vectorize(warn)]` attribute (2026-07-31, see the Done entry above); the attribute checks `NativeArray.map`/`map2` auto-vectorization eligibility and does not depend on first-class vector types existing.
