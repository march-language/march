# `[P2]` Compiler: Parallelism + Clustering (found during Core March widening slices 9 + 10, 2026-07-10)

- [ ] **P1 — `Parallel.psum_float` is not backend-portable and must not be golden-compared.** IEEE-754 `+.` is not associative, so `preduce`'s differing chunk counts (the interpreter's worker count comes from `Domain.recommended_domain_count`, the compiled runtime's from the physical CPU count, and both differ across machines) can reorder the additions and change the last bit. The same caveat applies to any `preduce` with a non-associative `merge`. `psum_float` has no doc comment flagging this; the existing `test_rrb_vec.march` unit test happens to use binary-exact inputs (`[1.0,2.5,3.5]==7.0`) so it passes, but that is luck, not a guarantee. Deliberately EXCLUDED from golden `g43` (documented in `core-march.md` §4.14 + the golden's header). Fix options (optional): add a doc-comment warning on `psum_float`, or pin it to binary-exact float inputs. NOT a soundness bug — a documented non-portability. See §4.14.
