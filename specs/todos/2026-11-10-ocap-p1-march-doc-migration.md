# march_doc needs the ocap phase 1 migration before the stdlib-docs bot can run

Logged 2026-11-10 by ocap phase 1 (capability operations return `Result(T, CapError)`).

The stdlib API reference (`docs/docs/stdlib/`) is generated by the external `march_doc`
archive (github.com/march-language/march_doc), which `scripts/gen-stdlib-docs.sh` and
`.github/workflows/gen-stdlib-docs.yml` run with the in-repo compiler. march_doc is March
code that calls `File.write`, `Dir.mkdir_p`, `Dir.list`, `Dir.exists`, `Env.get`,
`IO.warn` and `System.exit` as plain values, so under phase 1 it no longer typechecks
(`march_doc.doc exited with code 1`). Until it is migrated, the bot cannot regenerate the
pages after a stdlib change.

Phase 1's PR regenerated only the pages whose "Try it" examples it changed (Config,
Control, Task, Vault, plus the new Authority page) with a locally migrated copy:
`forge fix` over its `.march` files, `Authority.must(...)` around the capability calls
whose values it matches on, and `Authority.ignore(...)` around the `IO.warn`/`IO.puts`
arms and `System.exit` that sit beside `Ok(_) -> ()`.

Done when march_doc on its default branch typechecks against this compiler and
`scripts/gen-stdlib-docs.sh` succeeds.
