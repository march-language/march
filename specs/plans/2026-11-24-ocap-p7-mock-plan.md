# Object capabilities, phase 7: `mock`, retiring `Cap(IO.*)`, and `Actor.Introspect` as a kind — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status:** approved by the owner 2026-11-24 with every recommended answer (Q1–Q8). PR 7a is Tasks 1–6, PR 7b is Tasks 7–9.

**Goal:**
- `mock SCOPE with HANDLER do ... end` replaces `with_cap` / `cap_impl` on IO capabilities.
  It works the same way in every runtime: compiled, `march test` (the interpreter), `--jit`
  and JS. Closures, tasks and actors created inside the block keep the mock. `vault_*`
  operations become mockable.
- `Cap(IO.*)` values and parameters are retired: `root_cap`, `cap_narrow`, `with_cap`,
  `cap_impl` / `cap_ops_empty` on IO, and `fn main(c : Cap(IO.X))`. So are the
  composition-root witness parameters of `Actor.debug`, `Actor.introspect`, `Session.attach`,
  `ClusterNode.attach`, `ClusterNode.start`, `SessionNode.run*`, and the generated
  `run_<Role>` / `host_<Role>`.
- Each of those becomes a checked operation under a capability kind requested in `main`'s
  `needs`. `Actor.Introspect` is one of those kinds.
- The non-IO capabilities they return (`Cap(Actor.Introspect)`, `Cap(Actor.Debug)`,
  `Cap(Session.Live)`, `Cap(ClusterNode.Live)`) stay as they are.
- The stdlib, tests, examples, benches, demos, forge templates and docs are migrated off the
  retired forms in the same change.

**Architecture:**
- **The mock is a layer on the current authority.** `mock` pushes a layer onto the current
  authority, the same list phases 4–6 built. The layer carries the scope and an opaque box
  holding the handler record. Because it is part of the authority, capture is free:
  - closures already save and re-enter the authority (`Auth_rt.captures`, `Eval.current_capture`);
  - actors take it at spawn, and a supervised restart restores the first spawn's;
  - tasks copy the spawner's slot.
- **Interception happens at the builtin, in test builds only.** Every interceptable IO builtin
  call is routed to a generated wrapper `__march_dispatch_<op>` (natively and in JS). The
  interpreter has a matching hook in its builtin dispatch.
  - The wrapper asks `Authority.mock_for(kind, target)` for the innermost mock layer covering
    the op's target. If there is one and the handler's field for this op is `Some(f)`, the
    wrapper calls `f`. Otherwise it runs the real op.
- **What gets deleted.** Today's `Cap_passing` TIR pass threads hidden `$cap_IO_X` parameters
  and records capabilities on actor metadata (`march_set_actor_caps`). It is deleted together
  with `with_cap`. Release builds never contain the wrappers, so a program without `mock` pays
  nothing new.
- **Retirement is a type-checker rule plus a corpus migration.** The retired forms become
  diagnostics with machine fixes, so `forge fix` rewrites user code. A one-off script applies
  the same rewrites to this repo's corpus, and whatever it cannot do is finished by hand.

**Tech stack:**
- OCaml 5.5.1: lexer, parser, desugar, type checker, TIR, interpreter, JS emitter, forge.
- March: `stdlib/authority.march`, `prelude.march`, `actor.march`, `session.march`,
  `cluster_node.march`, `session_node.march`, `recon.march`, `trace.march`, `diagnose.march`.
- The C runtime: the policy port's layer walk, layer release, the new kinds in the generated
  lattice tables, and the removal of `march_set_actor_caps`.
- tree-sitter (a new keyword).

## What exists today (surveyed on 11cdf717a)

- **Mocking is a compile-time rewrite in `--test` builds**:
  - `bin/flags.ml:223` `cap_mocking ()` gates it.
  - `lib/tir/cap_passing.ml` threads `$cap_IO_X` parameters. It recognises
    `with_cap(mock, thunk)` by its TIR shape (`:712`) and records capabilities on actor
    metadata at spawn (`:633`).
  - The driver injects `MarchCapDispatch`, generated by `Io_ops_gen.dispatch_wrappers_source`
    (`bin/main.ml:4240`).
  - `with_cap` is `f(())` in the prelude (`stdlib/prelude.march:497`).
- **Where mocks do not work today:**
  - The interpreter (`march test`) and the JIT never honour a mock.
  - Calls through function values, and impls reached through a generic receiver, are not
    mocked.
  - JS has no `set_actor_caps`, so a mock probably does not reach actors there.
  - `march test` appears never to set `Typecheck.test_build` (`bin/main.ml:3033` returns
    before `:8482`).
- **Handler dictionaries** (`lib/typecheck/io_ops_gen.ml`, `march --emit-io-ops`):
  - Each is a structural record with one `Option` field per builtin of the kind, for example
    `IO.Console` has `print_line : Option(String -> ())` and four more.
  - Fourteen kinds have one.
  - `IO.Mut` has none, because the `vault_*` builtins are polymorphic and a field would need a
    rank-2 type.
  - A user writes `cap_impl(c, { cap_ops_empty(c) with print_line: Some(f) })` and then
    `with_cap(mock, fn _ -> ...)`.
- **The current authority** is `List(Layer)`, with `Layer(CapLimit, String, List(CapEntry))`.

    (`march_cap_release_k`, `runtime/march_runtime.c:11208`) and walks it in the policy port

## Global Constraints

- **`mock` exists only in test builds** (`--test`, `march test`, `forge test`, doctests).
  Anywhere else it is a compile error, `mock_outside_test` (design §12).
- **Every runtime agrees** (design §15). One conformance suite, `test/run_cap_conformance.exe`,
  runs every `mock` fixture in every mode.
- **A program without `mock` pays nothing new at run time.**
  - Release builds contain no dispatch wrappers.
  - The new layer kind is never pushed in them.
  - The only shared change is one more constructor case in the policy walk and in the release
    code.
- **Proof capabilities are untouched**: `proof cap`, `mint_cap`, and `cap_impl` on a
  program's own capabilities (design §14).
- **Refusals are values.** Every new checked operation returns
  `Err(CapError(kind, target, limit, scope))`. `ClusterNode.start` is the one exception; see
  builder's call 8.
- **Repo rules** (CLAUDE.md):
  - run `dune build --root .` in the worktree;
  - stage files by name;
  - no attribution lines;
  - merge `origin/main`, never rebase or force-push;
  - never skip or quarantine a test;
  - update `specs/todos/`, `specs/progress/`, `CHANGELOG.md` (`### Changed` for each
    breaking step, design §17) and `specs/lang/` (then `scripts/gen-lang-docs.py`) in the
    same commit;
  - the parser change carries `tree-sitter-march/grammar.js` and `keyword-allowlist.txt`;
  - regenerate `docs/_data/authority.json` (`scripts/gen-authority-data.py`), the explainer
    fallbacks (`node scripts/render-explainer-fallbacks.js`) and the TIR snapshots
    (`UPDATE_SNAPSHOTS=1`, diff reviewed) when the stdlib changes;
  - new slow suites go outside the `compiler` and `rest` CI shards.

## Open questions for the owner

My recommendation comes first in each. The plan is written to the recommendation.

**Q1. How hard is the retirement?** (design §11 fixes only `main`'s window: "one release".)
- *Recommended:*
  - `fn main(c : Cap(IO.X))` is accepted for one release with a `deprecated_main_cap` warning.
    The warning's machine fix rewrites it to `fn main() : () needs IO.X` and drops `c` from
    the body, so `forge fix` does it.
  - Everything else retired is a hard error now, each with a fix or a hint: `Cap(IO.*)` in
    any other parameter or type, `root_cap`, `cap_narrow`, `with_cap`, `cap_impl` and
    `cap_ops_empty` on an IO kind, and the `io` argument of the witness APIs.
  - Reasons: those forms are erased at run time and grant nothing since phase 4, so keeping
    them only misleads. `with_cap` also cannot keep working once `Cap_passing` is gone.
  - The whole in-repo corpus is migrated in this change. Two fixtures keep the deprecated
    `main` form, to pin the warning and its fix.
- *Alternative:* one deprecation release for everything. This needs `Cap_passing` kept alive
  beside the new mechanism for a release, with two mock paths to keep in parity.

**Q2. The handler's shape.** (Design §12 says it "follows today's operation dictionaries";
§20 leaves it to the builder.)
- *Recommended:* keep today's generated per-kind records, one `Option` field per builtin, and
  give them names and a shorthand:
  - Each kind's record becomes a nominal type in a test-build-only module `Mock`:
    `Mock.Console`, `Mock.FileRead`, `Mock.NetConnect`, … (`march --emit-io-ops` lists the
    fields).
  - Each type has an all-`None` value: `Mock.console()`, `Mock.file_read()`, ….
  - In the `with` position, a record literal may name only the fields it overrides, and every
    field it omits is `None`:

    ```march
    mock IO.Console with { print_line: Some(fn s -> log := s :: !log) } do
      Greeter.run()
    end
    ```

  - A named handler is an ordinary value:
    `let fake = { Mock.net_connect() with tcp_connect: Some(...) }`.
- *Alternative:* fields are plain functions and an omitted field means "real op". That is
  terser, but a named handler value would then need its own optional-field notion.

**Q3. What a `vault_*` mock looks like.** A per-op dictionary cannot type the polymorphic
`vault_get` / `vault_put`.
- *Recommended:* `mock IO.Mut("sessions", prefix("cache.")) with { ... } do` gives two things.
  - **Isolation.** Inside the block, every table whose name falls in the scope lives in a
    fresh private namespace. It starts empty, and the real table of the same name is neither
    read nor written.
  - **Fault injection on the monomorphic, checked entry points.** The handler is
    `Mock.Mut { open : Option(String -> Result((), String)) }`. It is consulted by
    `Vault.new`, `Vault.open`, `Vault.whereis`, `ns_get` and `ns_drop`. `Err(reason)` makes
    that open fail with `reason`.
  - `get`, `put` and `delete` need no handler: they act on the private table.
  - `with {}` (isolation only) is the common case.
- *Alternative:* an erased-value dictionary (`get : Option((String, Dyn) -> Option(Dyn))`).
  It needs a `Dyn` type March does not have, and it is unsound under the erased-i64 calling
  convention for unboxed values.

**Q4. An op inside the mock's scope whose handler field is `None`.** Design §12: "the block has
authority for that scope whether or not the test was launched with it".
- *Recommended:* the real op runs, checked against the authority outside the mock. The mock
  layer admits only the ops its handler takes over.
  - So partial mocks keep working (today's `cap_mock_actor_two` relies on them).
  - A mock never lets a test reach the real outside world beyond what the test was launched
    with.
  - A handled op is admitted even when the launch lacks the kind, which is §12's sentence.
- *Alternative A:* the mock admits the whole scope, so an unhandled op runs real and
  unchecked. That is simpler, but a mock silently widens real access.
- *Alternative B:* an unhandled op in scope is refused with
  `CapError(..., ByMock, ...)`. That is strict, but it breaks partial mocks.

**Q5. Kind names for the witness APIs.** (Design §21: "`Actor.Debug`, `Actor.Introspect`, and
one for sessions and clustering; names are the builder's".)
- *Recommended:*
  - `Actor.Introspect` and `Actor.Debug` become top-level lattice kinds, not under `IO`.
    `needs IO` then does not grant debugging other actors. Today it does, because
    `Actor.debug(io)` took the root `Cap(IO)`.
  - `IO.Cluster` covers sessions and clustering, under `IO`: attaching a session and starting
    a node are network operations. So existing `needs IO` programs keep that access.
  - `main` asks with `needs Actor.Introspect`, `needs IO.Cluster`, and so on.
  - The proof caps of the same names keep their names. A `needs Actor.Introspect` on a module
    that holds the proof cap (recon, diagnose, trace) keeps its proof-cap meaning. In a
    function clause or on `main` it also requests the kind.
- *Alternative:* all three under `IO` (`IO.Introspect`, `IO.Debug`, `IO.Cluster`). It is less
  breaking, but any `needs IO` program can then inspect every actor's state.

**Q6. `Actor.pid_from_int` and the other `Cap(Actor.Introspect)` functions.** §7 says
`pid_from_int` "becomes a checked operation under `Actor.Introspect`". §21 says the returned
non-IO caps "stay as they are".
- *Recommended:* reconcile the two like this:
  - `Actor.introspect()` and `Actor.debug()` lose their `io` parameter. They become checked
    mints returning `Result(Cap(Actor.Introspect), CapError)` (and the `Debug` equivalent).
  - `pid_from_int(n)` drops its `Cap` parameter and is checked directly, as §7 says.
  - The other ~25 functions that take `Cap(Actor.Introspect)` or `Cap(Actor.Debug)` keep the
    proof cap, as §21 says: `whereis`, `list`, `Recon.*`, `Trace.*`, `inspect_state`, and so
    on. Holding the cap stays the right to use them, with no per-call check.
- *Alternative:* keep `pid_from_int`'s `Cap` parameter and add the check. That is less churn
  (49 test files), but it is two gates for one right.

**Q7. The `mock` keyword.**
- *Recommended:* a hard keyword, like `restrict`:
  - one grammar rule;
  - clear syntax errors;
  - tree-sitter and the keyword allowlist updated.
  - `let mock = …` stops parsing. Every in-repo use is in the retired `with_cap` fixtures.
    Pre-1.0, this goes under `### Changed`.
- *Alternative:* a contextual keyword (`soft_lower_name`, `parser.mly:2642`). `mock` stays
  usable as a name, at the cost of a lookahead rule and likely another menhir conflict.

**Q8. One PR or two?**
- *Recommended:* two PRs, in sequence, each off `main`. Stacked PRs die when their base branch
  is deleted.
  - **7a:** `mock`, the new kinds, the checked witness APIs, and the deletion of
    `with_cap` / `Cap_passing`, with the `cap_mock` fixtures rewritten. About 60 files, so it
    can be reviewed.
  - **7b:** retire `Cap(IO.*)` / `root_cap` / `cap_narrow` and the deprecated `main` form,
    with the corpus migration. About 1,500 files, almost all mechanical, reviewed by script
    output and spot checks.
  - Each PR carries its own perf and oracle numbers.
- *Alternative:* one PR (the task as briefed). The migration diff would bury the `mock`
  review.

## Builder's calls (no question; for the owner to check)

1. **The layer.**
   - `CapLimit` gains `ByMock(String)`, the kind's text, and `Layer` keeps its shape. The
     handler sits in a side field: a new constructor `MockLayer(String, List(CapEntry), Box)`
     on a `Layer`-compatible type.
   - The exact encoding is decided in Task 1, after reading `march_cap_release_k`.
   - Whatever it is, the C policy walk treats a mock layer as transparent for refusal (it
     never refuses) and visible to `mock_for`.
   - `Box` is an opaque, reference-counted handle. A test-build-only builtin pair
     `mock_box` / `mock_unbox_<kind>` stores and reads it. Each generated wrapper unboxes
     only its own kind's type, so the erasure is safe.
2. **Matching a target.**
   - Each interceptable builtin gets a target argument in `Io_ops_gen`, taken from
     `Cap_ops`'s checked-entry metadata: the path for file ops, the host for network ops, the
     name for vault and registry ops, the program for exec.
   - An op with no single target matches only an unscoped mock of its kind.
   - Matching reuses `Authority`'s scope matcher, so a scoped mock follows the same path, host
     and prefix rules as `restrict`.
3. **Admission (Q4).**
   - The stdlib entry point's `Authority.check(kind, target)` passes when the innermost mock
     covering the target has a handler for any op of that kind. The check does not know which
     op follows.
   - The wrapper then re-checks with `Authority.check_unmocked` before running a real op. So
     an unhandled op is held to the outside authority.
   - That re-check happens only inside test builds.
4. **The interpreter.** `Eval_builtins` gets one hook for interceptable builtins when
   `test_build` is on: `mock_for` against `Eval_runtime.cap_slot`, then the handler or the
   real op. No source injection is needed there. JIT and JS go through the native
   wrappers / `js_emit`.
5. **Nesting.**
   - Mocks nest. The innermost layer covering a target wins.
   - A `restrict` inside a mock narrows as usual: a handled op outside the restrict's scope is
     refused. `restrict` binds tests too.
   - One kind per `mock`. Its scope may list several entries of that kind. Several kinds are
     written as nested blocks.
   - The scope must be literal, because the handler's type comes from the kind.
6. **`march test` sets `test_build`.** Today's gap is fixed in Task 1, so mocks work in the
   interpreter runner.
7. **Choreography and topology** follow design §21 with no question:
   - `role R needs ...` becomes a limit around the role's body;
   - `run_<Role>`, `host_<Role>` and `host_<Role>_or` lose their `Cap` parameters;
   - topology's generated `main` gets a `needs` clause;
   - the pool hooks lose their `Cap(P)…` parameters;
   - `--dump-role-authority` stays.
8. **`ClusterNode.start(cfg)` keeps `Result(Cap(ClusterNode.Live), String)`.** A refusal is
   `Err(Authority.describe(e))`. Changing the error type would touch 113 test files for no
   gain. A todo records the inconsistency.
9. **Migration tool.**
   - The fixes live in the diagnostics:
     - `deprecated_main_cap` rewrites `main`;
     - `cap_param_retired` drops a pass-through `Cap(IO.*)` parameter at its definition and
       at every call site;
     - `with_cap_retired` rewrites `with_cap(cap_impl(c, {cap_ops_empty(c) with f…}), fn _ -> body)`
       to `mock K with {f…} do body end` when the shape is literal;
     - `witness_io_arg` drops the `io` argument of the witness APIs.
   - `scripts/migrate-ocap-p7.py` (one-off, not committed) drives `march --check-json` and the
     fixes over the corpus, then prints what it could not rewrite.
   - `specs/lang/` and `docs/` code blocks are rewritten by the same script with a
     text-level rule, then checked by doc-lint and the doctest runner.
10. **Error corpus.** Cases that test a retired diagnostic are moved to the new diagnostic,
    not deleted, and each keeps its intent. Examples: a grant hint that recommended a `Cap`
    parameter now recommends a `needs` clause; a `cap_narrow` misuse becomes a
    `cap_param_retired` case. The internals allowlist may only shrink.

## Review Focus

1. **Capture.** A closure, a task, an actor and a supervised restart, each created inside a
   `mock` and run after the block ends, still reach the handler. One created outside and run
   inside does not. Pinned by `mock_closure_after`, `mock_task`, `mock_actor`,
   `mock_supervised_restart` and `mock_outside_closure`, on every backend.
2. **No widening of real access (Q4).** Inside `mock IO.FileRead("./fixtures/")` with only
   `file_read` handled, `file_exists("./fixtures/x")` under a launch without `IO.FileRead` is
   refused. Pinned by `mock_unhandled_refused`.
3. **Admission when the launch lacks the kind.** A handled op is admitted under a launch that
   lacks the kind (design §12). Pinned by `mock_admits_handled`.
4. **`restrict` inside `mock` still narrows.** Pinned by `mock_restrict_inner`.
5. **Vault isolation (Q3).** A mocked table name sees an empty private table. The real table
   is untouched after the block. A `put` from an actor spawned inside goes to the private
   table. Pinned by `mock_vault_isolation` and `mock_vault_actor`.
6. **Release builds.** `mock` outside a test build is `mock_outside_test`, and a release
   build of a file that defines no mock has no `__march_dispatch_` symbol. Pinned by an
   error-corpus case and a `test_cap_dict.ml` IR assertion.
7. **The migration did not change behaviour.** Every migrated fixture's `.expected` file is
   unchanged, except the deprecation warnings, and those appear only in the two fixtures that
   keep the old form. The script's "could not rewrite" list is empty at the end.
