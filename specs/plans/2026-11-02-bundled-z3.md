# Bundled z3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A March release proves refinements with a pinned, bundled z3 under a deterministic
`rlimit`, the same verdict on every tier-1 platform, and a loud warning when z3 is missing or
broken.

**Architecture:** `lib/refine/solver.ml` gains one lookup (`MARCH_Z3`, then
`<exe>/../libexec/z3`, then `PATH`), a cached version probe and a health report. Every query
runs after a `(reset)` under `:rlimit` instead of `:timeout`, with a driver-side 60 s
backstop for hangs. The z3 version, the limit and the platform key both caches. CI builds
the pinned z3 from source (static on Linux), ships it in each archive, and a cross-platform
job fails on any verdict that differs.

**Tech Stack:** OCaml 5.5.1 (dune, alcotest), z3 SMT-LIB over a pipe, GitHub Actions
(Alpine musl containers for Linux, macOS arm64), cmake for z3.

**Spec:** `specs/2026-11-02-bundled-z3-design.md`

## Global Constraints

- Pinned z3: **4.16.0**, recorded once in `z3.version` (repo root; line 1 is the version,
  `4.16.0`; Task 7 adds the source tarball's sha256 as line 2).
  CI, release builds and the version check all read it.
- Lookup order: `MARCH_Z3`, then `<real exe dir>/../libexec/z3`, then `PATH`. A set
  `MARCH_Z3` that does not exist is **broken**, never a silent fall-through.
- Archive layout: `libexec/z3` and `licenses/z3-LICENSE.txt`; nothing new in `bin/`.
- No `:timeout` option is sent to z3 any more. Limits are `:rlimit`; the only wall clock is
  the driver's hang backstop, default 60000 ms, overridable by `MARCH_Z3_BACKSTOP_MS` (for
  tests).
- z3 is `(reset)` before every query (the owner accepted the cost, 2026-11-02).
- Budget (owner, 2026-11-02): the refinecheck suite and the stdlib build no more than about
  25% slower than the baseline recorded in Task 2 Step 1.
- Missing/broken z3: the build succeeds and prints **one** warning per run, only on a run
  that sent at least one query. Under `cap verified` the undischarged-obligation error
  names z3 as the reason.
- A different z3 version is used, with one warning naming both versions.
- No z3 path ever enters a cache key (the determinism oracle runs from two cwds and HOMEs);
  only its version, the limit and the platform do.
- Linux release binaries stay static (`build.yml` scratch checks stay green).
- Editor work is out of scope.
- Repo rules: `dune build --root .`; stage files by name; specs/todos ↔ specs/progress and
  CHANGELOG in the same commit as the feature; `specs/lang/` edits then
  `scripts/gen-lang-docs.py`; never run two dune builds/test runs at once.

## Review Focus

1. **A dev build** (`_build/default/bin/main.exe`, no `libexec/` beside it) with z3 on
   `PATH`: works exactly as today, no warning when the version matches. → Task 1 test
   `lookup_falls_back_to_path_for_dev_build`.
2. **`forge` running the toolchain through `~/.march/current` (a symlink)**: the exe-relative
   lookup follows the symlink to the real install. → Task 1 test
   `lookup_resolves_symlinked_exe`.
3. **A warm VC cache from before this change** (entries with no version in the key, some
   holding `unknown`): never served as a verdict. → Task 3 test
   `old_cache_entries_are_not_served`.
4. **z3 dies mid-run** (crash after N queries): one warning, remaining obligations reported
   as undecided, build still succeeds, no per-obligation spam. → Task 4 test
   `z3_crash_mid_run_warns_once`.
5. **A cached build with z3 missing**: the warning still appears on the second (warm) run.
   → Task 4 test `missing_z3_warns_on_warm_cache`.

### Task 2: `rlimit`, reset per query, hang backstop

**Files:**
- Modify: `lib/refine/solver.ml` (`init_options`, `check`, new reader with backstop)
- Modify: `lib/refine/refine.ml` (`stage2_timeout_ms` → `stage2_rlimit`; caching of
  `Unknown`; restart on `Hung`)
- Modify: `lib/refine/vc_cache.ml` (`Unknown` is a hit; serialise `Rejected` never)
- Modify: every other match on `Solver.result` (11 sites, `grep -rn 'Solver\.Unknown'`)
- Test: `test/test_refine.ml`

**Interfaces:**
- Consumes: Task 1's `Solver.find_z3`.
- Produces:
  - `type Solver.result = Unsat | Sat of (string * string) list | Unknown | Rejected`.
    `Unknown` = z3 said `unknown` (rlimit or incompleteness; deterministic, cacheable).
    `Rejected` = z3 rejected the query (malformed; never cached).
  - `exception Solver.Hung` raised by `check` when the backstop fires.
  - `Solver.check : ?preamble:string -> ?assume:string list -> rlimit:int -> t -> Smt.vc -> result`
    (`timeout_ms` removed). Each call sends `(reset)`, `init_options`, the unsat-core option
    when `assume <> []`, `(set-option :rlimit <rlimit>)`, then the query; no push/pop.
  - `Solver.last_rlimit_count : int ref`, set from `(get-info :rlimit)` after each query
    only when `MARCH_REFINE_RLIMIT_LOG` is set (it also appends `<count>\t<stage>` to that
    file). Task 6 uses it.
  - `Refine.default_rlimit : int ref` and `Refine.stage2_rlimit : int ref`. Temporary values
    until Task 6: `20_000_000` and `5_000_000`.
