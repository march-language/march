# HCR Phase 4: `forge deploy hot` Design

**Date:** 2026-06-24
**Status:** Approved
**Depends on:** HCR Phase 3 (live dlopen hot reload — complete), `lib/cas/`, `forge/`, `runtime/march_reload.c`, `runtime/march_dispatch.c`

---

## Goal

Replace the manual `hot-deploy.sh` script with `forge deploy hot` — a CAS-native, ed25519-signed, drift-aware deploy command that:

1. Computes the minimal reload set via `impl_hash` set-diff against the live process
2. Gates on `sig_hash` compatibility before activating
3. Transfers artifacts through the existing reload socket (with CAS hit check to skip redundant transfers)
4. Activates in topological SCC order with ed25519-signed commands
5. Detects and re-applies patches lost to a process restart

---

## Architecture Overview

```
forge deploy hot [--target <env>]
  │
  ├─ 1. build with --hot-reload → CAS hashes all SCCs
  ├─ 2. SSH tunnel → ABI_QUERY → get server's active {name → impl_hash, sig_hash}
  ├─ 3. set-diff: reload_set = new_hashes \ active_hashes
  ├─ 4. sig_hash gate: reject if any changed def has changed sig_hash escaping boundary
  ├─ 5. for each artifact in reload_set:
  │      CAS_CHECK → PRESENT (skip) or MISSING → CAS_PUT (inline stream)
  ├─ 6. sign each ACTIVATE with ed25519 private key
  ├─ 7. send ACTIVATE commands in topological SCC order; await acks
  ├─ 8. record intended active set to .march/deploy-state.json
  │
  └─ on reconnect: VERSIONS → detect drift → re-apply automatically
```

### forge.toml

```toml
[hot-reload]
socket   = "/tmp/march_hcr_myapp.sock"    # Unix socket path on the server
ssh_host = "root@198.199.121.160"          # SSH target for tunnel
public_key = "base64-encoded-ed25519-pubkey"
```

## Protocol Extensions

All commands are newline-delimited text over the existing Unix socket (SSH-tunneled). Three new commands; one extended command.

### New: `CAS_CHECK`

```
CAS_CHECK <compilation_hash>
→ PRESENT
→ MISSING
```

### New: `CAS_PUT`

```
CAS_PUT <compilation_hash> <size_bytes>\n
<binary artifact data — exactly size_bytes>
→ OK <compilation_hash>
→ ERR <reason>
```

The server writes the artifact to its local CAS at the standard object path (`~/.march/cas/objects/<2>/<62>`).

### New: `VERSIONS`

```
VERSIONS
→ VERSION <name> baseline <impl_hash>
→ VERSION <name> hot      <impl_hash>
  (hot line only present for slots that have been reloaded)
→ END
```

`baseline` is the `impl_hash` the slot had at process startup (captured in `march_dispatch_publish` during `@main`). `hot` is the currently active impl_hash if it differs from baseline.

### Extended: `ABI_QUERY`

Adds `<sig_hash>` field so forge can run the sig_hash gate without a local CAS lookup:

```
ABI_QUERY
→ SLOT <id> <name> <impl_hash> <sig_hash>
   …
→ END
```

### Extended: `ACTIVATE`

Drops the Phase 3 `.so` path argument; adds `<compilation_hash>` (server resolves from CAS) and `<ed25519_sig_base64>`:

```
ACTIVATE <name> <impl_hash> <compilation_hash> <ed25519_sig_base64>
→ OK <impl_hash>
→ ERR bad_signature | sig_incompatible | missing_artifact | unknown_name | signing_not_configured | …
```

The signature covers the UTF-8 bytes of `"<name> <impl_hash> <compilation_hash>"` (space-joined, no newline). Signature is URL-safe base64, no padding.

## ed25519 Keygen / Sign / Verify

### Key management

`forge hot-reload keygen` generates a keypair:
- Private key → `~/.march/signing/private.key` (mode `0600`, base64-encoded 64-byte seed)
- Public key → printed to stdout and as a ready-to-paste `public_key = "..."` line for `forge.toml`

`forge hot-reload show-pubkey` prints the public key for the key in `~/.march/signing/`.

### Signing (forge side — OCaml)

Library: `mirage-crypto-ec` (available in opam). For each ACTIVATE:
1. Load private key from `~/.march/signing/private.key`
2. Sign `"<name> <impl_hash> <compilation_hash>"` with `Mirage_crypto_ec.Ed25519.sign`
3. Base64-encode the 64-byte signature (URL-safe, no padding)

Forge self-verifies the signature before sending (sanity check that the key in `forge.toml` matches `~/.march/signing/`).

### Verification (server side — C)

Library: vendored `tweetnacl.c` (~700 lines, public domain, `crypto_sign_ed25519_open`). Zero external C dependencies.

The public key is embedded at build time. `forge build --hot-reload` generates `runtime/march_signing_key.h`:

```c
/* Auto-generated by forge build --hot-reload. Do not edit. */
static const unsigned char MARCH_SIGNING_PUBKEY[32] = {
    0x3a, 0x7f, … /* 32 bytes */
};
```

If the `public_key` field is absent from `forge.toml` (or the key is all-zeros), `march_signing_key.h` contains all-zeros and `ACTIVATE` always returns `ERR signing_not_configured` — safe default, no unsigned deploys slip through.

Verification in `march_reload.c`:
1. Decode base64 signature from the ACTIVATE command
2. Call `crypto_sign_ed25519_open` with `MARCH_SIGNING_PUBKEY`
3. On failure: `ERR bad_signature`, nothing loads, process untouched

## `forge deploy hot` Command Flow

```
forge deploy hot [--target <env>] [--dry-run] [--force] [--timeout <ms>]
```

1. **Build** — `march --compile --hot-reload`; CAS produces `{name → (impl_hash, sig_hash, compilation_hash)}` for every boundary function
2. **Connect** — open SSH tunnel to `ssh_host`; forward Unix socket to a local temp path
3. **Drift check** — send `VERSIONS`; compare against `.march/deploy-state.json`; if drift detected (process restarted since last deploy), print warning and re-apply from step 6 using the recorded intended set
4. **ABI_QUERY** — receive server's `{id, name, impl_hash, sig_hash}` set
5. **Set-diff** — `reload_set = {defs where new impl_hash ≠ active impl_hash}`; if empty, print "nothing to deploy" and exit 0
6. **Sig_hash gate** — for each def in `reload_set`: if `new sig_hash ≠ old sig_hash`, check whether all direct callers of that def are also in the reload_set (contained interface change) or not (escaping interface change). A contained change is allowed (all callers are recompiled together). An escaping change → print targeted error (naming the non-reloadable caller), suggest `forge deploy`, abort (unless `--force`). Caller graph is available from the CAS SCC dependency edges recorded during step 1.
7. **Distribute** — for each def in `reload_set`: `CAS_CHECK <compilation_hash>`; on `MISSING`, stream artifact via `CAS_PUT`
8. **Sign + activate** — for each def in topological SCC order: sign, send `ACTIVATE`, await ack; any `ERR` aborts remaining activations (partial deploys are safe: topological order ensures no caller gets a new callee before the callee is activated)
9. **Record** — write `.march/deploy-state.json`: `{target, timestamp, activated: [{name, impl_hash, sig_hash}]}`
10. **Report** — print names reloaded, bytes transferred, skipped (already in CAS)

`--dry-run`: runs steps 1–6, prints reload_set and sig_hash gate result without sending anything.
`--force`: skips sig_hash gate, requires interactive confirmation prompt.

## Crash-Restart Drift Detection

When a process restarts after hot reloads, all slots revert to their AOT baseline — silently dropping every patch. Phase 4 surfaces and auto-heals this.

**Server state in `march_dispatch`:**
- Each slot now stores both `baseline_impl_hash` (captured at `march_dispatch_publish` during `@main` startup, before any reload) and the current `impl_hash` (updated on each `ACTIVATE`)
- `VERSIONS` reads both; `hot` line only emitted when they differ

**forge on reconnect:**
1. Sends `VERSIONS`
2. Reads `.march/deploy-state.json` for the last intended active set
3. For each name in intended set: if `VERSIONS` shows only `baseline` (no `hot` line), the process has restarted
4. Prints: `drift detected: Server.square reverted to baseline (process restarted?) — re-applying…`
5. Re-runs distribute + sign + activate for the drifted set

With `--dry-run`, drift is reported but not re-applied.

## Failure Modes

| Situation | Behavior |
|-----------|----------|
| Signature invalid | `ERR bad_signature`; process untouched |
| Signing not configured (all-zero pubkey) | `ERR signing_not_configured`; reject pre-activation |
| `sig_hash` changed, escapes boundary | `ERR sig_incompatible`; suggest `forge deploy` |
| Artifact missing after `CAS_PUT` | `ERR missing_artifact`; transfer and retry |
| `CAS_PUT` truncated / hash mismatch | `ERR cas_put_corrupt`; abort |
| Nothing changed (empty reload_set) | "nothing to deploy"; exit 0 |
| Process restarted (drift) | Auto re-apply pending activations |
| Partial activation failure | Already-activated defs stay live; caller always has its callee (topo order) |
| SSH tunnel unreachable | Clear error; fall back to `forge deploy` |
