# Pre-1.0 plan: every open item, bugs first

**Date:** 2026-11-23, written against `origin/main` at `4744a0830` (version 0.7.0, 345 open todos).
**Status:** proposal. It orders the work; it decides nothing an owner decision is listed for.

The checklist in `specs/plans/2026-09-28-road-to-1.0.md` ("Status 2026-11-22") says what is left
and groups it into 23 workstreams (W1 to W23). This plan says in what order to do it when bugs
come first, what each step changes, how to tell it is done, and what it waits on. It replaces the
ordering in `specs/plans/2026-11-11-pre-1.0-execution-plan.md`, whose package descriptions for
the gates and the freeze (G, B, F packages there) still apply.

Every one of the 345 open todos is assigned to exactly one stage; the full assignment is the
appendix. Todo references rot within days: before starting an item, check that its file is still
in `specs/todos/` on `origin/main` and re-run its repro.

## How the order was chosen

A bug is ranked by what it does to a user who hits it, worst first:

| Rank | What goes wrong | Stage |
|---|---|---|
| 1 | Memory is unsafe, or the one open P1 | A0 |
| 2 | The process dies, hangs, or loses data | A1 |
| 3 | A capability claim is false: code gets authority it did not declare | A2 |
| 4 | Two engines give different answers for one program | A3 |
| 5 | A stdlib function returns a wrong value | A4 |
| 6 | Memory or a descriptor leaks | A5 |
| 7 | CI fails without a code change | A6 |
| 8 | A tool is wrong (formatter, `forge`, checkers) | A7 |

Two things are not bugs but cannot wait behind all of them:

- **Owner decisions.** Fourteen bugs cannot be fixed until someone picks the behaviour (list
  below). They cost the owner minutes and block days of work, so they come first.
- **The breaking chain** (stage X). Capability phases 6, 7 and 8 and the API reshapes break user
  programs, so they must land before the freeze, and phases 6 and 7 have no plan. Writing those
  two plans starts in week one, beside stage A0. Implementing them starts when A0 to A2 are
  done, because phase 6 builds on the attribution fixes in A2.

Everything else (deploys, release artifacts, the refinement checker, docs, features) follows the
bugs, in stages R, V, T and Q. Ninety-two todos are proposed as not blocking 1.0 (stage P).

## Rules for every fix

1. **Reproduce first**, on a fresh build of `origin/main`, interpreted and compiled, under a
   private `HOME` (the shared `~/.cache/march` and compile CAS hide and invent failures). If it
   no longer reproduces, close the todo with the commit that fixed it; do not write a fix.
2. **Test first.** Add the failing test, watch it fail for the stated reason, then fix. A crash
   fix gets a compiled test; a divergence fix gets a test that runs on every engine it named.
3. **One fix, one PR**, unless the stage says the items share a mechanism and names the batch.
4. **Same commit:** `git mv` the todo to `specs/progress/`, add the `CHANGELOG.md` bullet, and
   run the benchmark `specs/benchmarks.md` maps to the change.
5. **A fix that changes reference counting** runs the ASan leg before it is called done
   (`scripts/triage.sh FILE --deep`), and `scripts/oracle-base.sh ir` to show nothing else moved.
6. **A gate is not done** until it has been seen to go red on a deliberate break.
7. **CI runs one PR at a time.** Put small fixes from one stage into a merge train (several PRs,
   one CI run); do not train a single PR. Merge by hand with `gh pr merge N --merge` after
   checking that the green run's sha is the PR head. Never `--auto`.
8. **Never skip, disable or quarantine a test** to get green.

## Lanes

Four lanes run at once because their files do not overlap. Within a lane the order is fixed.

| Lane | Works on | Order |
|---|---|---|
| 1. Compiler and runtime | `lib/`, `runtime/`, `bin/` | A0, A1, A2, A3, A5, then X |
| 2. Stdlib | `stdlib/*.march` and its tests | A4a to A4f, in any order |
| 3. Design | plans and owner decisions | decisions, then the phase 6 and 7 plans, then X4 to X6 designs |
| 4. Background | CI evidence | A6 (flakes), A7 (tools), T (docs) |

Lanes 1 and 2 both feed CI, so they share merge trains: one train a day holds what both produced.
