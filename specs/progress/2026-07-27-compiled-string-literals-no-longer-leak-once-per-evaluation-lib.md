- ✅ **Compiled string literals no longer leak once per evaluation (`lib/tir/llvm_emit.ml`, `lib/tir/llvm_ctx.ml`, `runtime/march_runtime.c`, 2026-07-27).** A string literal carries NO refcount obligation in TIR — `perceus.ml`'s `EAtom (ALit _)` arm returns the expression untouched, exactly as it does for a global `ADefRef` — but codegen emitted `@march_string_lit`, a fresh `rc=1` malloc, on every evaluation of the site. Nothing owned that cell, so no pass ever emitted a matching decrement and each evaluation leaked one string. **Why it hid for so long:** the two neighbouring shapes are both clean, so the obvious probes are vacuous. A let-bound literal (`let s = "xyz"`) gets an ordinary Perceus dec on its binding; a literal passed straight to a non-allocating call (`String.byte_size("xyz")` in a loop) is hoisted out of the loop by the optimizer and evaluated twice in total. Only a literal evaluated repeatedly as a direct OPERAND reaches it — canonically of `++`, i.e. exactly how ordinary string building is written (`acc ++ ", "`, `s ++ "\n"`). Measured: `let s = buf ++ "xyz"` over 2M iterations — 4,000,003 allocations against 2,000,001 frees, peak RSS 64.2MB, growing linearly with the iteration count; the same loop with two variable operands used 2.9MB. **Fix:** one immortal string per literal SITE. `intern_string_site` emits a null-initialised `internal global` beside the bytes, and `@march_string_lit_static` fills it once and returns the same pointer forever (atomic CAS, so a cold cell reached from two threads still yields one shared pointer; `march_runtime_wasm.c` gets a plain single-threaded counterpart, where the same per-evaluation growth was pushing the bump arena forward). The cell is `global`, not `constant`, so a stray RC op can never fault. **Why sharing is safe:** March strings are immutable and the runtime never mutates a string cell in place (`march_string_concat` allocates a fresh cell and reads both operands; no runtime path tests `rc == 1` on a string). `MARCH_RC_IMMORTAL` (1 << 40) is far enough above any reachable count that no sequence of decrements reaches the free-on-zero paths, and it makes the FBIP `rc == 1` uniqueness test in `llvm_emit.ml` always false, so an immortal cell is never reused in place. `march_free` — which bypasses the count entirely, and is what Perceus emits for a dead LINEAR/AFFINE binding — now skips immortal cells; defensive rather than a known reproducer. Post-fix the original repro matches the variable-operand control exactly (2.9MB). Guarded by `test_string_literal_operand_no_leak_compiled` (`string_literal_codegen` group), which reads the runtime's own `march_live_allocs` gauge through an extern rather than sampling RSS, and compares the SAME literal site across two loop lengths so the assertion is on GROWTH — one immortal cell per site is the intended permanent cost. Verified non-vacuous by reverting just the codegen arm: `LEAKED 20001` before, `BOUNDED` after. Interpreted execution was never affected (OCaml GC). Benchmarks show no regression; `bench/iolist_template.march` peak RSS 52.6MB → 45.4MB. The `llvm_builtins_preamble_golden` blob gained the new declare.
