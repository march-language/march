- ✅ **Final-review fix set for the pattern-matching work — five defects at feature COMBINATION points (`lib/tir/lower_match.ml`, `lib/typecheck/typecheck.ml`, `lib/tir/tir.ml`, 2026-07-24).** A whole-branch review of `b6cf0468..021b2463` found every isolated feature working and every combination broken; the shipped tests each exercised one feature alone, so the suite was fully green with all five present. **(1) An or-pattern arm that binds ANYTHING failed to compile.** The join point holding the shared arm body is bound OUTSIDE the whole decision tree and was 0-ary, justified by “alternatives bind no variables” — true of the alternatives, false of the ARM (`P(x, 1 | 2)`, `{ code: 1 | 2, msg: m }`, `(1 | 2) as n`). Those binders became free variables of the lifted lambda; Defun resolved them against the global namespace and clang rejected the module (`use of undefined value '@x'`), or, when a top-level fn shared the name, emitted a call to the WRONG function. Fixed by making `hoist_fallback_jp` take an optional `params` list and having both hoist sites (no-guard fast path, guarded path's `or_wrap`) pass the arm's binders — minted with the same source name and `ty_of_span` type the decision tree binds them with — as join-point parameters. Body still emitted once; duplicating per alternative was rejected again (exponential TIR blowup). **(2) A record pattern nested in a constructor payload SIGSEGV'd, compiled only.** `EField` needs the scrutinee's `Tir.ty` to be the record's or `llvm_emit` falls back to `march_record_field_dyn` and decodes the result with the FIELD's type; a statically-laid-out record stores `Float` inline as a raw double, so `march_unbox_float` dereferenced a double's bit pattern. Int/String fields survived by luck, so it was latent for most field types and lethal for Float, and every nested record pattern degraded to a runtime hash lookup instead of a GEP. Fixed by recording a record pattern's own type under its span in `infer_pattern` and re-annotating the scrutinee ATOM in place in `expand_record_column` — no extra `ELet`, so reference counting is untouched. **(3) `(p | q) as n` and `(p as a) as b` were internal compiler errors.** `expand_or_rows` ran before `strip_as_column`, which can PRODUCE a first-column `PatOr`; and `strip_as_column` peels one `PatAs` layer per pass. `compile_matrix_impl` now iterates strip-then-expand to a fixpoint. `expand_record_column`'s catch-all also stops silently dropping an unexpandable row (the B4 failure mode) and fails loudly like the sibling path. **(4) Nested or-patterns defeated exhaustiveness and produced false redundancy warnings.** `norm_pat` mapped a nested `PatOr` to `SPWild`, which in a coverage matrix means “matches everything” — so `Some(1 | 2)` claimed all of `Some(_)` (no non-exhaustiveness warning, runtime panic on `Some(99)`) and `P(x, 1 | 2)` made the next arm look unreachable (the same false positive `7b90133f` carved records out for). `norm_pat_rows` now enumerates the cross-product of alternatives at every depth, capped at `or_expansion_cap` = 256 rows; past the cap it falls back to the widening `norm_pat` and `check_redundant_arms` skips the arm exactly as it skips a record-pattern arm. **(5) `<record pattern> as name` did not typecheck** — `PatAs` dropped `expected`, so the alias got the narrow closed-synthesized record type; one `?expected` fixes it. Minors: the weak `test_or_pattern_exhaustiveness` assertion now matches the message; both live doc copies + `CHANGELOG.md` now state that record arms are excluded from BOTH coverage analyses.
