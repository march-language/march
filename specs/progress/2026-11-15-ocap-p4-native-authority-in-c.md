# ocap phase 4: the native slow path lives in the C runtime

Plan: specs/plans/2026-11-15-ocap-p4-runtime-plan.md, Task 4b. This follows the owner's
ruling "Work to shrink it" on the binary and IR growth from linking the March `Authority`
matcher into every program that does a capability operation.

## What changed

- **`runtime/march_authority.c`** is a new runtime file (role core, jit). It is a line-for-line
  C port of the policy in `stdlib/authority.march`:
  - the scope parser, with byte-identical error texts;
  - `admits`, over all six `Arg` forms;
  - `subset`;
  - the layered check;
  - `frame_layer`;
  - `launch_init`, with decision 4's launch errors through `cap_launch_fail`.

  The values it builds and reads keep the March shapes: `Authority.Layer`, `Scope`, `Arg`,
  `CapLimit`, `CapError`, `Result` and `List`, with the declared tags and type-id stamps. So
  `cap_layers()`, `Authority.enter_fn` and the release and immortalize walks are unchanged.

  The hot path makes no heap allocation. Scratch memory is a 2 KB stack arena, and kind names
  are compared by length first. The file is compiled `minsize`.
- **`runtime/march_authority_tables.h`** is generated by `lib/caps/emit_c_lattice.ml` from
  `Cap_lattice.hierarchy` and `Cap_scope`. It holds:
  - the lattice;
  - the path-, host- and name-kind tables;
  - the type ids, as constants.

  A freshness rule in `test/dune` (`@test/authority_tables_check`) diffs it against the
  generator's output.
- **The seam is `lib/tir/auth_native.ml`.** It runs right after `Auth_rt.frames` in the native
  pipeline (`bin/main.ml`, but not JS or wasm) and in `lib/jit/repl_jit.ml`. It retargets direct
  calls of these functions to the builtins `cap_rt_*`:
  - `Authority.parse`
  - `Authority.admits`
  - `Authority.subset`
  - `Authority.frame_layer`
  - `Authority.launch_init`
  - `Authority.check_layers`
  - `Authority.check_slow`

  `check_slow` is new: it is `check`'s branch after `cap_check_raw` answers non-zero. Mono then
  never sees the March bodies.

  The interpreter and JS keep the March policy. A program that declares a type whose short name
  collides with one of those shapes keeps the March policy natively too, because colliding types
  take global constructor tags.
- **`march_cap_set_launch_once`** (in `march_runtime.c`) sets the launch layers without
  panicking. The C launch therefore does not link `march_panic`. An internal error, such as a
  request the compiler accepted that fails to parse, prints `march: internal error: ...` and
  exits 2. The March policy panics in that case.

## Measurements

Hello world is `needs IO.Console` plus `println`, compiled with `--opt 2` on macOS arm64.

| | main 2caf18fdd | before (a19be4d56) | after |
|---|---:|---:|---:|
| binary | 252,904 B | 432,360 B | 272,184 B |
| `.ll` size | 55,732 B | 974,742 B | 54,577 B |
| `define`s in `.ll` | 9 | 118 | 8 |

Slow path, measured with the Task 4 microbench (1e6 ops, `--opt 2`, load 13 to 22):

| | before | after |
|---|---:|---:|
| host check, 1 layer | 516 ns | 176 ns |
| path check, 1 layer | 650 ns | 249 ns |
| host check, 2 layers | 848 ns | 237 ns |
| path check, 2 layers | 1149 ns | 399 ns |
| frame enter and leave | 52 ns | 54 ns |

## Tests

`test/test_authority_differential.ml`:
- `authority_differential` 2: the lib/caps rows judged by the C policy, using the same program
  compiled.
- `authority_differential` 3: about 100 parse, subset and hand-built `Paths`/`Hosts` rows. The C
  output must equal March's line for line, including every error text.
- `authority_size`: hello world has at most 13 `define`s, defines no Authority policy function
  other than `check`, and launches through `march_cap_rt_launch_init`. With the matcher linked
  back in, it would define 118. The binary size is printed, not gated, because it is
  page-rounded and depends on the toolchain.
