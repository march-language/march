- ✅ **`forge refactor bundle` — fix doc-comment insertion (silent no-op on documented fns)** — `bundle_fn` inserted the generated `type <Fn>Args = {…}` at the start of the target function's line, i.e. **between** an attached `doc "…"` comment and its `fn`. A `doc` must immediately precede the decl it documents, so `doc` → `type` failed to parse and the engine's own re-parse safety gate silently rejected the file ("skipped: result would not parse / 0 files changed") — bundle no-op'd on *any* documented function. Fix (`lib/refactor/refactor.ml`): when `fn.fn_doc <> None`, walk up from the `fn` line past any `@[…]` attribute lines to the doc block's opening line (`is_doc_start`: the `doc` keyword followed by a string literal, single- or triple-quoted, so multi-line docs and identifiers like `doctor` aren't mismatched) and insert the type **above** the doc. Found while building the `bastion_todos` LSP demo. +1 refactor test (`documented target fn`, 10 total); verified end-to-end on the demo controller (`render_link` with a doc now bundles + migrates its call site).
