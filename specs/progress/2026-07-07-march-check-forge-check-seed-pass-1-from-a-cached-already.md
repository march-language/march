- ✅ **`march check`/`forge check` seed pass 1 from a cached, already-typechecked stdlib env instead of re-typechecking stdlib from scratch every invocation (`lib/typecheck/typecheck.ml`, `bin/main.ml`, `specs/plans/2026-07-07-compiler-daemon-perf-plan.md`, 2026-07-07).** Follow-up to a compile/typecheck-speed opportunity sweep: `--timings` showed stdlib typecheck alone is ~68% of `forge check`'s wall time on a small (10-file) real project (`~/code/march_doc`), ~19% on a 16-file one, down to ~5% on an 80-file outlier — a large, avoidable, constant cost paid on every invocation of `run_check_cmd` (the `march check f1 f2 ...` subcommand `forge check`/`forge build` batch onto). **Investigated a persistent-daemon design first (see the plan doc's superseded "REVISED" section) but found it unnecessary:** `Typecheck.check_module_core` gained an additive `?seed_env` parameter — when given, pass 1 starts from it instead of `base_env`, with NO other change to pass 1/1b/2's structure, so every existing caller (passing `None`) is byte-for-byte unaffected. `bin/main.ml`'s `run_check_cmd` now builds (or loads from an on-disk Marshal cache, `get_stdlib_tc_env`, keyed by a content hash of `stdlib_decls`) a `stdlib_tc_env` via `check_module_core` on stdlib decls ALONE, then typechecks just the user's own files seeded from it — UNLESS a user file shadows a stdlib module name (rare; falls back unchanged to the original from-scratch combined check rather than parameterizing the cache key on the shadow set). Verified byte-identical diagnostic output against the unmodified compiler across `march_doc`/`marathon`/`scroll`/`bastion` plus synthetic error/warning fixtures. Measured: `march_doc` `forge check` 0.86s → 0.20s (~4.3x) on a warm cache, `marathon` 0.51s → 0.16s (~3.2x); `scroll`/`bastion` (both shadow a stdlib name via a transitive `depot` dependency) see no change, by design. **A real regression was found and reverted before shipping:** an earlier version also wired `compile` (`--compile`) the same way, but `compile`'s `desugared` value is ALSO used for TIR lowering (which needs stdlib's function BODIES, not just types) — skipping the stdlib prepend there silently dropped stdlib from what gets lowered, breaking every compiled program touching real stdlib internals. Caught by the full test suite (24 codegen + 6 stdlib failures, all "type-incorrect TIR reached codegen" ICEs) before being reported as done; `compile` was reverted to its original always-prepend behavior. Caching stdlib's LOWERED TIR for `--compile` is explicitly out of scope (a separate, riskier follow-up — `lower.ml`'s heavy use of global mutable `Hashtbl` refs makes this a bigger undertaking, not justified by `--compile`'s smaller measured lowering-cost share vs. typecheck's). Full six-runner suite green (804 stdlib / 391 codegen / 428 compiler / 231 eval, 0 failures) after the revert.
