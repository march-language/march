# Shadowed same-block `let` rebinding — two-bug fix (2026-07-08)


- ✅ **`lib/tir/js_emit.ml` alpha-renames shadowed same-block `let` bindings instead of reusing the literal source name.** TIR (`lower.ml`) intentionally does NOT alpha-rename a shadowed `let x = ...; let x = f(x)` — each binding's `Tir.var.v_name` is the literal source name (confirmed via a standalone post-lower TIR dump: `let x : Int = 5 in let x : Int = +(x, 1) in ...`, correct at that stage). `js_emit.ml` previously emitted the second binding as `const x = ...` inside a fresh `{ }` block, relying on JS block scoping alone for "shadowing" — but when the initializer references the PRIOR `x` (the common `let x = ...; let x = f(x)` idiom, and the `let s0 = if s0 == 0 do 1 else s0 end` shape used by `Random.seed`), JS `const`/`let` TDZ covers the declaration's own initializer, so the reference resolved to the not-yet-initialized new `x` and threw `ReferenceError: Cannot access 'x' before initialization` at runtime under `--target js`. Fixed with a per-function shadow-tracking map (`ctx.var_names`/`ctx.var_counters`, `fresh_name_for`/`commit_var` in `js_emit.ml`): a shadowing `let` mints a fresh JS identifier (`x$1`, `x$2`, ...) and only commits it to the active-name map AFTER its initializer is emitted (so the initializer still resolves against the OLD mapping), including param-name shadows (`fn f(x) { let x = x + 1; ... }`) via seeding `ctx.var_names` from `fn_params` in `emit_fn_decl_impl`.
- ✅ **`lib/tir/cprop.ml` had an independent, more severe bug with the same root cause — silently WRONG values (not a crash), in every target including native, whenever TIR optimization is enabled (the default).** `Cprop`'s constant-propagation `env` (name → known literal) was extended on a bare-literal rebind (`let x = 5`) but never INVALIDATED on a later same-name rebind whose RHS wasn't itself a literal (`let x = x + 1`) — so the stale outer literal stayed active for the rest of the block, and every subsequent reference to the (rebound) name was wrongly substituted with the OLD value. Confirmed via bisection across the full `bin/main.ml` pipeline (a standalone debug harness dumping TIR after each pass in order: Mono → Fusion → Defun → Known_call → Beta_adt → Join_points → Simplify(pre) → Perceus → Escape → Opt): `let x = 5 in let x = x + 1 in int_to_string(x)` was still correct (`+(x, 1)`) through Escape, but the post-Perceus `Opt.run` fixpoint (which runs `Cprop.run`) folded it to `int_to_string(5)` — wrong, should be 6. Fixed by shadowing (dropping) any existing `env`/`avar`/`fenv` entry for the rebound name before conditionally re-adding new knowledge, in `Cprop.cprop_expr`'s `ELet` case — the RHS is still evaluated against the UN-shadowed tables (so `let x = x + 1` still sees the prior `x`), the shadow only applies going into `body`.
- ✅ **New dual-target golden test: `test/native/let_shadow_rebind.march`/`.expected`** (`native_let_shadow_rebind` + `js_let_shadow_rebind` rules in `test/dune`, modeled on the existing `let_tuple_destructure` dual-target pair) — covers arithmetic rebind, the `Random.seed` if/else rebind shape, a 4-deep shadow chain, and a rebind shadowing a fn parameter; asserts native (`--compile`, default opt) and JS (`--target js`, default opt) both match the interpreter's ground truth (`6`/`13`/`4`/`12`). Both bugs had to be fixed together for this test to pass under DEFAULT flags (opt enabled) — fixing only `js_emit.ml` left native and default-opt JS silently wrong via the `Cprop` bug.
- ✅ **Stdlib audit: `stdlib/random.march`'s `mix`/`seed` are the only genuine same-block self-referential shadow sites found.** A heuristic grep across `stdlib/**/*.march` for repeated `let NAME = ...` within a function turned up 44 candidates; manual inspection showed all but `random.march` are false positives (separate `match`/`if-else` arms binding the same name independently, not a shared same-scope rebind) — e.g. `hamt.march`/`set.march`/`map.march`'s repeated `idx` and `msgpack.march`'s repeated `len` are each in mutually-exclusive branches. No other stdlib source changes were needed; `random.march`'s `mix` (5-deep `x` shadow chain) and `seed` (`s0` if/else rebind) now compile correctly under `--target js` without any workaround.
- ✅ **Full suite green:** `scripts/run-tests.sh` (805 tests, quick + slow) and the two new golden-test rules (`native_let_shadow_rebind`, `js_let_shadow_rebind`, verified via direct `dune build` + diff against `.expected`) all pass.
