- ✅ **Fix string ordering comparison miscompiled in the native path (`List.sort_by` garbage order)** — string `<`/`<=`/`>`/`>=` in compiled code compared the string struct POINTERS as integers instead of comparing contents, so any compiled program ordering strings through a comparator (e.g. `List.sort_by`) produced wrong/no-op order while the interpreter stayed correct. Root cause in `lib/tir/llvm_emit.ml`: the comparison-emission path (`is_int_cmp`) special-cased only string `==`/`!=` (→ `march_string_eq`); ordering operators fell through to the `icmp` integer/pointer fallback. Fix: added an `is_string_ord` branch that calls `march_compare_string(a, b)` (returns −1/0/1) and compares the result against 0 with the matching signed predicate. Regression tests added in `test/test_march.ml` (adversarial-regressions): an IR-level assertion that a polymorphic String comparator through a closure emits `call i64 @march_compare_string`, plus a value-level `List.sort_by` ascending/descending ordering check. 1418 → 1420 tests.
