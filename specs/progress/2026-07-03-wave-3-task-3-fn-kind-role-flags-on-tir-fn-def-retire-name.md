# Wave 3 — Task 3: `fn_kind` role flags on `Tir.fn_def` — retire name-sniffing (2026-07-03, `specs/plans/2026-07-03-wave3-chunk1-refactors.md`)


- ✅ **Added `Tir.fn_kind` (`FnNormal | FnLambda | FnJoinPoint | FnApply | FnFused`) as a mandatory field on `Tir.fn_def`, set honestly at all 21 synthesis sites in `lib/tir/*.ml`** (lower.ml ×15 covering parsed user/stdlib fns, `ELam`/`ELetFn` lambda-creation sites, the `compile_matrix` hoisted-fallback join point, actor handler/dispatch/spawn glue, module-level-`let`-as-zero-arg-fn, builtin Eq/Ord/Show/Hash iface shims, and `__march_test_N__`/`__march_setup__`/`__march_setup_all__`; defun.ml ×1 for the closure apply wrapper; fusion.ml ×3 for the map/filter/fold loop-fusion helpers). ADAPTED the plan's suggested kind list: dropped `FnTryThunk` (no synthesis site exists — `__try_call`/`__try_call_val` are typecheck/eval builtins, never lowered to a TIR `fn_def`; the thunk passed to them is an ordinary `FnLambda`), added `FnFused` (fusion.ml's generated loop helpers — a real synthesis site the plan's list missed; no consumer currently sniffs these names, so the kind exists purely for honest labeling, not yet load-bearing).
  - **Consumers converted with transitional flag-vs-sniff asserts (mandatory this chunk, removed in Chunk 2):** all three `Tir_names.is_apply_fn` call sites — `perceus.ml`'s post-call EDecRC/closure-consumes-`$clo` gating (via a new `_fn_kinds` module-level lookup table, mirroring the existing `_borrow_map`/`_type_defs` convention), `llvm_emit.ml`'s `emit_fn` (direct — the `fn_def` is already in scope), and `llvm_emit.ml`'s general `EApp` case (via a new `ctx.top_fn_kind` Hashtbl populated once from the top-level module's `tm_fns` at `emit_module`'s entry; deliberately NOT populated at the ~10 scattered REPL/JIT incremental pseudo-module registration sites — those callees have no table entry and the assert is skipped there, not treated as a mismatch). Zero assert firings across the full six-runner suite (1851 tests) — every synthesis site agreed with the pre-existing name-sniffing logic it replaces.
  - **Two named consumers left unconverted, by design, documented in place:** `borrow.ml`'s `is_clo_struct` checks a `Tir.ty` (closure-struct TCon name from an EAlloc), not a `fn_def` — there is no `fn_kind` to assert against without re-deriving the lambda's `uid` back out of the type name, which would be a new fragile re-derivation, not a fix. `borrow.ml`'s `is_try_call` checks a call-target name against the hardcoded `__try_call`/`__try_call_val` builtin names — since those are never TIR `fn_def`s, a `fn_kind` lookup by that name would always miss; this is builtin call-target dispatch, not synthesis-role classification (same shape as the `"task_spawn_steal"` check elsewhere).
  - **Printer caveat honored:** `pp.ml`'s `string_of_fn_def` and `tir.ml`'s `show_fn_def` write specific fields by name (not exhaustive record patterns) — neither needed an edit, neither prints `fn_kind`; snapshot output stayed byte-identical (0 `.expected` diffs).
  - **Critical finding, flagged not fixed:** `lib/cas/serialize.ml`'s `write_fn_def`/`write_letrec_fn`/`write_fn_sig` (feeds `impl_hash`/`sig_hash` — cross-binary RPC admission + the CAS artifact cache key) likewise write fields by name and so did NOT start hashing `fn_kind` — verified explicitly and documented with an in-code warning that `fn_kind` must NEVER be added there (it would silently invalidate every cached artifact and change RPC admission the day it was hashed — `fn_kind` is a same-binary compiler-internal role tag, not part of a function's externally observable identity).
  - **Test-file mechanical fallout:** adding a mandatory record field forced every `Tir.fn_def` literal across the repo to set it (`bench/bench_opt.ml`, `test/test_cas.ml`, `test/test_codegen.ml`, `test/test_compiler.ml`, `test/test_eval.ml`, `test/test_helpers.ml`, `test/test_hot_reload.ml`) or the build would not compile — OCaml has no default field values. This unavoidably included **`test/test_properties.ml`** (on the plan's "do not touch" list); applied the plan's own `bin/`-exception precedent ("except if a moved module forces a reference update — flag it") since there is no way to make one field mandatory-everywhere-except-one-file in OCaml.
  - **Proof of behavior preservation:** zero TIR snapshot churn (29/29 `run_snapshots` green). Same-machine A/B against a detached-HEAD `git worktree` built from `0cd6b627`: all four `specs/benchmarks.md` benchmarks produce identical outputs with timings within noise (tree_transform ~8.0s both; list_ops/binary_trees/mutual_recursion sub-second, both sides matching to within measurement noise). **384 compiler / 230 eval / 364 codegen / 791 stdlib / 53 stdlib_march / 29 snapshots — all six runners exit 0 (1851 tests total).**
