- ✅ **FBIP niche self-reference fix (`lib/tir/llvm_emit.ml`, 2026-06-22)** — The FBIP (frame-based in-place) optimization in `llvm_emit.ml` wrongly generated a self-referential object for niche-encoded patterns like `Some(result) -> Ok(result)`. For niche `Option`, the payload IS the scrutinee (no wrapper allocation), so the FBIP reuse branch overwrote the payload's own structure (`store ptr result, ptr result+16`) creating a cycle. The fresh branch also wrongly called `march_decrc` on the reuse atom, decrementing the very value about to be stored as Ok's field. Fix: in the `EReuse (reuse_atom, TCon(ctor,_), args)` handler's fallback branch (`lib/tir/llvm_emit.ml`), detect when `reuse_atom`'s parent type is niche-shaped (`Repr.is_niche_shaped`) and skip FBIP entirely — allocate fresh without touching the reuse atom's RC (ownership flows from niche payload → branch var → Ok field). Root cause: Perceus's `add_scrutinee_free_for` insertes `EDecRC(scrutinee)` because the scrutinee and branch var have different TIR names even though they're the same runtime pointer under niche encoding; `args_alias_reuse` can't catch value aliasing. Verified: `dune build` clean, 300 compiler + 320 codegen tests all pass. This unblocks `NetKernel.recv_frame` which was hanging due to the self-referential Ok object confusing `List.length` in the caller.
