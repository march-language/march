# Bundled z3: refinements that work on a fresh install

Design: `specs/2026-11-02-bundled-z3-design.md`. Plan: `specs/plans/2026-11-02-bundled-z3.md`.
Road to 1.0, Pillar 4 / Phase 2.

## What landed

- **Pin and lookup.** `z3.version` holds the pinned version (4.16.0) and the source
  tarball's sha256; `lib/refine/z3_pin.ml` is generated from it. `Solver.find_z3` looks in
  `MARCH_Z3` (a set path that does not exist is broken, not a fall-through; empty counts as
  unset), then `<real exe dir>/../libexec/z3` (through symlinks, so forge's
  `~/.march/current` works), then `PATH`. `Solver.probe_version` runs `z3 --version` with
  no stdin and under the hang backstop, memoised in process and on disk
  (`~/.cache/march/z3-probe/`), so a warm machine never runs z3 just to learn its version.
- **rlimit instead of a timeout.** Every query is sent after `(reset)` with
  `(set-option :rlimit N)`: 3,000,000, and 50,000 for stage-2 reflection queries
  (`2026-11-02-z3-rlimit-measurement.md`). No `:timeout` is sent. The only wall clock is a
  60 s backstop (`MARCH_Z3_BACKSTOP_MS`) that raises `Solver.Hung`; a hung query costs only
  itself (not retried, not cached), where two hangs used to disable z3 for the rest of the
  run. `Solver.result` gained `Rejected` (z3 refused the query), split from `Unknown`;
  an rlimit `Unknown` is cached, a `Rejected` never is.
- **Cache keys.** `Vc_cache.key_of_vc` hashes `Solver.identity` (z3 version, limits,
  platform; never the path). The build cache's tag (`Solver.cas_tag`) never runs z3: it uses
  a probe already on disk, else `unprobed`. Determinism oracle green (small corpus).
- **Warnings.** `solver_unavailable` (missing, broken, crashed or hung mid-run) and
  `solver_version_mismatch`, one per run, only for a run with obligations in the user's own
  files, reported on the entry file's first line so a warm build replays it. Under
  `cap verified`, a solver-undecided obligation's reason reads "the solver could not be run".
  `--explain` pages in `specs/lang/errors/`.
- **Overrides.** `--refine-rlimit N`, `MARCH_REFINE_RLIMIT`, and forge.toml
  `[refine] rlimit = N` (passed through `Cmd_build.lib_path_env`, the prefix behind every
  march forge runs). Stage 2 keeps its ratio to the main limit.
- **Release and CI.** `scripts/install-z3.sh PREFIX [--static]` builds z3 from the pinned,
  checksum-verified source with cmake. `build.yml` builds it (static inside the Alpine
  containers), ships `libexec/z3` and `licenses/z3-LICENSE.txt`, and the archive checks
  require them, run `libexec/z3` in bare images, and prove a refinement violation with no z3
  on `PATH`. `.github/actions/march-setup` puts the same pinned build (cached) on `PATH`
  instead of brew/apt's z3, and builds blake3 per architecture.
- **Agreement.** `scripts/refine-verdicts.sh` writes every per-site refinement verdict of
  `test/native`, the conformance corpus and the stdlib; CI's `refine-agreement` runs it on
  darwin-arm64, linux-x86_64 and linux-aarch64 and fails on any difference.

## Decisions taken while building (beyond the design)

- Every run checks the stdlib's own obligations (~340 queries for hello-world), so "a program
  with no refinements never probes z3" does not hold. The warning instead fires only for
  obligations in the user's own files; a broken z3 is still started by the stdlib queries.
- The codes are `solver_*`, not `z3_*`: doc-lint Check G and `seed-error-corpus.sh` match
  slugs as `[a-z_]+`.
- The platform keys every cached verdict, not only rlimit-unknowns.
- With no usable z3 the VC key is `noz3`, so a warm cache serves no verdicts without z3.

## Verification

- New suites: `test/test_z3_lookup.ml` (lookup, probe, driver-level warnings with fake z3s,
  the rlimit flag/env), `test/test_refine.ml` (rlimit, reset, backstop, hung query, keys),
  forge's `forge_toml_refine_rlimit_passed`, typecheck unaffected.
- refinecheck suite green with no case edited; determinism oracle green; doc-lint green.
- Locally: z3 built from source on macOS (3 min, 14 cores); a release-shaped install proved a
  refinement with `PATH=/usr/bin:/bin`. The static Linux build is verified only by CI (no
  Docker daemon here).
