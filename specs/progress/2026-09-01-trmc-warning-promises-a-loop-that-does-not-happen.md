# The non-tail-recursion warning promised a TRMC loop that does not happen

**Filed:** 2026-09-01  **Resolved:** 2026-09-01

The warning in `lib/typecheck/typecheck_tailcall.ml` for structural non-tail
recursion ended with:

> …may use O(depth) stack space; **when the recursive call is the direct
> argument of a constructor, the compiler turns it into a loop.**

A function written in exactly that shape still warned *and* still overflowed.

## Which of the two cases it was

Neither cleanly — and the distinction matters, so it is recorded here.

**TRMC is not broken. It is off by default.** `lib/tir/trmc.ml:467` is
`let enabled : bool ref = ref false`; the pass only runs under `--trmc` (or the
legacy `MARCH_TRMC`). The transformation itself is implemented through Phase 4
and works on this exact shape.

Evidence, all on the 400k repro from the original report:

| build | result |
|---|---|
| `--compile --opt 2` (default) | exit **138** (SIGBUS, stack overflow) |
| `--compile --opt 2 --trmc` | exit **0**, prints `399999` |
| control, no user recursion | exit 0, prints `399999` |

`MARCH_TRMC_REPORT=1` classifies the repro's `map_inc` as
`eligible … modcons=1 other=0  List.Cons@1` — i.e. the analysis agrees the
shape is transformable; nothing runs the transformation on the default path.

**Root cause of the false sentence.** It was not written in error. It was
written *in anticipation* of the default flip, by Task 9 of
`specs/plans/2026-08-10-trmc-on-by-default.md` (that step is checked off, and
quotes this exact replacement text). The later task in the same plan — actually
flipping `Trmc.enabled` — never landed. So the warning describes the
post-flip world while the compiler stayed in the pre-flip one.

A test pinned the false claim in place: `test_compiler.ml`'s
`…does_not_prescribe_accumulator` asserted the message *does* say
`"turns it into a loop"`, with a comment stating the shape "is compiled into a
loop by TRMC". Both were untrue on the default pipeline.

## What was done

Scope decision (with the user): **reword only.** Flipping the default is a
larger change that `specs/todos/2026-08-07-trmc-tail-recursion-modulo-cons.md`
deliberately reserves ("Still gated… Not a default pipeline stage"), with the
remaining coverage laid out in the 2026-08-10 plan. That plan stays open.

- `lib/typecheck/typecheck_tailcall.ml` — the non-arithmetic branch now states
  the real behaviour: deep input **can overflow the stack**, an accumulator is
  the fix available today, and TRMC "can compile a recursive call that is the
  direct argument of a constructor into a loop instead, but it is off by
  default; enable it with `--trmc`." The *arithmetic* branch (`f(n-1)`) is
  unchanged — TRMC can never transform it and "use an accumulator" was already
  correct there.
- `test/test_compiler.ml` — the test was inverted to assert the honest
  properties instead: the message must **not** contain
  `"the compiler turns it into a loop"`, and must contain `"overflow the
  stack"`, `` `--trmc` `` and `"off by default"`. Renamed to
  `test_structural_recursion_warning_states_trmc_is_opt_in`.

## Verification

- **Every claim the new message makes was executed, not just read.** Default
  build of the repro exits 138 ("can overflow the stack" — true); the same
  source with `--trmc` exits 0 ("enable it with `--trmc`" — true).
- **Non-vacuousness proved by perturbation.** Reverting *only* the message text
  to the old wording turns the new test RED (`Expected: false / Received: true`
  on "does not promise an automatic loop"); restoring it turns it GREEN.
- **The warning keeps its meaning.** A genuinely non-TRMC-able shape
  (`h + sum_len(t)` — a call under a binary op, classified `non-trmc`) still
  warns and still exits 138 *even with* `--trmc`. The warning is not merely
  suppressed for the shapes TRMC would handle.
- CI-only diagnostic-text gates, run with `--force` and checked by log contents
  rather than exit code: `@types-check` → `303 passed, 0 failed` (25 508-byte
  log, non-vacuous); `@grammar-check` → `48 passed, 0 failed`.
- Full `scripts/run-tests.sh` green, and green again with `MARCH_TRMC=1`.

## Not done (deliberately)

`docs/assets/march_compile.js` is a generated JS build of the compiler bundled
for the docs playground; it carries an even older revision of this string
("uses O(depth) stack space." with no TRMC clause) and is regenerated by the
docs build, not edited by hand.

The default flip itself remains open in
`specs/plans/2026-08-10-trmc-on-by-default.md`. The evidence gathered here
supports it — suite green with TRMC on, TIR snapshots inert with it off, 2.7x
measured on the list-producer workload — but it was consciously left as its own
change.
