- ✅ **Distributed OTP — L4 compiler enroll/stub (`remote_ref_hashes` + `remote_register_stub` + `remote_count` builtins, 2026-06-22)** — the compiler touchpoint that closes the CAS-hash gap: functions now carry their real identity into the runtime. Three new builtins wired through all three layers (typecheck `builtin_bindings`, eval `builtin_env`, codegen). **`remote_ref_hashes(mod, fn)`** is constant-folded at codegen time — the `emit_expr` handler intercepts the `EApp` before it becomes an LLVM call, looks up the Blake3 64-char hex hashes from the CAS pipeline's `hash_module` output, and emits a heap-allocated `(String, String)` tuple. Two fixes were required: (1) added all three builtins to `defun.ml`'s `builtin_names` so defun doesn't wrap them in closures (keeping them as `EApp`, not `ECallPtr`); (2) top-level user-module functions have no module prefix in their TIR `fn_name` (`"fib"` not `"TestRRH.fib"`) so the lookup tries the unqualified name when the qualified lookup misses. **`remote_register_stub(impl, sig, stub)`** maps to `march_remote_register` (runtime C registry). **`remote_count()`** maps to `march_remote_count`. **`march_remote_init()`** is auto-emitted in `@main` before user code runs. Eval path uses FNV-1a 32-char hex (deterministic, non-empty). Tests: 8 eval tests in `test_stdlib_march` (`test_remote_ref_hashes.march`) + 1 compiled native test (`test/native/remote_ref_hashes.march` — verifies 64-char Blake3 hashes with a recursive `fib` to survive DCE).
