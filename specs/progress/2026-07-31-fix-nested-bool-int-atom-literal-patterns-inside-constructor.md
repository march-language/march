- ✅ **Fix nested Bool/Int/Atom literal patterns inside constructor patterns miscompiled in the native path** — `match r do Ok(true) -> … Ok(false) -> … end` printed the FIRST bool arm for both inputs (T T E instead of T F E); nested Int/Atom literal matches segfaulted. The interpreter was always correct. Root cause in `lib/tir/llvm_emit.ml` `emit_case`: the field bound by the outer constructor pattern is ptr-typed at the LLVM level (its TIR type is a `TVar` placeholder), so the inner literal test took the heap ctor-tag path — `getelementptr; load i32; switch` — but ADT fields holding immediates are stored low-bit-tagged (`(n<<1)|1`), not as heap pointers, making the tag load a wild dereference. With an `unreachable`-defaulted switch LLVM folded the test away entirely (bool case: first arm always wins) or it crashed (int/atom cases). Fix: literal-pattern tags are syntactically unambiguous (lowercase `true`/`false`, integers, `:atoms` — ADT ctors are capitalized), so `emit_case` now detects all-immediate-literal-tag cases and never treats the scrutinee as a heap pointer: bool cases reuse the existing untag (`ashr`) + `trunc` + `br i1` path; int/atom cases switch on the raw `ptrtoint` bits against `(lit<<1)|1` labels (comparing tagged-vs-tagged is exact; untagging would lose bit 63 of 64-bit atom hashes). Same shape existed in `stdlib/check.march` `format_error` — correct only by accident of arm order; now correct by construction. Resolves the deferred discovery from the `__try_call` fix below. 3 IR-level regression tests (`nested_lit_pattern_codegen` group) assert exactly one i32 ctor-tag switch (the outer `Ok`/`Err`) survives. 1423 → 1427 tests after merge.
