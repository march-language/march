- ✅ **JIT Phase 3.2: actors work in the REPL** — `specs/plans/2026-04-22-jit-improvements-plan.md` Phase 3.2. Actor declarations parsed and typechecked fine, and `spawn`/`send`/`run_until_idle` compiled under the JIT — but the JIT backend calls into the runtime's native actor scheduler (`march_send`, `march_run_until_idle`) while the REPL registers actors only in the interpreter's scheduler. Result: sends succeeded, `run_until_idle()` returned `1` instead of `()`, and `println` inside message handlers vanished (they ran in a scheduler with no actor registered). Fix in `lib/repl/repl.ml`: a new `actors_declared` flag flips the moment any `DActor` is processed; once set, the three JIT paths (fn decl, let decl, ReplExpr) fall through to the interpreter in both `run_simple` and `run_tui`. Interpreter then owns spawn/send/receive for the rest of the session — consistent scheduler, visible `println` output. Smoke test: `actor Counter ... ; spawn ; send(Inc(5)) ; send(Probe()) ; run_until_idle()` now prints `5` and returns `()`, matching file mode.
