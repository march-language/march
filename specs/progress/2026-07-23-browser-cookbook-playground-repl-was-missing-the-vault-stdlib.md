- ✅ **Browser cookbook/playground REPL was missing the `Vault` stdlib module — `docs/cookbook/vault.md`'s examples errored with `no member 'new' in module 'Vault'` (2026-07-23, `js/march_browser.ml`, `scripts/gen-browser-stdlib.py`).** Reported by a user hitting the runtime error live on the docs site. `vault.march` is a fully working, fully-tested stdlib module — the interpreter builtins (`lib/eval/eval.ml`) are correct — but it was never added to either `js/march_browser.ml`'s `browser_stdlib_files` load-list (what the browser interpreter session actually loads) or `scripts/gen-browser-stdlib.py`'s `FILES` list (which bundles `docs/assets/march_stdlib.js`, the JS blob the browser reads module source from). So the module simply never entered the playground's environment, and `Vault.new`/etc. resolved as missing members on an otherwise-real module namespace (the exact error text comes from `eval.ml`'s `"no member '%s' in module '%s'"`, which only fires when the qualifier IS a known module). **Fix:** added `"vault.march"` to both lists, regenerated `docs/assets/march_stdlib.js` (`python3 scripts/gen-browser-stdlib.py`), rebuilt `docs/assets/march.js` (`dune build js/march_browser.bc.js`). Verified against the rebuilt bundle directly in Node (not just the OCaml test suite, since this bug is browser-bundle-only and the OCaml suite doesn't exercise it): both the "Basic CRUD" snippet and the full rate-limiter example from `docs/cookbook/vault.md` now run correctly end-to-end (`hit 1: true / hit 2: true / hit 3: true / hit 4 (over limit): false`). **Same report, second bug:** `docs/cookbook/capabilities.md`'s "sandboxed plugin runner" example called `sandbox_eval`, which never existed anywhere in the compiler or stdlib — pure illustrative pseudocode that could never run in the same playground REPL (`unbound variable: sandbox_eval`). Stubbed it inline (`fn sandbox_eval(code : String) : Result(String, String) do Ok("evaluated: " ++ code) end`) so the example compiles and runs as written; the example's actual teaching point (the `PluginCap` capability gate around `run`) is unaffected. Verified: prints `result: evaluated: 1 + 1` with no error. Both landed on `main` (merge commit `88402bcc`).
