- ✅ **`DataFrame.eval_agg` O(n) boxing overhead on Min/Max/Std/Variance (2026-07-27).** Reported as "~40ms fixed overhead per call regardless of column size" on `Sum`; a from-scratch multi-size microbenchmark showed it's not fixed at all — it scales linearly with row count (100K rows: ~8ms/call, 500K rows: ~43ms/call), because `eval_agg`'s `Min`/`Max`/`Std`/`Variance`/`Median` branches called `float_list(df, col)` to materialize a boxed `List(Float)` from the column's `NativeArray` before folding over it with `Stats.*`, paying an O(n) allocation on top of the O(n) reduction. `Sum`/`Mean` had already been fixed in the same session (commit `f4301ac0`, landed just before this investigation) by routing through `native_float_arr_sum`/`native_int_arr_sum` directly; this extends the same idea to `Min`/`Max`/`Std`/`Variance`. **False start, load-bearing lesson:** a March-level recursive index loop calling `native_float_arr_get(arr, i)` per element looks allocation-free but isn't — `get`'s `Float`/`Int` return is boxed at the call site under the generic calling convention any ordinary March function uses, so it pays the *same* O(n) boxing cost as `float_list`, just with one box per element instead of one box-plus-cons-cell. Confirmed by benchmarking the index-loop version directly: no improvement over the original. **Real fix:** six new compiler builtins that each stay inside a single C-level reduction loop, mirroring `native_float_arr_sum`'s existing pattern exactly — `native_{float,int}_arr_min`, `native_{float,int}_arr_max`, and `native_{float,int}_arr_sumsq_dev(arr, mean)` (sum of squared deviations from a precomputed mean — the stable second pass of the standard two-pass variance algorithm; not bit-identical to `Stats`' single-pass Welford but equally free of catastrophic cancellation, and verified numerically matching `Stats.variance_safe`/`std_dev_safe` to full precision on a test vector). Touched all five sites a native-array builtin needs (`runtime/march_runtime.c`, `lib/tir/llvm_builtins.ml` declare_sig + PDeclare, `lib/tir/defun.ml` builtin_names, `lib/eval/eval.ml` interpreter case, `lib/typecheck/typecheck.ml` type signature). `DataFrame.col_native_min_max`/`col_native_moments` replace the old `float_list`-based `Min`/`Max`/`Std`/`Variance` branches; `Median` is untouched (needs a full sort, a separate and larger problem — `Stats.percentile`'s `List.nth` on a linked list is itself O(n) per call, independent of this boxing bug). Result: Min/Std at 500K rows went from ~33-42ms/call to ~0.5-0.6ms/call (60-80x), matching Sum/Mean's existing native-path speed. **Regression benchmark:** `bench/dataframe_bench.march`'s new `bench_agg_overhead` compares direct `NativeArray.sum_float` against `DataFrame.eval_agg(Sum)` over 500K rows and panics if the ratio blows up past 20x while eval_agg takes ≥5ms absolute — verified it actually fires by temporarily reintroducing the `float_list`-based `Sum` branch (41ms, panicked as expected) and confirmed silent on the fixed code. **Process footgun, twice:** editing this repo from inside a worktree, passing the MAIN REPO's absolute path to a file-editing tool (rather than the worktree's own path) edits the wrong checkout with no error — happened once for `stdlib/dataframe.march` and again for all five compiler-builtin sites, caught only because the compiled benchmark showed zero improvement despite the source apparently having the fix; recovered by diffing the two checkouts, copying the main-repo edits into the worktree, and `git checkout --` to restore the main repo. Also relearned the existing "stale `_build/default/stdlib`" and "CAS cache lives per-worktree, not in the main repo" gotchas along the way.
