# Wave 2 — Task 3: W2.1 — LLVM IR validity gate (2026-07-02, `specs/plans/2026-07-02-wave2-testing-infra.md`)


- ✅ **Emitted LLVM IR is now verified for the whole native fixture corpus — new `test/test_ir_verify.ml`, wired into `run_codegen.exe`.** Previously nothing ever ran an LLVM verifier over emitted IR; an ill-typed emission (the `coerce` catch-all class, or any other emitter bug producing textually-plausible-but-type-incorrect LLVM assembly) only ever surfaced as an opaque `clang` parse/verify failure at `--compile` time, with no locatable `.ll:line:col` pointer at TEST time. **Tooling probe:** Xcode's Command Line Tools clang does NOT ship `opt`/`llvm-as` (`xcrun -f opt` fails) — the verifier had to come from Homebrew LLVM (`brew --prefix llvm`, not linked onto PATH to avoid shadowing Xcode's clang). `find_llvm_verifier_tool` (`test/test_helpers.ml`) probes, in order: `opt` on PATH, `opt` at the brew keg, `llvm-as` on PATH, `llvm-as` at the brew keg; `` `None `` is a legitimate, counted skip (`record_jit_skip`, same ledger as the W2.0 clang-absence skips) — never a silent pass. This machine has `opt` at `/opt/homebrew/opt/llvm/bin/opt` (Homebrew LLVM 22.1.1); the gate ran for real, not skipped. **RED:** a hand-crafted `.ll` with an `i64`/`double` type mismatch (`%r = add i64 %x, %f` where `%f` is `fadd double`) is asserted REJECTED by `verify_llvm_ir_file` (`opt -passes=verify -disable-output`, rc≠0 with a locatable `file.ll:line:col` error) — proven to actually matter by temporarily sabotaging the helper to always return `` `Ok `` and confirming the RED test then fails (restored clean afterward); a converse sanity test confirms well-typed hand-crafted IR is accepted, so the gate isn't just "reject everything." **Gate:** one aggregated Alcotest case (`test_native_corpus_ir_is_verifier_clean`) emits IR via `--emit-llvm` (bypasses the CAS artifact cache entirely, unlike plain `--compile`, so the gate always inspects freshly emitted text) for every `test/native/*.march` fixture and runs the verifier, collecting every failure before asserting (a full run names every bad fixture in one shot rather than stopping at the first). **Finding, disposition = scope exclusion, not a loud skip:** of the 43 `test/native/*.march` fixtures, the 6 `js_*` ones (`js_dom_available`, `js_extern_import`, `js_ffi_async`, `js_ffi_blocking_raises`, `js_ffi_cbacked`, `js_ffi_raises`) are compiled ONLY with `--target js` anywhere in `test/dune` (producing a `.mjs`; the JS backend never touches `Llvm_emit` at all — confirmed in `bin/main.ml`'s JS-target branch, which returns before the LLVM/clang path). Compiling them natively instead (no `--target js`, what a naive "gate everything in test/native/" would do) DOES produce a `.ll` that fails verification — the emitted `declare` for a JS-side extern keeps its raw JS-style name verbatim (e.g. `@node:path_dirname`, `@./foo.mjs_bar`), and `:`/`.`/`/` are invalid characters in an LLVM identifier — but this is a probe artifact, not a real bug: no existing test ever exercises these 6 fixtures as native IR, only as `.mjs`. `list_native_fixtures` (`test/test_ir_verify.ml`) therefore excludes any `js_`-prefixed fixture, mirroring actual `test/dune` usage rather than inventing a loud skip for a scenario the corpus never puts them in. **GREEN on the real corpus:** all 37 gated (non-`js_`) fixtures emit verifier-clean LLVM IR as of 2026-07-02 — zero emitter bugs found, no `specs/todos.md` entries needed for this task. **Design: new file, not a growth of `test_codegen.ml`** (already ~6400 lines) — a distinct corpus-scanning concern (walk a directory, shell out to an external tool, aggregate a failure list) vs. `test_codegen.ml`'s single-source-snippet IR assertions; wired into the EXISTING `run_codegen.exe` runner per the task brief (`Test_codegen.codegen_suites @ Test_ir_verify.suites`), not a 6th dune test executable, so the mandated five-runner invocation recipe is unchanged. **Review hardening (same commit):** (1) the `js_` exclusion is loud, not silent — an `at_exit` note names every excluded fixture in the terminal (same mechanism as the W2.0 skip ledger), plus a misclassification invariant: the gate FAILS if `test/dune` ever contains a `native_<fixture>` compile rule for an excluded `js_` fixture (`assert_excluded_are_js_target_only`). (2) A real temp-dir leak found and fixed: even `--emit-llvm` drops a `.march/cas/vc/` verdict-cache tree in its CWD, so the original flat remove+`rmdir` cleanup silently ENOTEMPTY'd on every fixture (~240 leaked dirs observed); replaced with `rm_rf_temp_dir` (`test/test_helpers.ml`) — recursive, lstat-based (symlinks removed as links, never followed), and SELF-CONFINING: refuses `""`/`"/"` outright and refuses (`Alcotest.failf`, deleting nothing) any existing path that is not a strict realpath-resolved descendant of the realpath-resolved system temp root (realpath on both sides neutralizes the macOS `/var`→`/private/var` `$TMPDIR` spelling mismatch); the unconfined walker is local to the function so it cannot be called unguarded. Confinement unit test (refuses `""`, `"/"`, and an existing outside-temp-root dir, with a sentinel file asserted to survive) proven load-bearing by sabotage (guard arm removed → test fails exit 1; restored byte-identical). **384 compiler / 227 eval / 346 codegen (+4 new: RED-rejects, valid-IR sanity, delete-confinement, corpus gate) / 790 stdlib (789 pass + 1 pre-existing documented skip from W2.0) / 53 stdlib_march all pass, all exit 0.**
