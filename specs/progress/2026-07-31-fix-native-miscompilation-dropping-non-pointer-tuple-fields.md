- ✅ **Fix native miscompilation dropping non-pointer tuple fields (module-nested default-arg fns)** — a module-nested fn with default-arg params (`fn greet_d(name, loud : Bool \\ false, suffix : String \\ "?")`) desugars — because `FPDefault` forces `desugar_fn_def`'s general match-merge path — into `match (a, b, c) do (x, y, z) -> …`, a tuple built from the args and immediately destructured. Native codegen silently corrupted any non-pointer (`Bool`/`Int`/`Float`) field: `ETuple`/`EAlloc` **build** the tuple storing each field with its concrete LLVM type (a `Bool` is a raw `i64`), but `emit_case` **destructured** via the synthetic `$TupleN` `ctor_info` entry whose fields are all `TVar "_"` → `ptr`, so the load untagged (`ashr 1`) a value that was never tagged — `loud = true` (`1`) arrived as `false` (`1 >> 1 = 0`). The repro printed `Def!` instead of `Def *!` natively while the interpreter stayed correct. Fix in `lib/tir/llvm_emit.ml`: `resolve_ctor_fields` gained a `TTuple ts -> ts` case, and `emit_case`'s field-binding loop now loads tuple fields with their **concrete element types** (matching `ETuple`/`EField`) instead of the polymorphic `ce_fields` fallback; variant ctors keep `ce_fields` (their generic `TVar` fields ARE stored tagged via `coerce i64→ptr` in `EAlloc`). Also a general bug — any `(_, Bool, _)` tuple destructured natively was affected, not just default-arg fns. Regression wired into `dune runtest`: `test/native/default_args_nested.march` is compiled natively, run, and its stdout diffed against `test/native/default_args_nested.expected`. Downstream: bastion's `test/test_form.march` "required marker appended to label" test (`Form.Input.render`'s `required = true` was dropped) now passes natively.
