- ✅ **`Bool` and `Float` refinements are enforced (`lib/refine/smt.ml`, `lib/refinecheck/refine_check.ml`, 2026-07-27).** Both parsed and type-checked while producing no verification condition at all; probed against the built compiler first and confirmed inert — `needTrue(false)` against `{Bool | _ == true}` and `sqrtish(0.0 -. 1.0)` against `{Float | _ >= 0.0}` each exited 0 with zero warnings, while an `Int` control of identical shape in the same file reported. **Bool** needed only the missing dispatch: `is_bool_base` beside `is_string_base`, wired through `refined_param_ty` / `refined_scope_ty` / `return_refine_sorted` / `return_refine_ext`, with the value reflected at `Smt.SBool`. **Float** is a new sort. **The encoding is Z3's bit-precise IEEE-754 FloatingPoint theory, NOT reals, and that is a correctness requirement rather than a preference:** the query `¬(x >= 0.0) ∧ ¬(x <= 0.0)` is **sat** over `Float64` (witness `NaN`, confirmed by asking z3 directly) and **unsat** over `Real` (trichotomy). The checker reports exactly when it proves a predicate can never hold, so a reals encoding would flag that ordinary contract on every argument — a demonstrated false-positive source, not a theoretical one. Verified empirically end-to-end: a predicate whose only witness is NaN is SKIPPED, not reported. Equality is `fp.eq`, not SMT-LIB `=`: `=` on `Float64` is bitwise, under which `{Float | _ != 0.0}` would accept `-0.0`, a divisor as bad as `+0.0`; under `fp.eq` a negative-zero argument IS reported (confirmed with a `0.0 *. (0.0 -. 1.0)` fixture). **Sort plumbing.** The `sort` marker channel previously meant "None = Int, `Some s` = a DECLARED sort name"; `$Bool`/`$Float` are a third shape (built-in SMT sorts), so every consumer that treats an unrecognised `Some s` as an ADT name now tests `is_scalar_sort` first — otherwise `(declare-const b $Bool)` names a sort nobody declared. `fn_sig` gained `param_scalar`; `reflect_scalar` gained a `~sort`; `check_post` gained a `~scalar_env` for a clause's declared-`Bool` parameters (`scope` carries only *refined* locals, so a bare `b : Bool` was invisible to it). **Containment, since adding a sort is what has poisoned the shared `z3 -in` channel before.** A `sort_conflict` guard abandons any VC declaring one symbol at two sorts; `float_wellsorted` drops any term still mixing a float with an Int after the `fp_rewrite` pass; and a new `formula_wellsorted` drops a term in Boolean position that is not a formula. That last one fixed a **pre-existing** malformed-VC source found during the sweep: a bare Bool guard (`if j do needTrue(k) else 0 end`) reflected `j` as an integer constant and asserted it, drawing `invalid assert command, term is not Boolean`. March spells float comparison with the ordinary operators, so `smt_of` cannot distinguish Int from Float and builds `Smt.Ge` for both; `fp_rewrite` runs over the finished term once the declarations are final and converts only comparisons whose BOTH operands are float-sorted. **Out of scope, and silent rather than guessed:** symbolic float arithmetic in a predicate (`_ +. 1.0 > 0.0` — modelling it needs rounding-mode surface), `Float` record fields and ADT payloads, special-value predicates (`is_nan`), and a literal with no exact plain-decimal SMT-LIB form. Literal-only float arithmetic IS folded (`0.0 -. 1.0`), which is how the negative literal March has no direct spelling for is recognised. **9 new tests** (236 → 245) in `bool-refinements` and `float-refinements` groups, 5 of them asserting SILENCE. Adversarial sweep — unknown Bool/Float in the newly-checked position, a fact retired by each of the five binding forms, Float alongside Int/String/record/ADT parameters in one function, unproven Bool and Float postconditions, guards about the wrong value — all exit 0 cold-cache with **zero** `(error` lines on a tee'd solver channel, and a 12-violation-kind file reports all 12, also with zero errors. `test_refine`, `run_compiler`, `run_eval` and `scripts/check-docs.sh` clean.
