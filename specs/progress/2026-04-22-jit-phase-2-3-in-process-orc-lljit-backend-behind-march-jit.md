- ✅ **JIT Phase 2.3: in-process ORC LLJIT backend behind `MARCH_JIT_BACKEND=orc`** — `specs/plans/2026-04-22-jit-improvements-plan.md` Phase 2.3. New `lib/jit/jit_orc_stubs.c` drives LLVM's ORCv2 C API: `LLVMOrcCreateLLJIT`, `LLVMOrcLLJITAddLLVMIRModule`, `LLVMOrcLLJITLookup`, process-wide `DynamicLibrarySearchGenerator` so already-dlopen'd stdlib/runtime symbols resolve inside the JIT. libLLVM.dylib is `dlopen`'d lazily on first `Jit_orc.create` (fallback paths for Homebrew / system, `MARCH_LLVM_LIB` override); linker flag `-Wl,-undefined,dynamic_lookup` lets us reference LLVM symbols without a link-time dep (avoids +157 MB on every startup). `Repl_jit.compile_fragment` is now a backend dispatcher returning a `fragment_handle` sum; `lookup_sym` abstracts `Jit.dlsym` vs ORC lookup. Clang path still handles the stdlib prelude and is the default. **Measured gain on 30-fragment REPL: 4.52 s → 0.19 s (~24× end-to-end); per-fragment latency 145 ms → 0.2 ms after an 11 ms LLJIT warmup.** Smoke test: 54/54 PASS on both backends.
