- ✅ **Parallel list ops + parallelization lint (2026-06-21)** — `stdlib/list.march` gains `pmap`, `pmap_n` (bounded concurrency), `pfilter`, and `preduce` (parallel associative reduction; associativity is the caller's contract). All order-preserving, identical results to the sequential forms; chunked via `List.chunks` over one task per chunk on the existing multithreaded scheduler (real parallelism in compiled code — verified ~281% CPU; sequential in the interpreter). New nullary builtin `pmap_threshold() -> Int` (typecheck `Mono Int`, interpreter `Eval.pmap_threshold_value`, LLVM constant) gates a sequential fallback; configured by `--pmap-threshold=N` (default 1024), wired into interpreter + codegen, **included in the CAS cache key** (else cached binaries ignored the flag), and passed through by forge via `MARCH_PMAP_THRESHOLD`. LSP adds a `perf/parallelizable` Hint on pure `List.map`/`filter` with a "Convert to `List.pmap`/`pfilter`" quick-fix (purity via shared `March_tir.Purity.impure_builtins`; folds never flagged).
