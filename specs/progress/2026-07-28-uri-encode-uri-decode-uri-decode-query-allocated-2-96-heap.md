- ✅ **`Uri.encode`/`Uri.decode`/`Uri.decode_query` allocated ~2.96 heap strings per byte of the component being encoded/decoded; rewritten as byte-index scanners (2026-07-28, `stdlib/uri.march`).** `Uri.parse`/`to_string`/`merge`/`merge_strict` were already fine — they route through `string_split_first`/`string_split`/`string_slice`, which allocate once per delimiter-bounded SEGMENT, not per byte. The per-byte cost was isolated to `encode` (walked `string_chars(s)`, materialising a 1-char string plus a list cons cell for every input byte, even for a fully-unreserved string) and `decode`/`decode_query`'s shared helper (same `string_chars` walk, plus `decode_query` pre-processing every value with a full `string_replace_all(t, "+", "%20")` pass before calling `decode` — a second full pass with its own allocation). `encode` now tracks a run of unreserved bytes and slices it out in one call, only breaking the run at a byte needing `%XX` escaping; `decode`/`decode_query` share one `decode_scan(s, len, i, start, acc, plus_is_space)` byte-index scanner using the same run-slicing idea as `Json.scan_string`, which also lets `decode_query` fold the `+`-means-space convention into the same pass instead of a separate pre-pass. Measured compiled `--opt 2`, a 157-byte URL exercised through every public function, 5,000 iterations: **allocs/byte 2.96 → 0.73** (2,320,024 → 575,021 allocations, a 4.0x reduction). Verified via the existing `test_stdlib_suite.ml` "uri stdlib" group (11/11 passing) plus a round-trip corpus covering full/partial URLs, percent-encoded multi-byte UTF-8 (`%C3%A9`, `%E6%97%A5%E6%9C%AC`), and `decode_query`/`encode_query` over repeated/empty-valued/`+`-encoded params. **Found and deliberately NOT fixed**, pre-existing and reproduces identically on the unmodified file: `Uri.parse`'s authority/path split treats a scheme-less relative reference with no leading `/` as having an authority (`Uri.parse("../d")` yields `host=".."`, `path="/d"` instead of the RFC 3986 path-noscheme reading), which makes `Uri.merge`'s dot-segment resolution over such references — including the doc comment's own example — misbehave; unreachable from `encode`/`decode`/`decode_query`.
