- ✅ **`Dom.set_timeout`/`set_interval`/`on_frame` callbacks had a never-satisfiable extern signature — FIXED (`stdlib/dom.march`, `runtime/march_dom.mjs`, 2026-07-09).** Resolves the zero-arg-lambda follow-up filed by the Canvas 2D API entry below (`task_f422fd93`). The three externs declared `cb: Unit -> Unit`, but a zero-arg March lambda (`fn -> body`, the documented idiom for a 0-arg callback) types to its body's result DIRECTLY with no arrow wrapper (T-Abs, `specs/lang/core-march-types.md` §2; `List.fold_right (fun pt acc -> TArrow (pt, acc)) param_tys body_ty` in `lib/typecheck/typecheck.ml`'s `ELam` inference arm returns `body_ty` unchanged when `param_tys = []`), so it can never unify with a declared arrow type — `call_it(fn -> once())` against a `Unit -> Unit` param failed with "expected `() -> ()` but got `()`" both at the call site and inside the callee. This means the three callbacks were never actually callable from real March source; no existing test exercised them end-to-end. Root cause confirmed via `--check` repro; the bidirectional checker's `check_expr`'s `ELam` arm (`peel` helper) is not buggy — it faithfully implements the same direct-body-type rule in checking mode. **Fix:** followed the codebase's own established idiom for this exact shape (`task_spawn`'s thunk param, `pmap_threshold`, `task_cancel_token_new` all avoid arrow types for 0-arg-like values) — changed all three `cb` params to `Int -> Unit` (a dummy, ignored Int argument), so callers write `fn _ -> body` instead. Updated `runtime/march_dom.mjs`'s `march_dom_set_timeout`/`set_interval`/`request_animation_frame` to call `cb._0(cb, 0)` (was `cb._0(cb)`), matching the `f._0(f, args...)` closure-call ABI (`lib/tir/js_emit.ml`) for a 1-declared-param closure. Documented the limitation in `stdlib/dom.march`'s module doc and each wrapper's `doc` string. Regression: `test/native/js_dom_timeout_callback.{march,expected}` + `test/dune` rule compiles `--target js` and runs under `node`, verifying the callback both typechecks with `fn _ -> ...` and actually fires via the `cb._0(cb, 0)` ABI (prints "fired"); a `march_dom.mjs` copy-rule was added to `test/dune` alongside the existing `march_runtime.mjs` one since this is the first JS test to actually invoke a `Dom` extern (previous `js_dom_available` test only referenced `Dom.body()` in dead code, so `march_dom.mjs`'s import was never exercised). Full suite green (`scripts/run-tests.sh`, 807 tests) plus all `test/dune` JS-target golden tests (`js_dom_available`, `js_dom_timeout_callback`, `js_extern_import`, `js_ffi_async`, `js_ffi_blocking_raises`, `js_ffi_raises`, `js_ffi_cbacked`) diff-clean.
