- ✅ **Refinement types Path 1: use/alias-aware call resolution (2026-06-21)** — replaced the fragile "qualified key OR globally-unique bare name" matching (`build_table`/`collect_sig_list`) with proper lexical resolution that mirrors the typechecker. `collect_all_defs` records EVERY function (refined or not) under its fully-qualified key; a new `resolve_call` resolves a call name through (1) lexical module scope — the nearest enclosing module that defines the name wins, with shadowing, (2) alias expansion (`alias X.Y as P` → `P.foo` resolves to `X.Y.foo`), (3) `use`-imported bare names (`use M.{f}` / `use M.*`). The resolution context (module path + in-scope aliases/uses, inherited by nested modules) is threaded through `visit`/`visit_decls`. Recording non-refined defs is what makes it sound: a bare call resolving to a non-refined sibling no longer falls through to a refined function of the same name in an enclosing module (which would check the wrong predicate — a false positive). This both CATCHES violations the old code dropped on any cross-module name collision AND stays false-positive-free. Wrong resolution can at worst *skip* (only a refined resolution triggers a check). Verified end-to-end through the full pipeline (a `use`-imported `take_pos(-7)` is caught). 5 new tests (51 total in `test/test_refinecheck.ml`: collision-resolution, local-vs-colliding, alias, use, shadowing-safety); a new desugaring test harness (`has_refine_error_d`) for qualified calls, since the parser emits `EField` and desugar flattens to a dotted `EVar`. **Remaining Path 1:** concrete unfolding of user measures over literal constructors; use/alias module *paths* resolved relative to the top scope only (deeply-nested `use` of an inner-of-inner module isn't prefix-walked — rare).
