- ✅ **JIT REPL-mode gate for static closures was incomplete — `precompile_stdlib`'s `emit_fns_fragment` call omitted `~repl:true` (2026-07-28, `lib/jit/repl_jit.ml:823`, found in final whole-branch review of the static-closures work above).** `static_closure_ok`'s REPL/JIT exclusion depends on `ctx.repl`, which every `emit_fns_fragment`/`emit_repl_*` call site must opt into by passing `~repl:true`. Two of the three `emit_fns_fragment` call sites in `repl_jit.ml` did; `precompile_stdlib` (the JIT's stdlib-prelude fragment, warmed once per content-hash and cached to `~/.cache/march/stdlib_prelude_O1_*.so`) did not, silently falling back to `Llvm_repl.emit_fns_fragment`'s `?(repl : bool = false)` default. Proven with a cold cache (`HOME` override): the resulting `.so` contained 13 `$static_clo` symbols (e.g. `_Cluster.parse_addr$static_clo`), contradicting `specs/optimizations.md`/`specs/progress.md`/this file's claim that the optimization is gated off for the REPL/JIT. The observed behavior was benign in practice (the globals are `internal`/non-external so JITDylib-collision can't fire, they live in writable `__DATA`, and the prelude `.so` is never unloaded mid-session) — but the invariant was enforced by linkage luck, not by code. **Fixed** by passing `~repl:true` at the call site, and by removing the `?(repl = false)` default entirely (`lib/tir/llvm_repl.ml`'s `emit_fns_fragment` now takes `~repl:bool` unconditionally, `lib/tir/llvm_emit.ml`'s wrapper likewise) so every future call site must state its REPL-mode explicitly — this turns the same bug class into a compile error instead of a silent default. **Verified**: rebuilt the JIT stdlib prelude cold (fresh `HOME`) before and after — `nm -m <so> | grep -c static_clo` went from 13 to 0. **Regression added**: `test_static_closure_not_emitted_in_fns_fragment_repl_mode` (`test/test_codegen.ml`) drives `Llvm_emit.emit_fns_fragment ~repl:true` directly — the exact function `precompile_stdlib` calls — with a fn materialized as a value inside the fragment, and asserts no `$static_clo` global appears (previously only `emit_repl_expr` had REPL-mode coverage).
