- ✅ **`forge refactor bundle` — introduce a parameter object** — New `bundle_fn` in `lib/refactor/refactor.ml` + `forge refactor bundle <Fn> [--record NAME]` subcommand. Bundles a function's parameters into a generated record (`type <Fn>Args = { p : T, ... }`), rewrites the signature to take it (`fn f(args: <Fn>Args)`), rewrites the body's unshadowed parameter references to field accesses (`args.p`, via a scoped free-variable-style walk), and migrates **every call site project-wide** to pass the record literal (`f({ p = v, ... })`) — the cross-file part the cursor LSP can't do. Re-parse safety gate as with the other commands. v1 limits: single-clause function, all params type-annotated (else a clear error), recursive calls rewritten as call sites may need manual touch-up. **Notable bug found & worked around:** string-literal spans in the parser only cover the opening quote, so argument source can't be sliced per-span — `bundle` recovers args by splitting the call's parenthesised text on top-level commas (`split_top_commas`, string/nesting aware). +2 refactor tests (9 total). This is the "values that travel together → struct" / Introduce-Parameter-Object refactor; built in the forge engine rather than the LSP because the valuable part (rewriting all callers) is project-wide.
