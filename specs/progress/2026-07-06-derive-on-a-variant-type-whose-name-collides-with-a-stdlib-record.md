- ✅ **`derive` on a variant type whose name collides with a stdlib RECORD type silently failed to typecheck — "`T` does not implement interface `Eq`/`Show`" (`lib/typecheck/typecheck.ml`, `test/test_codegen.ml`, 2026-07-06).** Found verifying `docs/interfaces.md`'s canonical `type Color = Red | Green | Blue` / `derive Eq, Show for Color` example live: it failed to compile with "`Color` does not implement interface `Eq`", while renaming the type to `Status` made the identical program work. **Root cause:** record types register in `env.records` under their BARE name globally (both `name.txt` and the qualified `qname`), so a user's variant `Color` collides in that flat namespace with stdlib `Plot.Color = { r, g, b }` (always auto-loaded). Both `surface_ty` (the `Ast.TyCon` record-expansion at the impl-type conversion in `check_decl`'s `DImpl`) and `register_impl_shape`'s `lenient_ty` (pass-1 pre-registration) then structurally expanded the variant's derived `impl Eq(Color)` to the record's `TRecord{r,g,b}` shape — confirmed by a structural dump of `env.impls["Eq"]`: `target=TCon(Color/0)` vs `impls=[TRecord{b,g,r}; …]`, `impl_matches_ty` false, so the derived impl was invisible and the type read as "does not implement". (The trigger is purely the type-NAME collision with a stdlib record; the `Plot.Color` fields even leaked into a two-*variant* repro, proving stdlib Plot — not any nested type — was the corruptor in every case.) **Fix:** a new `name_is_variant env name` helper (checks whether any constructor in `env.ctors` has `name` as its parent `ci_type`, bare or `.name`-suffix) now guards all three record-expansion `when` clauses (the two in `surface_ty` — direct + module-registry — and the one in `register_impl_shape`): a name that also denotes a variant is kept nominal (`TCon`) instead of being expanded to a same-named record's structure. A variant is never itself a record, so this only removes incorrect expansions — genuine record impls (`type Point = {x,y}` / `derive Eq, Show for Point`) still expand and dispatch structurally (verified). **Regression tests:** 2 compiled-interp-parity cases in `test/test_codegen.ml`'s `newtype_derived_method_crash` group — a variant colliding with stdlib `Plot.Color`, and a self-contained variant colliding with a *local* nested record (distinct `hue/sat/lum` fields, so it guards the fix even if `Plot.Color` is renamed/removed); both RED pre-fix (verified via file-copy swap to `git show HEAD:…typecheck.ml`), GREEN post-fix. **Gates (six runners):** 400 compiler / 230 eval / 391 codegen / 804 stdlib (full, with Slow) / 53 stdlib_march / 29 snapshots — all exit 0.
