- ✅ **`NativeIntArr`/`NativeFloatArr` (`NativeArray`'s real backing types) added to `non_sendable_types`.** `check_sendable` (`lib/typecheck/typecheck.ml`) only listed `RingBuf`, despite `NativeArray` being structurally the same "flat, in-place-mutable buffer that must stay owned by one actor" hazard the list's own doc comment describes. `NativeArray` is a stdlib function namespace (`stdlib/native_array.march`), not a distinct type — the actual `TCon` names are the opaque 0-arity `NativeIntArr`/`NativeFloatArr` (registered alongside `native_int_arr_make`/`native_float_arr_make`), which is why the fix targets those two names specifically rather than `"NativeArray"` (which would have been a silent no-op match, matching nothing `check_sendable`'s `TCon`-name walk ever sees). Confirmed no existing stdlib/test/example code combines `NativeArray` with actor messaging before adding the restriction. Pinned by `specs/lang/types/reject/t164`–`t165`.
