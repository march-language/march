- ✅ **Cross-module typeclass dispatch — bare interface-method binding** — A bare interface-method call (`summarize(x)`) from a *different* module than the one defining the `interface`+`impl` failed with "I cannot find `summarize`". Root cause: the whole-program forward-reference pre-pass `prebind_mod_members` (`lib/typecheck/typecheck.ml`) bound only the **qualified** method names (`Iface.method`, `Mod.Iface.method`) for sibling modules, never the **bare** name — but the single-file path (`check_decl` `DInterface`) does `bind_var m.md_name.txt`, which is why typeclasses worked within one file but not across files (sibling `mod` blocks are exactly how the resolver presents a multi-file project). Fix: bind the bare method name in `prebind_mod_members` too, skipping when already bound so a builtin/user fn of the same name isn't clobbered. Now the idiomatic pattern (interface in one module, each `impl` co-located with its type, dispatch from anywhere) typechecks and runs. +1 test (`interface cross-module dispatch`). Known remaining restriction (orphan impls): `impl Iface(T)` where `T` is defined in *another* module than the impl still fails to resolve `T`, because sibling-module types are registered qualified-only in `env.types` — co-locate the impl with its type (the usual coherence rule).
