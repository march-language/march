- ✅ **`Yaml.parse` allocated ~5.56 heap strings per INPUT BYTE (worse than `Toml.parse`'s pre-fix 3.69); rewritten as a byte-index scanner (2026-07-28, `stdlib/yaml.march`).** Same `string_split(src, "")` + `acc ++ c` char-list pattern as Json/Toml, converted to a `(src, byte_index, line, col)` cursor using `string_byte_at`/`string_slice`/`string_join`, following the same template. Byte-value dispatch uses `match byte do N -> ... _ -> ... end` rather than `if`/`else if` chains where practical, sidestepping the chained-`if` `end`-counting pitfall (a `match` needs exactly one `end` regardless of arm count) that dominated the Toml rewrite's iteration count. Measured compiled `--opt 2`, a 361-byte document, 2,000 iterations: **allocs/byte 5.56 → 1.02** (4,016,065 → 738,040 allocations, a 5.4x reduction); residual allocation is mostly `string_trim` (which always allocates, even with nothing to trim) plus `YMap`/`YSeq` object construction (not string allocs). Verified via the existing `test_yaml.march` suite (unchanged, all passing) plus a 20-case round-trip corpus (nested block/flow structures, escapes, comments, `---` separator, bool/null spellings, negatives/floats, multibyte UTF-8, malformed-input errors) — byte-for-byte identical output old vs. new.
