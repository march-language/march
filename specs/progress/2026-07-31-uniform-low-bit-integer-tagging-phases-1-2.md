- ✅ **Uniform low-bit integer tagging (Phases 1 + 2)** — Fixed SIGSEGV when integers pass through polymorphic ADT fields (e.g. `List(Int)` with n ≥ 4096). Tag scheme: immediates stored as `(n << 1) | 1` (low bit 1); heap pointers remain even (always aligned). Changes: (1) `IS_HEAP_PTR` macro in `runtime/march_runtime.c` extended with `((uintptr_t)(p) & 1u) == 0` as first clause (short-circuits before page/sign guards on hot RC path). (2) `coerce ("i64", "ptr")` in `lib/tir/llvm_emit.ml` now emits `shl i64 %v, 1` + `or i64 %s, 1` + `inttoptr` to tag; `coerce ("ptr", "i64")` emits `ptrtoint` + `ashr i64 %i, 1` to untag (sign-preserving). (3) All three closure-wrapper emitters (top-level fn ref, AVar cross-module ref, REPL closure wrap) tag i64 return values before `inttoptr`. (4) `march_value_to_string` checks low bit first and calls `march_int_to_string((intptr_t)p >> 1)` for tagged immediates (Phase 2 fix, lands with Phase 1). Spec: `specs/plans/2026-04-16-uniform-integer-tagging.md`. Regression tests: `test_int_tag_coerce_ir` (shl+or+ashr appear in IR for `List(Int)` code), `test_int_tag_wrapper_ir` (wrapper emits tagged return). `test_march.exe` 1342 → 1358 (+2 new llvm_emit tests, +14 previously covered by tag-dependent paths now exercised).
