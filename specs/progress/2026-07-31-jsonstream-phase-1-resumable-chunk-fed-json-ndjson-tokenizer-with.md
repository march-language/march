- ✅ **JsonStream phase 1 — resumable chunk-fed JSON/NDJSON tokenizer with bounded memory, depth/token limits, and typed byte-offset errors (2026-07-31, `stdlib/json_stream.march`, `test/stdlib/test_json_stream.march`, `bench/json_stream.march`).** Adds a hand-written tokenizer (`JsonStream.start`/`start_ndjson`/`feed`/`finish`) that consumes input in arbitrary-size chunks and returns `Event` lists (`EvObjStart`/`EvObjEnd`/`EvArrStart`/`EvArrEnd`/`EvKey`/`EvStr`/`EvNum`/`EvBool`/`EvNull`) plus a typed `JsonStreamError` (`EMalformed`/`EDepthLimit`/`ETokenLimit`/`ETruncated`, each carrying an absolute byte offset), a `JsonLimits(depth, token_bytes)` config, ndjson mode (repeated top-level values over one chunk stream), and drivers (`fold`, `build`/`bpush`, `each_value`) layered on the core tokenizer. Totality harness: every test document is fed through EVERY possible byte-split point (not just a handful of hand-picked chunk boundaries) to prove chunking never changes the event stream vs. feeding the whole document at once, plus truncation sweeps (drop the input at every prefix length and confirm either a clean partial-event set or a final `ETruncated`, never a silent wrong answer) and a differential corpus against `Json.parse`. 212 tests green interpreted. **Compiled parity confirmed** (Task 5): checksum-identical compiled vs. interpreted on the `bench/json_stream.march` corpus (280000 for 20,000 records) and on a dedicated surrogate-pair probe (`a😀b` round-trips to `a😀b`, 6 UTF-8 bytes, byte-identical compiled vs. interpreted) — the first compiled exercise of the `byte_to_char`-based string-content emission Task 4 introduced. Baseline benchmark: ~225ms / ~85MB MaxRSS at n=20,000 (`--opt 2`); a 10× record-count spot-check (n=200,000) shows MaxRSS scaling ~9.9× in step with the 10×-larger in-memory input string, consistent with the parser itself holding no unbounded state across `feed` calls (see `specs/benchmarks.md`). **Deferred, per plan:** the decoder-combinator layer (design Component 4) — "separable, nothing in Components 1–3 depends on it."
