# Wave 3 Chunk 2 — Task 4: `llvm_builtins.ml` — declarative builtin table (2026-07-03, `specs/plans/2026-07-03-wave3-chunk2-emit-lower.md`, HAZARD H2)


- ✅ **New `lib/tir/llvm_builtins.ml`** replaces llvm_emit.ml's four historically-unsynchronized builtin structures (`is_builtin_fn`'s 272-name `List.mem` list, `builtin_ret_ty`, `mangle_extern`, and the ~400-line hand-written preamble `declare` blob — source of ≥5 "missing builtin" fix commits per `specs/analysis/2026-07-01-pipeline-deep-review.md` §5) with one ordered table (`builtin` record: `march_name`; `c_name : string option`; `ret_ty : Tir.ty option`; `in_is_builtin : bool`; `declare_sig : string option`), 318 rows, in the preamble's real declaration order (286 rows with a preamble presence, then 32 declare-less rows — arithmetic/comparison operators and `int_and`/etc bitwise ops emitted as native LLVM instructions, `task_spawn`/`task_await`/etc and `pmap_threshold`/`get_work_pool`/`remote_ref_hashes` synthesized/constant-folded by dedicated `EApp` match arms — appended in their original `is_builtin_fn`-list order since they have no preamble position). All three consumers (`is_builtin_fn`, `builtin_ret_ty`, `mangle_extern`) are hashtables built once from the table at module load, answer-identical to the deleted functions (verified against a throwaway probe executable calling both old and new implementations over the full 318-name universe plus negative-control names: 0 mismatches). `Llvm_emit.mangle_extern` stays re-exported (lib/jit/repl_jit.ml references it as `March_tir.Llvm_emit.mangle_extern`); `Llvm_emit.emit_preamble` becomes a thin wrapper translating `target_config` to the `is_wasm`/`triple` values `Llvm_builtins.emit_preamble` needs (kept decoupled from `target_config` to avoid a module cycle, since `bin/main.ml` depends on `Llvm_emit.target_config`/`Native`/etc extensively and moving those was out of this task's scope).
- ✅ **HAZARD H2 (byte-identical preamble): satisfied by construction, not by a formatting function.** The original blob's per-line whitespace is hand-tuned and inconsistent (e.g. `declare i64  @foo` vs `declare i64    @bar` — return-type column padding varies within the same block to visually align with neighboring `double`-typed lines), so a generic `declare_sig`-from-fields formatter would risk silent reformatting drift. Instead each row's `declare_sig` holds the EXACT historical `declare ...` line text (copied verbatim); `Llvm_builtins.emit_preamble` replays a fixed per-target list of `preamble_item`s (`PComment`/`PDeclare`/`POther`/`PBlank` markers mirroring the original blob's line-by-line structure 1:1, including its native/WASM/REPL conditional branches) and resolves each `PDeclare` marker's text via a C-symbol lookup across the table + a 57-entry `runtime_only_declares` table (RC ops, Hot-Code-Reload/dispatch machinery, the test harness, LLVM intrinsics, task/scheduler internals — preamble declares with no March-callable name at all, hence no `builtin` row). Verified byte-identical for all three target/repl combinations (native non-REPL, native REPL, WASM) against the actual pre-refactor `emit_preamble` output via a throwaway probe executable, AND pinned as a permanent regression test: `test/test_codegen.ml`'s new `llvm_builtins_preamble_golden` suite (4 tests) embeds the four deleted `Buffer.add_string buf {| ... |}` literals verbatim as goldens and diffs `Llvm_builtins.emit_preamble`'s actual output against them byte-for-byte (confirmed the test actually catches drift, not just passes vacuously, by transiently corrupting one declare line's text and observing 3 of 4 sub-tests fail, then reverting).
- ✅ **Membership drift FILED, NOT repaired (Step 3 — the drift the table now makes visible):** two drift classes found, both preserved exactly as historical behavior via the table's optional/bool fields (no behavior change in this task):
  - **38 names have a `builtin_ret_ty` + `mangle_extern` + preamble entry but are ABSENT from `is_builtin_fn`'s recognition set:** `chan_new`/`chan_send`/`chan_recv`/`chan_close`/`chan_choose`/`chan_offer`, `mpst_new`/`mpst_send`/`mpst_recv`/`mpst_close`, `record_keys`/`record_values`/`record_entries`/`record_get`/`record_has_key`/`record_put`/`record_from_list`, `ws_handshake`/`ws_recv`/`ws_send`/`ws_select`, `http_parse_request`/`http_serialize_response`/`http_server_listen`, `tcp_recv_http`/`tcp_send_all`, `html_auto_escape`, `panic`, `send_linear`, `sha1_bytes`, `stdlib_gzip_encode`/`stdlib_gzip_decode`/`stdlib_deflate_encode`/`stdlib_deflate_decode`/`stdlib_zstd_encode`/`stdlib_zstd_decode`/`stdlib_brotli_encode`/`stdlib_brotli_decode`. Consequence: `is_leaf_callee` (`is_builtin_fn name || Tir_names.has_runtime_prefix name`) treats a direct call to any of these BY ITS MARCH NAME as non-leaf, forcing an unnecessary reduction-check emission (`emit_reduction_check`) in any caller whose body is otherwise leaf — a missed optimization, not a correctness bug (the reduction check is always safe to over-emit). Likely explanation: these names are dispatched through dedicated non-generic `EApp` match arms (session-typed channels, MPST, record introspection, WS/HTTP, compression) that never needed `is_builtin_fn`'s "is this a no-op-for-RC-purposes operator/value" check, so nobody noticed the recognition-set gap. Repair (if ever done) is a `is_builtin_fn` membership fix, tested via `expr_has_call`/reduction-check IR assertions — out of scope here.
  - **7 names (`march_compare_int`/`march_compare_float`/`march_compare_string`/`march_hash_int`/`march_hash_float`/`march_hash_string`/`march_hash_bool`) have a `builtin_ret_ty` + preamble entry but NO `mangle_extern` case and are ABSENT from `is_builtin_fn`:** these are already-mangled C-runtime names used directly as March-level call targets (no renaming needed, so `mangle_extern`'s identity fallthrough naturally does the right thing) — the reduction-check gap above doesn't apply to these specifically since `Tir_names.has_runtime_prefix` (the `is_leaf_callee` OR-clause) already recognizes the `march_` prefix. Recorded here only because the table's per-structure membership flags make the `is_builtin_fn`-absence visible; no known consequence.
  - Separately noted (NOT drift, verified as intentional dedicated-codegen design, no filing needed): arithmetic/comparison operators (`+`/`-`/`==`/etc, native LLVM instructions), `int_and`/`int_or`/`int_xor`/`int_not`/`int_shl`/`int_shr`/`int_popcount` (native bitwise instructions), `native_int_arr_*`/`native_float_arr_*` (18 names, `mangle_extern`-bypassing direct-emit arms), `task_spawn`/`task_await`/`task_await_unwrap`/`task_yield`/`task_spawn_steal`/`task_reductions`/`pmap_threshold`/`get_work_pool`/`remote_ref_hashes` (constant-folded or synthesized by dedicated `EApp` arms), and `main` (the user's own compiled entry point, not a runtime builtin).
