- ✅ **Fire-and-forget task safety (RC fix) + 250K-task scheduler stress test** — `march_task_spawn_thunk` and `march_task_spawn_with_cancel_thunk` (`runtime/march_runtime.c`) now call `march_incrc(task)` immediately after allocating the Task object, bumping RC to 2. The trampoline (`march_thunk_trampoline`) calls `march_decrc(task)` after storing the tagged result and release-storing `done=1`. This prevents a use-after-free when callers do fire-and-forget (`let _ = task_spawn(...)`) — the caller's `decrc` drops RC 2→1 (not 0), so the task object outlives the trampoline's write. Previously fire-and-forget could UAF because the trampoline's raw `wa->task` pointer outlived the heap object. Stress test: `test/native/sched_stress.march` — 250 batch tasks × 1000 workers = 250,250 green threads; each worker computes `fib(8..19)`. Throughput: **250K tasks in 1.32s wall, ~189K tasks/sec**. Scaled to 1M tasks: 4.79s wall, ~209K tasks/sec. Scheduler exits cleanly (EXIT:0) as tasks drain. All 1450 tests pass.
