- ✅ **`examples/csv_example.march` renders `#<tag:1>` compiled, real values interpreted — FIXED (2026-08-12).** Filed 2026-08-10 while verifying the R1 stage D migration; not caused by stage D (a pre-fix control at `413d3c48`, the last commit before any stage-D code, reproduced the identical `#<tag:1>` output compiling the pre-migration `csv_example.march`). **Root cause, found via a minimal repro (`pfn print_row(row) = to_string(row)` called with a concrete `List(String)` argument, no closures needed) and a `MARCH_DUMP_TXT=tir-mono`/`tir-defun` stage-by-stage TIR diff against a working top-level `to_string(Cons(...))` call:** `to_string(x)` on a *concretely-typed* argument is resolved at `lib/tir/lower.ml`'s `dispatch_name` redirection (`to_string` → `show`, `resolve_iface_method`) to the matching `Show$T.show` impl — but that redirection runs once, at the CALLING FUNCTION'S OWN lowering time. Inside a still-generic function (`print_row`'s `row : TVar` at its own definition), the argument's type is unresolved then, so the redirection can't fire and the call is lowered as the bare `to_string` builtin — which `lib/tir/llvm_emit.ml`'s codegen dispatch (`to_string: dispatch on argument TIR type`) only special-cases for Int/Float/Bool, falling through for everything else to the runtime `march_value_to_string` (`runtime/march_runtime.c`), which itself only special-cases String/Float-boxed and prints `"#<tag:%d>"` for any other heap tag — including a `List.Cons` cell (tag 1, matching the observed `#<tag:1>`). Monomorphization (`lib/tir/mono.ml`) DOES later specialize `print_row`'s `row` parameter to the concrete `List(String)` once a real call site is found (confirmed via the TIR dump: `fn print_row$List_String(row : List(String))`) — but its body's `to_string(row)` call was never revisited: `rewrite_calls`'s interface-method resolution (`find_iface_impls`, present in both the `EApp` and `ECallPtr` "callee not in fn_table" branches) looks up the call's callee name directly in `iface_methods`, and the literal builtin name `"to_string"` was never registered there (only `"show"` is, per `lower.ml`'s `reg_method "show" ty_name mangled`) — so the lookup silently failed and the call stayed the generic builtin, even though the surrounding function's parameter was now perfectly concrete. This is a genuinely separate bug from the ALREADY-FIXED lower-time case (`to_string_show.march`'s regression, "route it through Show dispatch") — that fix only covers calls where the concrete type is known when the function containing the call is itself lowered; a call inside a function that starts out generic and gets concretized later by mono was never covered. **Fix:** `lib/tir/mono.ml`'s `find_iface_impls` (both the `EApp` and `ECallPtr` copies) now retries under `"show"` when the literal callee name is `"to_string"` and a direct/prefix-stripped lookup finds nothing — mirroring `lower.ml`'s own `to_string → show` aliasing, just re-attempted once mono has a concrete type to resolve against.
