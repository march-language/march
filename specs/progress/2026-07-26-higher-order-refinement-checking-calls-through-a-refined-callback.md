- ✅ **Higher-order refinement checking: calls through a refined callback parameter and through a local alias (`lib/refinecheck/refine_check.ml`, 2026-07-26).** Two call shapes `visit`'s `EApp` case previously skipped entirely, since `resolve_call` only resolves a NAMED callee: a call made *through* a refined function-typed parameter (`fn ap(f : ({Int | _ >= 0}) -> Int) : Int do f(-3) end`), and a call through a local alias of a named function (`let g = takepos  g(-3)`). Both were probed against the built compiler beforehand and confirmed silently unchecked (exit 0, zero violations). Fixed by adding a third fact channel, `cbenv` (`string -> fn_sig`), alongside the existing `scope`/`path`: `callback_sig_of_ty` synthesizes a one-parameter `fn_sig` from a `TyArrow (TyRefine (...), _)` domain, reusing `refined_param_ty` so Int/String/ADT/record domains behave identically to a directly-refined parameter (returns `None` for an unrefined or multi-argument domain, out of scope per fact 2 of the plan); `cb_add_binding` populates an alias entry only for a bare-`EVar` RHS that `resolve_call` resolves to a refined function (a call, field access, or lambda RHS is never chased). `EApp`'s named-callee path is tried first; only on a miss does `visit` consult `cbenv`. **Retired at all five binding forms** (`ELet`, `ELetQ`, `ELam`, `ELetFn`, `EMatch` arm binders) exactly like `scope_shadow`/`path_shadow`, each verified NON-VACUOUS by temporarily stubbing the retirement and confirming a false positive appears on correct code — including a genuinely new one found this way: `EBlock`'s per-statement fold only ever retired a fact for `A.ELet`, so a block-level `fn f(...) do ... end` (`ELetFn` as a SIBLING statement, not the dedicated `A.ELetFn` visit arm that only walks that local function's own body) never retired its bound name for the statements that follow it in the same block — fixed alongside the new channel. 10 new tests in a `hof_suite`/`higher-order` group (173 → 183 total): six for the callback-parameter shape (one checked, four silence, one lambda-shadow), four for the local-alias shape (one checked, three silence including a rebind-then-call-again control). Adversarial sweep (14 hand-written programs covering all five shadowing forms for both shapes, a callback passed onward to another callback-taking function, String/record callback domains, and a combined callback+alias+record+ADT+string+relational-postcondition module) all exit 0; two deliberately-violating variants of the String/record cases exit 1, confirming the checks are live rather than vacuously silent. `accept/t77_refine_hof_bypass_limitation.march` (the pre-existing conformance witness for the "direct calls only" limitation) is unaffected and still passes — its callback parameter is declared `Int -> Int` (unrefined), so it demonstrates the boundary that remains open: a caller's contract is enforced only when actually declared refined on the callback type, never inferred from what a concrete argument happens to point to.
