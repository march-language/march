- ✅ **Fix let-generalization hole for forward-referenced polymorphic `pfn` helpers** — `lib/typecheck/typecheck.ml` `generalize`: when a function is generalized to a `Poly` scheme, the quantified `TVar` refs are now deep-copied with fresh, isolated allocations. Previously the scheme shared the original mutable `TVar` refs with forward-reference placeholders used by mutual-recursion partners processed later in pass 2. A later function's body could unify those original refs (e.g. `go(rest, n+1)` inside `list_len_acc` unifying the `lst` parameter type), silently corrupting the already-stored `Poly` scheme and causing a second call site with a different element type to fail with a spurious type mismatch. Repro: `pfn go(lst, n)` + `pfn count(lst)` defined before `go` in source order — `count([1,2])` then `count(["x"])` used to fail. Now works. All 147 tests pass.
