- ❌ **String hashing: measured, NOT changed (2026-07-27).** `march_hash_string` is scalar FNV-1a, one byte at a time. A word-at-a-time alternative benchmarked ~2× faster on realistic key lengths (2–29 bytes) — but the absolute figures kill it: 5.5ns per hash today, 2.7ns saved. A workload would need tens of millions of string-keyed lookups for that to register. Worth noting the measurement gap that prevented a better answer: **no benchmark in the repo exercises string-keyed maps** — `bench/hash_map_bench` makes 73 string allocations against 22.8M object allocations, i.e. it is Int-keyed. If string-keyed map performance ever matters (JSON objects, HTTP headers), that benchmark should exist before the hash is revisited.
