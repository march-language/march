- ✅ **JS backend emitted a closure's apply slot as the `$clo` wrapper object when the allocation was `EReuse`/`EStackAlloc` (`lib/tir/js_emit.ml`, 2026-07-27).** Reported as "`Json.to_string` crashes on any `Object` value under `--target js`" with `TypeError: f._0 is not a function`, correct interpreted and compiled native. Neither the `Object`-specific nor the `json.march`-specific framing survived: the `Array` arm fails identically, and a JSON-free fixture (a lambda passed to a local higher-order helper from a match arm) reproduces it exactly. The JS closure layout is `{$: "$Clo_name", _0: apply_fn, _1: fv1, ...}` and post-Defun dispatch calls `f._0(f, args)`, so slot `_0` must hold the RAW function — but `emit_atom` deliberately rewrites a module-level function name to its `name$clo` wrapper, which is an *object* (`{_0: fn}`), so that bare function references work as first-class values. `EAlloc` compensated with an `is_clo` tag check that emitted slot 0 through `emit_atom_raw`; `EStackAlloc` and `EReuse` — the two rewrites escape-analysis and Perceus produce *from* `EAlloc` — each re-implemented the tagged-object emission without it. A closure allocated in a match arm whose scrutinee cell is dead is reuse-eligible, so Perceus rewrites it to `EReuse` and dispatch then called a record. `json.march`'s `Array`/`Object` arms are exactly that shape (match on `jv`, then allocate a lambda for the local `map_list`), which is why every non-scalar `to_string` died. **Diagnosis note:** the first hypothesis was `EStackAlloc` — plausible, since `known_call.ml:71` matches a closure in precisely that node — and it was WRONG; distinguishing it took emitting a separate marker comment from each of the three arms, at which point the output showed `EReuse` unambiguously. Guessing between two same-symptom candidates would have produced a fix that changed nothing. The three forms now share one `emit_tagged_alloc` helper, so the closure rule can no longer be applied to one and missed by the others. Pinned by `test/native/js_closure_reuse_apply_slot.{march,expected}`, covering the general shape plus `Json.to_string` over an array and an object — a dune-RULE test, so it needs `dune build @runtest` and is invisible to the four alcotest binaries. Verified red before the fix through the real harness, and the fixture now agrees across all three backends (interpreted, native `--opt 2`, JS).
