- ✅ **`Toml.parse` allocated ~3.7 heap strings per INPUT BYTE (worse than `Json.parse` before its rewrite); rewritten as a byte-index scanner (2026-07-28, `stdlib/toml.march`, no runtime/compiler changes — reuses the `string_byte_at`/`string_index_of_from` primitives added for the JSON and prior string-perf work).** State went from `(chars : List(String), line, col)` — built once via `string_split(src, "")` and walked by consing/unconsing one-character strings, with every token (string bodies, bare keys, digit runs) accumulated via `acc ++ c`, an O(n²)-copying pattern for an n-byte token — to `(src, byte_index, line, col)`, inspected with `string_byte_at` and materialised with `string_slice`/`string_join`, following the `Json.parse` template from commit `556cf7e9`. On a 340-byte document (title/owner/database/servers sections, arrays, an inline table, nested tables) compiled `--opt 2`, 2,000 iterations: **allocs/byte 3.69 → 0.37** (2,506,057 → 250,044 string allocations; `obj_allocs` also fell 3,272,000 → 1,738,000 from less list/tuple churn in the character-list walk). Escaped/multiline string bodies use the same run-slicing scheme as `Json.scan_string` (segments collected only around actual escapes, one `string_slice` in the common no-escape case); bare keys and digit runs (with `_` separators dropped) are each a single slice or a short run-join; the previous digit-to-int conversion additionally re-split its own digit string char-by-char (`string_to_int_digits` via `string_split`) — replaced with a `string_byte_at` loop, so this fix also removes an O(n²) hot path the JSON rewrite didn't have. `line`/`col` state, needed for `TomlError` positions, is rebuilt in one pass (`reposition`) after a raw byte-index scan rather than threaded through every character step. Verified via the full `test_toml.march` describe/test suite (unchanged, all passing) plus a 33-case round-trip corpus (all escape forms, multiline basic/literal strings including embedded `"`/`'` runs that don't close the triple-quote, 2/3/4-byte UTF-8 in keys and values, dotted/quoted keys, nested tables, arrays, inline tables, array-of-tables, comments, and 7 error cases), diffed old-vs-new and interpreted-vs-native. `col` now counts BYTES rather than decoded characters, matching the JSON rewrite's precedent (unchecked by any existing test).
