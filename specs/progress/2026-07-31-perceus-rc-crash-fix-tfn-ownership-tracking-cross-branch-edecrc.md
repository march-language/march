- ✅ **Perceus RC crash fix: `TFn` ownership tracking + cross-branch EDecRC** — Fixed a `march_decrc` crash where a `.text-segment address` was being passed to the RC system during `Map.fold` with a `Bytes` accumulator. Two interlocking bugs in `lib/tir/perceus.ml`: (1) `needs_rc (TFn _)` was `false` — Perceus generated zero RC operations for function-typed parameters (e.g. `f` in `Map.node_fold`), causing no EIncRC when `f` is captured into the `go` closure and no EDecRC in the HEmpty arm where `f` is unused; the closure's code pointer slot was then misidentified as a Bytes payload pointer. Fix: changed to `needs_rc (TFn _) = true` with a guard comment explaining that post-defun any `AVar` with `TFn` type is a heap-allocated closure struct (never a raw code pointer — those are `ADefRef` and are never in AVar liveness; `llvm_ty (TFn _) = "ptr"` so RC ops emit correctly at the LLVM level). (2) ECase handler was discarding `live_before_br` for each branch — variables live in some branches but dead in others never got `EDecRC` in the dead branches (a second class of RC leak). Fix: collect `live_before_br` per branch, compute their union (`union_live_br`), and insert `EDecRC v` at the head of any branch where `v` ∈ `union_live_br` but `v` ∉ branch's `live_before_br` (excluding closure FVs, arm-bound vars, and vars live after the case). New `_var_ctx` global (`Tir.var StringMap.t ref`) maps names to their typed `Tir.var` records for emitting correctly-typed EDecRC ops. `_var_ctx` is seeded from function params in `insert_rc` and extended via ELet with save/restore semantics to avoid stale cross-branch interference. All tests pass.
