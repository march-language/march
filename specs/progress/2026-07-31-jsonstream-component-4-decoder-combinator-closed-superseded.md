✅ **JsonStream Component 4 — decoder-combinator layer: CLOSED, superseded rather than built (2026-07-31, typed JSON decoding plan, tasks 1-7, `specs/2026-07-31-json-typed-decoding-design.md` + `specs/plans/2026-07-31-json-typed-decoding.md`).** The phase 1 design doc (`specs/2026-07-30-json-streaming-design.md`) scoped a typed decoder-combinator layer over the raw `Event` stream (e.g. `Decoder.field`/`Decoder.list`/`Decoder.at` composing into a value decoder, analogous to `Json.Decode` in Elm) as Component 4. The typed-JSON-decoding plan reconsidered this before starting: `derive Json` already existed and covered the same ground, so building a from-scratch combinator library would have duplicated working machinery. Tasks 1-7 instead (a) proved `derive Json` × `JsonStream` end to end, (b) gave `from_json` a structured `Json.DecodeError` with a JSONPath and byte offset, (c) added `JsonStream.each_typed` (byte-offset-carrying NDJSON → typed records), and (d) generated a SECOND decoder per derived record type, `from_json_events` (Task 7, `lib/desugar/desugar.ml`), that consumes the `Event` list directly — so a record never becomes a `JsonValue` tree even for one huge top-level object. That closes the need Component 4 was scoped for. **Combinators themselves (a `Decoder.field`/`map2`/`one_of` API) remain explicitly NOT built and open** — genuinely unmotivated by any demonstrated workload; revisit only if one appears (design doc's non-goals section).
