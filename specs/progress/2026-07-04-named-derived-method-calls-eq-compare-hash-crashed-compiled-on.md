- ✅ **Named derived-method calls (`eq`/`compare`/`hash`) crashed compiled on `Newtype`-repr variants — SIGSEGV / non-exhaustive panic (`lib/desugar/desugar.ml`, `lib/tir/llvm_case.ml`, 2026-07-04).** Fixed the P1 filed at Wave 4 Task 5 (verified matrix at `f8b25df7`). Two independent, STACKED defects, both required to reproduce the crash — fixing only one left the other's symptom intact:

  **Defect 1 (derive-specific): shared `dummy_span` collision in the typechecker's span-keyed `type_map`.** `expand_derive`'s `derive_impl` (`lib/desugar/desugar.ml`) minted every AST node in a derived `Eq`/`Ord`/`Hash`/`Show` impl body with the SAME `dummy_span` (`mk_name`/`mk_fn_def` both hard-code it). The typechecker records inferred types keyed by span (`env.type_map`, `Hashtbl.replace` — last write wins), and `Lower_state.ty_of_span` reads them back during TIR lowering — so every node across every derived method for a type collided on ONE table entry. Lowering saw whatever type happened to be the last one recorded for that shared span (e.g. `Ord$Wrap.compare(a : (Wrap) -> Int, ...)` — a function type where an `Int` was expected), not the node's real type.

  **Defect 2 (general, not derive-specific): `lower_match` mints destructured sub-pattern variables with `unknown_ty`.** Independently of defect 1, `lower_match.ml`'s match-compilation matrix (`compile_matrix`, the `tir_branches` builder) creates fresh `Tir.var`s for each constructor's destructured fields with `v_ty = Lower_types.unknown_ty` (a `TVar`) — it has no way to know the field's concrete type at that point. `llvm_case.ml`'s `emit_case` already had a narrow recovery for exactly this shape when the scrutinee is Option-shaped (`branches_match_niche_shape`, added for the niche repr) but nothing analogous for `Newtype`-repr scrutinees: a nested match on a Newtype-repr value (e.g. derived `Eq`'s `match (a, b) do (Wrap(x), Wrap(y)) -> ... end`, or — confirmed via a **hand-written** `impl Eq(Wrap)` with a nested tuple-destructure match and real, non-dummy spans — ANY nested destructure on a Newtype value) reached `emit_case` with the scrutinee typed as `TVar`, which `Repr.repr_of_ty` conservatively classifies `Boxed`. The Boxed strategy loads a ctor tag at `scrut+8` — a value that has no heap header (Newtype-repr values ARE their raw payload, `lib/tir/repr.ml`): an `Int` payload is a tagged scalar (wild deref → SIGSEGV, lldb confirmed `EXC_BAD_ACCESS` in `Ord$Wrap.compare` at exactly the ctor-tag offset); a `String` payload is a heap pointer whose header byte at that offset is garbage (no arm tag matches → non-exhaustive-match panic, not a crash — matches the verified matrix's `WrapS(String)` row).

  The hand-written-impl repro is what separated the two defects: it has real per-node spans (so defect 1 cannot apply) yet still crashed identically to the derived case — proving defect 2 was independently sufficient and had to be fixed regardless of defect 1.

  **Fix — defect 1:** new `respan_derived_decl` (`lib/desugar/desugar.ml`) walks every AST node inside a derive-generated `DImpl`/`DFn` and assigns each a fresh, structurally-unique span (`fresh_synthetic_span`, a monotonic counter under the sentinel file `"<none>"` — preserves every existing synthetic-span filter, e.g. `lib/coverage/coverage.ml`'s file check and the LSP's `= dummy_span` checks, which compare the whole record and never match a numbered synthetic span to a real document). Applied once in `expand_derive`, right after `derive_impl` returns, before the results are appended to the module's decls. The decl's own top-level span (the derive site, a real user span used for error attribution) is left untouched.

  **Fix — defect 2:** a Newtype analogue of `emit_case`'s existing niche TVar-recovery (`llvm_case.ml`'s `newtype_recovery_payload`): when the scrutinee type is unresolved (`TVar`) and the match has exactly one branch whose ctor tag identifies the type unambiguously — every type definition owning a ctor with that name classifies as `Repr.Newtype` AND they all agree on payload tagging (`Repr.payload_needs_tag`) — commit to the `Newtype` decode strategy with that payload type, exactly mirroring `EAlloc`'s encode side. Any ambiguity (a Boxed type sharing the ctor name, or disagreeing tagging) falls back to the pre-fix `Boxed` behavior, so no other match shape is affected.

  Both fixes were independently verified via a controller-reproduced discriminator: the derived-impl repro crashed pre-fix-2 even with fix-1 alone (span uniquification alone typechecks correctly but `lower_match`'s TVar sub-pattern vars still hit the Boxed path); only fix 2 — combined with fix 1 so the derived body typechecks against its OWN correct type rather than a collided one — resolves both stacked defects together.
