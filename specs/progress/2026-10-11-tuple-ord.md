# Tuples are `Ord` when every component is

**Landed:** 2026-10-11 (first written 2026-10-07 on `fix/tuple-ord`). The todo
was logged 2026-10-06 and split from
[2026-10-01-tuple-eq.md](2026-10-01-tuple-eq.md). Its other half, the
conditional-impl `when` bound, landed separately in
[2026-10-08-conditional-impl-bounds.md](2026-10-08-conditional-impl-bounds.md).

`(1, 2) < (1, 3)`, `compare(a, b)`, `<=`, `>` and `>=` on 2- to 5-tuples order
lexicographically: the first component pair that differs decides, each compared
by its own `Ord` (a `derive Ord` ADT by declaration order).

- **Typecheck.** `interface_satisfied` (used by `discharge_constraints`) gains a `TTuple` arm for
  `Ord`, beside `Eq`'s, limited to arity 2..5. It is structural, so the
  prelude impls' `when` bound is never relied on: that bound is the open
  conditional-impl gap.
- **Interpreter.** `Eval_runtime.tuple_compare` / `ord_compare_value` order
  `VTuple`s directly (Int/Float/String/Bool by `compare`'s rules, anything
  else by its `Ord` impl). Both `cmp_op`'s ordering operators and the `compare`
  builtin use it. Before, `<` panicked, and `compare` fell to OCaml's
  structural `compare`, which ordered an ADT component by constructor NAME.
- **Compiled.** `stdlib/prelude.march` has `impl Ord((a, b)) when Ord(a),
  Ord(b)` through 5-tuples. Mono's existing `$TupleN` dispatch resolves
  `compare` to them and specialises each component's `compare`. For `<` & co.,
  `Mono.rewrite_calls` rewrites a call whose first argument is a `TTuple` into
  a call of the prelude's `__tuple_lt` / `__tuple_le` / `__tuple_gt` /
  `__tuple_ge` (`compare(a, b) <op> 0`). This runs in Mono, not at lowering,
  so a generic `fn gt(a, b) do a > b end` used at a tuple is covered too.
  Before, compiled `compare` was an ambiguous interface call, and compiled `<`
  reached `march_poly_compare`, which returns 0 for heap cells, so every tuple
  `<` was false.

Tests: `test/native/tuple_ord.march` (golden = interpreter output; Int, String,
Float slots, nested tuples, 3- and 5-tuples, a `derive Ord` ADT whose
declaration order differs from its name order, a generic caller, and
`List.sort_by` with `<`). Also `test_compiler`'s
`test_tuple_ord_structural_accepts` / `test_tuple_ord_component_without_ord_rejects`.
