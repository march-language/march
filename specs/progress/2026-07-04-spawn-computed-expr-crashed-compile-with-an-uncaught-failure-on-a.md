- ✅ **`spawn(<computed expr>)` crashed `--compile` with an uncaught `Failure` on a well-typed program — shape restriction now enforced in the typechecker (`lib/typecheck/typecheck.ml`, `test/test_compiler.ml`, 2026-07-04).** Found during Task 1 of `specs/plans/2026-07-04-differential-oracle-plan.md` (differential-oracle `classify_compile` work). A well-typed program that spawns a *computed* actor expression — e.g. `spawn(if true do Counter else Counter end)` — passed `--check` with exit 0 but, when compiled, escaped to OCaml's top-level handler with `Fatal error: exception Failure("TIR lower: ESpawn argument must be a plain actor name")` (exit 2, no binary produced). Distinct from the known "Monomorphization limit reached" P0 above: this is compiled-backend-only and specific to the `spawn` argument shape. **Root cause:** the parser (`lib/parser/parser.mly:1222`, `SPAWN LPAREN expr RPAREN`) and the typechecker (`ESpawn` arm) accepted `spawn(e)` for *any* expression with zero shape restriction, but `lib/tir/lower.ml`'s `ESpawn` lowering only handles a bare actor name (`ECon(_,[],_)` / `EVar` — it dispatches by *name* to a statically generated `<Actor>_spawn` function) and hit an unguarded `failwith` for anything else; `bin/main.ml`'s compile path runs the TIR pipeline with no enclosing `try/with`, so the `Failure` propagated straight to the top level. **Why "reject earlier" and not "support it":** there is *no runtime actor-descriptor value* in either backend — the interpreter (`lib/eval/eval.ml:7122-7127`) *also* requires a plain actor name (`eval_error "spawn: expected actor name (got complex expression)"`), so "spawn a computed actor" is a feature that exists in neither backend, not merely a lowering robustness gap. **Fix:** the `ESpawn` arm in `typecheck.ml` now checks the argument is a plain actor name (`ECon(_,[],_)` / `EVar`, mirroring exactly what `lower.ml` accepts) and otherwise emits a structured `Err.error` pointing at the argument span, so `--check` / `--compile` / interpret now all reject the program uniformly with the same clean diagnostic before it can reach the internal `failwith` (which is retained as a now-unreachable invariant backstop). Valid `spawn(Counter)` is unaffected (compiles + runs). **Regression:** 2 new `test/test_compiler.ml` typecheck cases — `spawn computed actor: rejected` (asserts `has_errors` + the diagnostic mentions "spawn" and "plain actor name") and `spawn plain actor name: ok` (no false positive on the valid form).
