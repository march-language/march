# `task_poll`: a non-blocking `task_await`

**Done 2026-11-12.**

Asked for by Strata (a voxel engine in March), whose chunk streaming starts generation
and meshing as tasks and collects them on the main thread each frame. With only
`task_await` it awaited each task two frames after spawning it and stalled whenever one
was late (30-100 ms stream ticks on a loaded machine). Its gap list (S12) asked for
`task_poll(t) : Option(a)`.

## What shipped

`task_poll(t : Task(a)) : Option(Result(a, String))`, and the wrapper `Task.poll`
(`stdlib/task.march`). `None` while the task runs; `Some(r)` once it has finished, `r`
being exactly `task_await(t)`'s answer.

- Runtime: `march_task_poll` (`runtime/march_runtime.c`) acquire-loads the done word
  (word 4) and answers NULL while it is 0, which is Option's niche `None` for an
  `Option(Result(..))`, so a pending poll allocates nothing. It never registers as the
  task's waiter and never touches the proc. Once done it builds the same answer as
  `march_task_await` (shared `task_result_ok`).
- Codegen: `Llvm_emit_task.emit_task_poll` normalises the Ok payload exactly as the await
  arm does (shared `normalise_task_result`) and re-encodes through
  `emit_vault_opt_reencode` where the call site decodes `Option` as boxed. The Task is
  borrowed (`lib/tir/borrow.ml`), so a poll costs no RC traffic and the caller still owns
  its handle.
- Interpreter: tasks run to completion at spawn, so `task_poll` answers `Some` of what
  `task_await` answers.
- Typecheck, `Builtin_name.Task_poll`, `Alloc_contract`, `Defun.builtin_names`, the
  preamble declarations, refinecheck's event builtins.

## The ownership fix it needed

A task's heap result used to be handed to the FIRST reader: the Task released a Float
box when it died, but any other heap value (a String, a list) went to whoever awaited
first. A second `task_await`, or one after `let _ = task_await(t)`, read freed memory
(reproduced: SIGSEGV). Polling a task every frame and then reading it made that the
common case.

Now the Task keeps every heap result (`MARCH_TASK_OWNS_RESULT` in the header pad, set by
the trampoline; `march_run_resource_dtor` releases it when the Task dies) and each read
takes its own reference: `task_result_ok` for await and poll, a `march_incrc` before the
Task handle's release in `task_await_unwrap`'s pointer path. The Float-only `+1` in the
await arm is gone (subsumed). A task cancelled after it finished has its result word
overwritten by the cancelled sentinel, so that result is not released (a leak, never a
double free), as for a Float box before.

## Tests

- `test/test_codegen.ml` (`tasks`): IR uses `@march_task_poll` and no await; interpreter
  finished / cancelled / poll-then-await; one program run interpreted and compiled at
  `--opt 0` and `--opt 2`, single and multi scheduler (finished, polled again, awaited,
  polled after await, cancelled, Float, String, 200 tasks polled from one loop); and a
  compiled-only program where a gated task polls `None` 1,001 times within the time limit,
  then `Some(Ok(42))`, plus String and Float read legs whose `live_allocs` delta is 0
  over 1,000 tasks.
- `test/test_search.ml`: `forge search` qualified-name match (`task_poll` finds
  `Task.poll`).
