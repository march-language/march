- ✅ **Perceus dead br_var EDecRC leak fix (2026-06-24)** — In the Perceus pass (`lib/tir/perceus.ml`), pattern-match branches that bind constructor fields but never use them (e.g. `PVec(n, _, _, _) -> n`) caused a permanent RC leak. When the scrutinee was shared (RC > 1), `llvm_emit`'s shared path incremented RC for all heap-typed br_vars (root, tail); the branch body only returned `n`, so root/tail RCs inflated permanently. Fix adds two pieces to the `ECase` handler in `insert_rc_expr`: **(1) br_var ctx population** — before processing each branch body, all br_vars are added to `_var_ctx` (with save/restore for shadowing) so the cross-branch dead-variable pass can see them and emit `EDecRC` for fields dead in some branches but live in others; **(2) dead br_var EDecRC** — after `insert_rc_expr` on the branch body, emit `EDecRC` for each br_var that is heap-typed (`needs_rc`), not in `live_before_br` (never referenced in the branch body), not in `_closure_fvs`, and not in `_borrowed_field_vars`. In the unique (FBIP) case the field was moved from the freed constructor and is released here; in the shared case the llvm_emit shared-path inc_rc is balanced by this dec_rc. The `scrutinee_borrowed = true` case is handled correctly: all br_vars are re-added to the live set so the dead-check suppresses EDecRC for borrowed fields. Also registers `rrb_vec.march` and `parallel.march` in `stdlib_file_list` (`bin/main.ml`) so `--compile` finds the `RRB` and `Parallel` modules; and fixes the double-untag in `task_await_unwrap` (`lib/tir/llvm_emit.ml`): for i64 results, the thunk stores 4*n+3 (doubly tagged) — one coerce gives 2*n+1 (still tagged); a second conditional `ashr` recovers the raw integer (parallel reductions were returning `2×correct + N_workers`). Test count unchanged: **321 compiler / 224 eval / 786 stdlib / 49 stdlib_march**.
