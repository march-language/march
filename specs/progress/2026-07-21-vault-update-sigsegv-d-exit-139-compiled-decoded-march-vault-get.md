- ✅ **`Vault.update` SIGSEGV'd (exit 139) compiled — decoded `march_vault_get`'s niche Option as boxed, and used a stale closure-invocation ABI (`runtime/march_extras.c`, 2026-07-21).** Found while auditing `docs/cookbook/vault.md` against the compiler: `Vault.update(store, key, fn n -> n + 1)` crashed with no output whenever compiled, for both an inline lambda and a named top-level fn callback (interpreted was always correct — compiled-only). **Bug 1 (the crash):** `march_vault_get` returns a **niche-encoded** `Option(ptr)` — `None = NULL`, `Some(v) = v` itself (`make_some`/`make_none` at `:312-313`; no boxed tag/payload struct) — but `vault_update` decoded it as a **boxed** Option, reading a tag word at `cur+8` and a payload pointer at `cur+16`. For a scalar value (e.g. `Int`, tagged `(n<<1)|1`, so never a valid heap pointer) this read 8 bytes past the end of the value's own machine word, landing on an unmapped page → SIGSEGV on the very first access, before the closure was ever invoked. **Bug 2 (the closure-invocation call itself):** the code additionally called `fn(env, v)` with `env` read from a bogus `f+24` field, instead of the actual convention (`call_closure_1`, `march_http_internal.h`'s `closure_fn_t`) of passing the closure struct pointer itself as the first arg — `fn(f, arg)`. Investigation was initially done against a several-hundred-commit-stale local branch; **merging `origin/main` before landing turned up a THIRD, superseding wrinkle:** upstream (`specs/plans/2026-07-17-closure-scalar-abi-uniform-ptr.md`) had, in the interim, moved a closure apply-fn's *parameters* onto the same uniform-ptr ABI its return already used — the apply fn now conditionally untags a tagged scalar itself at entry (bare heap pointers pass through unaffected) and re-tags on return (`lib/tir/llvm_toplevel.ml`'s `emit_fn`: "Apply wrappers use the uniform ptr ABI for params too... The entry prologue below unboxes such params back to double/i64 for the body"). An initial version of this fix (written pre-merge, when params were still native/untagged) manually untagged the value before calling `fn` — that additional untag, once merged onto the new upstream ABI, double-processed odd/tagged values and silently produced wrong results (`3` incorrectly became `4`, confirmed by a fresh disassemble-and-recompute pass post-merge). **Final fix:** pass `cur` straight through unchanged to `fn(f, cur)` — the closure now handles the uniform-value conditional untag/retag entirely on its own, on both the param and return sides. Verified: the exact minimal repro (inline lambda + named fn) prints `2`/`3` compiled, matching interpreted; a `String`-valued `Vault.update` (`s ++ "!"`) round-trips correctly compiled (guards the heap-pointer branch); `docs/cookbook/vault.md`'s rate-limiter example runs end-to-end compiled with output identical to interpreted. New permanent regression test `test_compiled_vault_update` (`test/test_stdlib_suite.ml`, `adversarial-regressions` Slow group) exercises Int (lambda + named fn) and String, asserting exit 0. `scripts/run-tests.sh -q` (780 tests) and the targeted Slow Vault tests pass post-merge.
