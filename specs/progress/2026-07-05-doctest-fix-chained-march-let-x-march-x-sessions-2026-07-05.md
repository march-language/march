- ✅ **Doctest fix: chained `march> let x = ...` / `march> ...x...` sessions (2026-07-05)** — the extractor previously flushed and started a brand-new example on every `march> ` line, so a `let`-bound variable on one `march>` line was unreachable on the next: `lib/doctest/doctest.ml`'s `parse_expr` (via `bin/main.ml`) fed each line to the parser's `expr_eof` in isolation, which can't parse a bare `let` binding (block-`let` requires `do...end` or a following statement) — this raised `doctest parse error in: let parsed = ...`, then a spurious `unbound variable` failure on the next line's independently-evaluated example. Fixed in `lib/doctest/doctest.ml`'s `extract`: a `march> ` line arriving while the buffered example still starts with `let `/`let? `/`linear let ` (no expected-output line has closed it yet) now appends onto the SAME example instead of flushing, so the binding stays in scope. `bin/main.ml`'s `parse_expr` now wraps every doctest source in `do ... end` before calling `expr_eof` so multi-statement chained sessions parse as a block body (transparent no-op for the single-expression case). Fixes `Cli.get_string_or`/`get_bool`/`positional`/`get_int` (branch-only module, not on this branch) and the already-present `RRB.fold`/`RRB.chunk` doctests in `stdlib/rrb_vec.march`; verified via `test/stdlib/test_rrb_vec.march --verbose` (both now pass as a single doctest each) and a full stdlib-doctest sweep (`test/stdlib/test_*.march`, 91 files) showing zero `doctest parse error` occurrences. `Path.assert_no_traversal`'s two independent (non-`let`-headed) examples in `stdlib/path.march` are intentionally left un-merged and its pre-existing panic-vs-`ExpectNothing` failure is unrelated/unchanged.
