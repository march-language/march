- ✅ **Self-referencing block-`let` shadowing miscompiled on the native + JS backends — TWO bugs, both fixed (2026-07-10).** `let x = 10 / let x = x + 5 / …x…` printed 15 interpreted but a silently-wrong **10** compiled (and TDZ-crashed or mis-folded on `--target js`). The idiomatic `let x = x + 1` rebinding pattern, so high severity despite the narrow trigger (RHS must reference the binder being shadowed). Root-caused to TWO independent defects, each with a regression test/golden. **(1) `lib/tir/cprop.ml` (shared TIR, hit native + interp-constant-fold + JS):** the `ELet` arm extended the literal/alias/field env with the new binding but never REMOVED the outer binding's stale mapping when the shadowing RHS was not itself a literal/alias/record (e.g. `let x = x + 5` lowers to an `EApp`). So the outer `x -> 10` literal survived into the body and the body's uses of the NEW `x` were const-propagated to the OLD value; a later Fold baked in the wrong constant. Fix: drop `name` from all three envs (`env`/`avar`/`fenv`) before conditionally re-adding the new binding — mirrors the shadow-filtering the `ECase` arm already did for branch-bound vars; RHS look-ups still use the pre-removal envs so a self-alias can inherit outer field shape; `remove_assoc` on an absent name is a no-op so non-shadowing lets are unchanged. Regression: `test_compiled_let_shadowing_parity` (`test/test_codegen.ml`, `iface_impl_mono_codegen`) — chain `((10+5)*2)=30` (buggy=10). **(2) `lib/tir/js_emit.ml` (JS only, surfaced once cprop couldn't fold to a constant, e.g. a param-driven `mix32`):** a shadowing `let x = <expr using x>` emitted `const x = (…x…)` inside a fresh `{ }` block, and the RHS's `x` resolved to the block-HOISTED inner `const x` in its temporal dead zone → `ReferenceError`. Fix: thread a `name_env` (source name → current JS id) through emission; a binding that shadows an in-scope name is emitted under a fresh unique id (`x$sN`), the RHS is emitted BEFORE the new id is installed (so it reads the outer binding), and pattern-variable bindings in `emit_case` are registered the same way (a scrutinee/branch var on a renamed local now resolves correctly — also fixed `scrut_name` to use the rename). `name_env` is saved/restored around nested (`ELetRec`) fns. Golden: `test/native/js_let_shadowing.{march,expected}` (self-ref chain, a binding read before it is shadowed, and a match arm whose pattern var shadows an outer local — `29/129/101/8`, identical on all three backends). With both fixed, `stdlib/random.march`'s `mix32` was restored from the distinct-name workaround (`a`/`b`/`c`) to the classic self-shadowing splitmix32 idiom (`let x = f(x)` chain) and `seed`'s workaround comment corrected; the `js_random_determinism` golden stayed byte-identical. Full suite green: **451 compiler / 231 eval / 396 codegen / 807 stdlib**; all 10 JS goldens pass. Filed by the Random-on-JS work; a dedicated background session (`task_259907b1`) was also spun up.
