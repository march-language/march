✅ **Typed JSON decoding plan, Task 1 — `derive Json` capability map + `JsonStream` wiring proof (2026-07-31, `test/stdlib/test_json_typed.march`, `test/test_stdlib_march.ml`, `specs/2026-07-31-derive-json-capability-map.md`).** Discovery task for `specs/plans/2026-07-31-json-typed-decoding.md`: mapped what the existing `derive Json` generator (`lib/desugar/desugar.ml` ~1479-1730) actually supports, and proved `JsonStream.each_value` + `from_json` work end to end on the happy path (NDJSON file → typed records). **Two bugs found, both blocking for Phase A/B, not mere gaps:** (1) **cross-type shadowing** — `derive Json for T` binds one bare `from_json`/`to_json` per module, and a second `derive Json for U` in the same module silently rebinds those names, so every earlier type's bare call resolves to the *last*-declared type's decoder (reproduced via a pre-existing, previously-unregistered file `test/stdlib/test_derive_json_multi.march`, committed in `6486a275` but never wired into the alcotest suite — now recorded, not yet fixed); (2) **nested records panic**, not merely misdecode — a record with a field of another `derive Json` record recurses into decoding that field via the same shadowed name, reaches the *enclosing* type's own decoder, gets a graceful `Err` back, and a wrapping `match ... | Err(e) -> panic(e)` unconditionally promotes that to an uncatchable panic (reproduces with the minimal two-type case, not just as a shadowing artifact). Also found: `Option(T)`/`List(T)`/a type parameter all **compile** but **crash at runtime** on first `to_json`/`from_json` call with the same self-recursion failure (`field access on non-record value`); missing-field and wrong-type errors both collapse to the same generic `invalid JSON for <Type>` message; unknown fields are silently ignored (matches design Decision 2, but by accident — the decoder never reads extra keys — not by a designed check); duplicate keys resolve first-occurrence-wins; `JsonStream.each_value`'s callback return value is discarded (`stdlib/json_stream.march:791-797`), so a `from_json` failure inside the callback never reaches the stream-level `Result` — `each_value` reports `Ok(())` for a file even if one record failed to decode.
