- ✅ **`check_sendable` (the `RingBuf`-can't-be-a-message-payload rule) was a complete no-op — for `send()` too, not just `send_checked`/`Actor.cast`/`Actor.call`.** Actor message constructors are registered as `{ ci_type = "<Actor>_Msg"; ci_params = []; ... }` (`lib/typecheck/typecheck.ml`, three `DActor`-handling sites), a flat, non-parametric sum type shared by every handler on that actor. `check_sendable` was being called on `infer_expr env msg` — a constructor application's RESULT type, e.g. `TCon("Worker_Msg", [])` — which can never carry payload information since `ci_params` is always `[]`; the walk had nothing to recurse into regardless of what was sent. Confirmed empirically: reverted to the pre-session baseline and sent a genuine `RingBuf(Int)` payload through plain `send()` — it typechecked clean. There was no reject-corpus witness for `RingBuf` before this session, which is why this was never caught (an accept-only witness, `t40`, only proved an *ordinary* payload wasn't wrongly rejected). **Fix:** added a `ci_is_actor_msg : bool` field to `ctor_info`, set `true` only at the three `DActor` message-registration sites (`false` everywhere else, including the actor's own zero-arg name ctor used by `spawn`, and every ordinary user ADT/builtin ctor — OCaml's record-literal exhaustiveness check enumerated every site that needed updating, so none could be silently missed). The shared `ECon` typing arm now runs `check_sendable` over each **instantiated argument type** (already computed via `instantiate_ctor` for the existing per-argument unification) when `ci.ci_is_actor_msg` is true — this fires once, at message-*construction* time, so it uniformly covers `send`, `send_checked`, `Actor.cast`, `Actor.call`, and indirect sends (constructing a message, binding it to a variable, sending later) with one check instead of one per builtin. Removed the now-provably-redundant `check_sendable` call from the `ESend` arm and three dead `EApp` special-cases an earlier attempt at this fix had added for `send_checked`/`actor_cast`/`Actor.cast`/`actor_call`/`Actor.call` (all checked the same uninformative flat result type — harmless no-ops, but redundant once the construction-site check exists).
