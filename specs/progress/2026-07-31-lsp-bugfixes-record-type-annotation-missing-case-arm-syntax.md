- ✅ **LSP bugfixes: record-type annotation + missing-case arm syntax** — two code-action bugs that produced source the parser rejects. (1) **Add type annotation** rendered an inferred *record* return as `{ a : Int, b : Int }` and inserted `fn … -> { … } do`, which is a parse error — `Tc.TRecord` is purely structural (no nominal name), so `pp_ty` cannot print a valid annotation and March has no anonymous-record type syntax. Fix: `annotatable_ty_str` guards all three annotation kinds (`AnnLet`/`AnnFnReturn`/`AnnFnParam`) and skips the action when the rendered type contains `{`. (2) **Add missing case** generated `| Ctor -> ?` with a leading `|`; March match arms separate on `NL | PIPE`, so a `|` after the existing newline is a double separator → parse error. Fix: `arm_text_for_case` drops the leading `| ` (the `?` hole body is valid). Two existing tests that asserted the buggy `|` format were corrected. +3 LSP tests (226). Note: records printing structurally (e.g. hover shows `{ … }` not the type name) is an upstream `Tc.pp_ty`/type-rep matter, out of LSP scope.
