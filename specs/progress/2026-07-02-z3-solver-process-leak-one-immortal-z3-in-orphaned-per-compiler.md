- ✅ **Z3 solver process leak — one immortal `z3 -in` orphaned per compiler/test process (`lib/refine/solver.ml`, `lib/refine/refine.ml`, `bin/main.ml`, 2026-07-02)** — two compounding defects: (1) `Refine.shared_solver`, the lazily-created per-process singleton behind every `Refine.discharge`, was never closed on any production path (`Solver.close` had zero callers outside two test files), so every `march --check`/`--compile` run and every test binary left its z3 child running at exit; (2) `Solver.create` built its pipes without `~cloexec:true`, so the z3 child inherited the write end of its own stdin pipe — after the parent died the pipe never delivered EOF and the orphan blocked in `read(0)` forever (1,174 immortal orphans at 0% CPU, ages 2h–24h, found reparented to PID 1 on 2026-07-02). Fixed: cloexec on all four pipe ends; `Solver.close` SIGKILLs before `waitpid` (reaping can never block on a wedged solver); new `Refine.shutdown` closes + clears the singleton, registered `at_exit` on first spawn and called explicitly at the end of both refinement-pass scopes in `bin/main.ml`; `discharge` supervises the solver (dead/wedged → reap, respawn once, then mark unavailable for the run); SIGPIPE ignored (only if at default) so solver death is a catchable error, not parent death. Regression tests in `test/test_refine.ml` ("lifecycle" suite, pgrep-based, loud-skip without z3): spawn-count check (3 discharges → 1 child during, 0 after `shutdown`) and an orphan probe (re-exec via `MARCH_Z3_ORPHAN_PROBE=1`, exit without cleanup, assert z3 dies ≤5s; verified RED against pre-fix pipes). End-to-end verified with a `MARCH_Z3` pid-logging shim: one z3 per `--check` run, reaped before exit. Full suite green (compiler 384, eval 230, codegen 337, stdlib 792 incl.
