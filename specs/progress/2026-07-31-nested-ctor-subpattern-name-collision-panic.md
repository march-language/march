- ✅ **Nested constructor sub-pattern over a name-colliding ADT panicked "non-exhaustive pattern match" compiled-only (2026-07-31, `lib/typecheck/typecheck.ml` `infer_pattern`'s `PatCon` arm, `lib/tir/lower_match.ml` `field_ty_at`).** `match rows do Cons(Row(fp), rest) -> ... end` — a nested constructor sub-pattern (`Row(fp)`) destructuring a field whose declared type (`Row`) shares its short name with an unrelated stdlib type (`DataFrame.Row`, `Csv.CsvRow`'s `Row` ctor) — matched fine interpreted but panicked `non-exhaustive pattern match` compiled. Flagged by the differential oracle sweep (`test/native/nested_cons_ctor_heap.march`, previously an UN-TRIAGED FAILURE). Root cause: `lower_match.ml`'s pattern-matrix compiler mints every destructured sub-pattern variable at `unknown_ty` (`TVar "_"`) unless every row in the group either wildcards the field or (for scalar RC-safety reasons, see the long-standing comment there) names it directly — a NESTED constructor sub-pattern fell into neither carve-out and always got `TVar "_"`, an undocumented gap. At codegen, `Collision_set` correctly forces any type whose short name is declared by ≥2 modules to `Boxed` with a globally-unique per-constructor tag (`Llvm_toplevel.build_ctor_info`, keyed `"TypeName.CtorName"`) — correct on the `EAlloc` side, which always has the concrete type. But `emit_case`'s `qualified_br_key` can only qualify a bare tag ("Row") into that key when the scrutinee's static type is a concrete `TCon`; with it erased to `TVar "_"` the tag stayed bare, and `Llvm_data.ctor_entry`'s ambiguous by-arity suffix-scan fallback (built for a different, legitimate cross-type-collision case) picked among all THREE same-short-name `Row` ctors — Main's, `DataFrame.Row`'s, `Csv.CsvRow`'s — by arity alone, which tied at 1 for all three, so hashtable iteration order could hand back a foreign type's tag. The switch's case label then never matched the value's real (correctly-tagged) heap header, always falling to the default arm. **Fix:** `infer_pattern`'s `PatCon` arm now records the constructor pattern's own resolved type into `env.type_map` at the ctor name's span (mirroring the existing `PatWild`/`PatVar` recordings), making it resolvable via `Lower_state.ty_of_span` for the first time. `lower_match.ml`'s `field_ty_at` now looks up a concrete type whenever NO row binds the field to a raw name (`PatVar`/`PatAs`) — widened from the previous "only if every row wildcards it" — so a nested constructor sub-pattern gets its real static type (e.g. `TCon("Row",[])`) instead of `TVar "_"`. That lets `qualified_br_key` build the exact `"Row.Row"` ctor_info key up front, the same key `EAlloc` already used, so match and construction always agree. The existing scalar-RC safety invariant for NAME-bound fields (`Ok(n) -> int_to_string(n)`, see the surrounding comment) is untouched — only `PatVar`/`PatAs` still force `unknown_ty`. **Verified:** `scripts/run-tests.sh` full suite green (`run_compiler` 620, `run_eval` 256, `run_codegen` 538, `run_stdlib` 780, all exit 0); `dune build --root . @test/oracle` — `test/native/nested_cons_ctor_heap.march` now MATCH (was UN-TRIAGED FAILURE), corpus back down to 0 total divergences.
