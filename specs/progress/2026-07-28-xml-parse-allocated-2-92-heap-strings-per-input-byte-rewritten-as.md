- ✅ **`Xml.parse` allocated ~2.92 heap strings per INPUT BYTE; rewritten as a byte-index scanner (2026-07-28, `stdlib/xml.march`).** Same template applied to tag/attribute-name scanning, quoted attribute values, and text content. Comment/CDATA/PI bodies (no entity expansion needed) collapsed to a single delimiter scan + one slice each; text/attribute-value scanning (which needs `&amp;`/`&lt;`/`&gt;`/`&quot;`/`&apos;`/`&#NNN;` entity expansion) uses the same run-slicing scheme as `Json.scan_string`. The output-side `escape_xml_text`/`escape_xml_attr` serializers had the identical per-character pattern and were rewritten too. Measured compiled `--opt 2`, a 616-byte document, 2,000 iterations: **allocs/byte 2.92 → 0.10** (3,600,066 → 124,047 allocations, a ~29x reduction). Verified via the existing `test_xml.march` suite (unchanged, all passing) plus a 10-case round-trip corpus (nested tags, quoted attrs, entities, comments, CDATA, DOCTYPE+PI, deep `find`, multibyte UTF-8, `to_string`/`to_string_pretty`, 3 malformed-input error cases).
