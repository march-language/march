- ✅ **Cross-session-safe ~/.cache/march: content-hash-keyed artifacts + atomic writes** — the shared cache dir let concurrent sessions/worktrees corrupt each other. Two fixed-name artifacts were the worst: `libmarch_runtime.so` (`bin/main.ml ensure_runtime_so`, invalidated only by `march_runtime.c`'s mtime — edits to the other ~10 runtime C files never invalidated it) and `libmarch_rt_test.so` (`test/test_march.ml setup_jit_runtime`, existence-check only — NEVER invalidated). A worktree with diverged runtime sources overwrote the shared file with an ABI-mismatched binary, hanging whichever session dlopen'd the wrong build (observed: 22-minute test_march.exe hangs); a reader could also dlopen a half-written .so mid-compile. Fix: both are now keyed `libmarch_runtime_<hash16>.so` / `libmarch_rt_test_<hash16>.so` where the digest covers every compiled .c file, every runtime/*.h, and (for the runtime) the full clang flag string — identical inputs share one artifact, divergent worktrees get separate files — and ALL five cache writers (those two plus `stdlib_prelude_<h>.so`/`.names` in `lib/jit/repl_jit.ml`, `stdlib_ast_<h>.bin` in `bin/main.ml`, `stdlib_tcenv_<h>.bin` in `lib/repl/repl.ml`) now write to a pid-suffixed temp and `rename(2)` into place, so no reader ever sees a partial file. The prelude `.names` is renamed BEFORE its `.so` so a visible .so always implies a complete names file. `ensure_runtime_so` with no source tree falls back to the newest cached `libmarch_runtime_*.so`. Verified: fresh-cache REPL eval, warm-cache reuse (mtime unchanged), runtime-source edit produces a NEW key leaving the old artifact intact, JIT test group green on isolated HOME, no `.tmp` leftovers.
