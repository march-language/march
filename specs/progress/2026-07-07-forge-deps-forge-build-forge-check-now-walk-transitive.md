- ✅ **`forge deps`/`forge build`/`forge check` now walk transitive dependencies instead of only a project's own direct `[deps]` (`forge/lib/project.ml`, `forge/lib/cmd_deps.ml`, `forge/lib/cmd_build.ml`, `forge/test/test_build_check.ml`, 2026-07-07).** Found while running a `forge build`/`forge check` timing analysis against a real external project (`~/code/scroll`, depends on `bastion` via path): `forge check` failed with `` Unknown module `Pool` `` (a module belonging to `depot`, which `bastion`'s own `forge.toml` depends on) — scroll never declared `depot` itself. **Root cause:** both `Cmd_deps.run` (installs deps + writes `forge.lock`) and `Cmd_build.lib_path_env` (builds `MARCH_LIB_PATH`) iterated only the current project's own flat `deps` list — neither recursed into an already-installed dependency's own `forge.toml` to discover ITS dependencies. (Note: `Archive_store.dep_lib_paths_for_archive`, used by the separate `forge publish`/archive-packaging path, already walked transitively — this gap was specific to the live dev-build/check path.) **Fix:** new `Project.dep_root_dir` resolves an installed dependency's own root (a `PathDep`'s target, or a git dep's CAS clone under `~/.march/cas/deps/<name>`) so its `forge.toml` can be read. `Cmd_build.collect_transitive_deps` recursively expands `MARCH_LIB_PATH` through every dependency-of-a-dependency, carrying each entry's own declaring root (a nested dep's `PathDep` is relative to ITS root, not the top-level project's). `Cmd_deps.bfs_install` installs wave-by-wave, discovering the next wave from each just-installed dep's own `forge.toml` `[deps]` (must run AFTER install since a git dep's `forge.toml` doesn't exist until cloned) and records every transitively-discovered dep in `forge.lock`. Both dedup by name with nearest-wins semantics and a `visited` set guards against dependency cycles. Verified live against the real scroll → bastion → depot chain (workaround of adding `depot` directly to scroll's `forge.toml` reverted first): `forge deps` now records `depot` in scroll's own `forge.lock`, and `forge check` passes cleanly with no direct scroll→depot dependency declared. New Alcotest case `test_lib_path_env_walks_transitive_path_deps` in `forge/test/test_build_check.ml` (a 3-project A→B→C path-dep chain where A's own code calls a C module directly).
