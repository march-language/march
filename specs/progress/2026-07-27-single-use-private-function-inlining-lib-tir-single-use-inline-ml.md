- ✅ **Single-use private-function inlining (`lib/tir/single_use_inline.ml`, `lib/tir/inline.ml`, `lib/tir/dce.ml`, 2026-07-27).** A new `single-use-inline` TIR pass, scheduled in the Opt fixed-point loop right after ordinary pure-only inlining, relocates a private top-level function's body to its call site when it has exactly one direct, arity-correct reference anywhere in the module — even when the body is impure — since Perceus has already made ownership explicit by that point in the pipeline, so substitution just carries the existing `EIncRC`/`EDecRC`/`EFree`/`EReuse` operations and their order along unchanged. Reuses the existing 50-node size limit, DCE-root/address-taken/collision-dispatch/hot-code-reload exclusions, and recursive-SCC detection from the ordinary inliner. **Post-implementation review found three Critical soundness gaps, closed in the same fix wave:** (1) a caller-local binding could shadow and silently capture one of the callee's free names — `single_use_inline.ml`'s `try_inline_call` now checks the callee's free-name set against the caller's bound set and conservatively keeps the un-inlined call on any collision; (2) `Inline.alpha_rename` mutated ONE ambient rename table across sequence siblings, case arms, and the default arm, so a binder in one arm could leak into an unrelated sibling, and never bound a nested `ELetRec`'s own parameters at all — replaced with a persistent, properly lexically-scoped environment (`SMap`) threaded per-subexpression, and freshening now also avoids every existing free/global name in the body, not just the parameter list; (3) a bare unqualified call (`helper(...)`) and a fully-qualified call (`Module.helper(...)`) to the SAME function were counted as two separate references instead of one, under-counting call sites — reference/successor accounting and SCC construction now resolve bare names against qualified top-level names first (exact name, then extern, then a same-suffix qualified alias), and an AMBIGUOUS bare alias (two same-named functions in different modules) conservatively marks every candidate target non-direct rather than guessing. Also fixed: the native-LLVM Dune regression gate raced two rules writing the same undeclared `.ll` sibling and treated `grep`'s "no match" exit status 1 the same as a real grep error (status ≥2) — rules now copy the fixture onto distinct declared basenames per rule and the check script distinguishes missing/unreadable input, a real match, and a genuine grep failure. **Verification:** focused `single_use_inline` (29 cases, was 24), combined `inline` (10, includes 4 new lexical-scoping regressions), DCE, mutual-TCO, and reduction-check groups all pass; full `run_codegen` suite passes including the native LLVM verifier corpus. **Corpus measurement (93 non-JS top-level native fixtures at the measurement commit, now 94 after an unrelated rebase — see `specs/progress.md`'s 2026-07-27 entries for the count correction and the independent no-op check on the added fixture):** 180 removed call/definition occurrences across 53 affected fixtures, 159 of them touching explicit RC operations; no runtime speedup was measured, only fewer emitted LLVM definitions and calls.
