- ✅ **Fix `hmac_sha256` typecheck signature disagreeing with every implementation** — the typechecker entry (`lib/typecheck/typecheck.ml`) declared `Bytes -> Bytes -> Bytes`, but the eval builtin returns `Ok(Bytes)`, the native runtime (`march_hmac_sha256` in `runtime/march_extras.c`) reads `march_string` args and returns `Result(Bytes, String)` via `make_ok`, and llvm_emit's `builtin_ret_ty` says `Result(Bytes, String)`. Net effect: correct usage (`match hmac_sha256("k","m") do Ok(b) -> ...`) was rejected by the typechecker, while the only usage it accepted (treating the result as bare `Bytes` with `Bytes` args) would have crashed or miscompiled at runtime. Canonical signature is now `String -> String -> Result(Bytes, String)` — matching the C runtime, eval, llvm_emit, and the existing `stdlib_hmac_sha256` entry. The Bytes-domain variant `hmac_sha256_bytes : Bytes -> Bytes -> Bytes` (bare result, commit d07356d) was already consistent across all four sites and is unchanged. Typecheck-level regression tests added for both builtins (the existing tests only exercised eval, which is how the mismatch slipped through). 1424 → 1426 tests.
