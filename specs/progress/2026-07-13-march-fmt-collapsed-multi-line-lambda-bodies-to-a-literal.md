- ✅ **`march --fmt` collapsed multi-line lambda bodies to a literal `...` placeholder, producing invalid syntax (`lib/format/format.ml`, `test/test_fmt.ml`, 2026-07-13).** Any lambda whose body needed multi-line rendering (a multi-statement `let`-chain) was formatted via the single-line `expr_inline` pretty-printer, whose `EBlock` case returns the literal string `"..."` for any block with more than one statement — a terse-summary stub meant for other diagnostic contexts, never meant to reach formatter output. Hit the dominant real-world shape (a lambda passed as a trailing call argument, e.g. `List.map(xs, fn x -> ...)`, ~167 occurrences across `stdlib/`), a `let`-bound lambda, a pipe stage (`xs |> List.map(fn x -> ...)`), and a lambda nested through wrapper constructors in tail position (`GenTree(w, Thunk(fn _ -> ...))`, real case in `stdlib/gen.march`). **Fix:** `is_multiline` now recognizes `ELam` (via its body) and `EApp`/`ECon` whose argument list ends — possibly through a chain of wrapper calls/constructors — in such a lambda (`trailing_multiline`). The block renderer gained a matching `ELam` case in `emit_stmt` and a new `emit_call_multiline` for the "trailing block" call shape, which walks the same wrapper chain and closes all opened parens together on one line, matching existing idiomatic stdlib style; `emit_pipe_chain` now uses the same renderer per stage instead of unconditionally calling `expr_inline`. Verified via targeted repros (let-bound/call-arg/pipe-stage/nested-ctor lambdas, each checked for idempotence and re-parseability) plus a full `--fmt` sweep of every `stdlib/*.march` file — zero remaining `-> ...` artifacts. 4 new regression tests in `test/test_fmt.exe`. **Two pre-existing, unrelated `--fmt` round-trip bugs found incidentally and filed separately (not fixed here):** float literals reformatted into scientific notation the parser then rejects (`0.0000009537` → `9.537e-07` → parse error), and record literals that fail to re-parse after formatting (`test_record_literal`, already failing on `HEAD` before this fix). See `specs/progress.md`'s "`march --fmt` multi-line lambda body corruption fixed" entry for the full writeup.
