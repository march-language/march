- ✅ **LSP DAP inline values (`textDocument/inlineValue`)** — the LSP side of the DAP debugger: while the debugger is stopped at a breakpoint, the editor requests inline values for the visible range and the server returns the in-scope locals so the editor renders their live values next to the code. Capability `inlineValueProvider = Some (\`Bool true)` in `config_modify_capabilities`. Handler in `on_unknown_request` parses `range` + `context.stoppedLocation` from the raw JSON params defensively (missing/garbled → empty list, never throws) and serialises `InlineValue.t list`. Computation in `analysis.ml`: `inline_values_at ~range_start_line ~range_end_line ~stopped_line` walks the scoped, shadow-correct symbol tables (`sym_defs`/`sym_name`/`sym_id_uses`) — each binder's definition span plus all its use spans are candidate occurrences — keeping those whose 0-indexed start line is within the requested range **and** at/above the stopped line; de-duplicated by variable name (the occurrence nearest the stopped line from above wins) so the editor draws one value per variable; underscore-prefixed and non-user-file names skipped. Emitted as `InlineValueVariableLookup` (`caseSensitiveLookup:true`, name + span range) for the debugger to resolve. UTF-16 wrapper `query_inline_values` remaps outbound ranges (line band is encoding-independent). +5 LSP tests (246 total): locals-in-range, names+positions (case-sensitive, stopped-line use chosen for `a`), below-stopped-line exclusion, de-dup of repeated `x`, no-crash on error buffer.
