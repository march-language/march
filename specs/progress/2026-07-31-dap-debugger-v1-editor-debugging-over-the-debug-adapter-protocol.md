- ✅ **DAP debugger v1 — editor debugging over the Debug Adapter Protocol** — Exposes the interpreter's existing trace/breakpoint engine to editors. **Engine** (`lib/eval/eval.ml`): new `step_mode` type and `dc_breakpoints`/`dc_step`/`dc_on_pause`/`dc_last_line` fields on `debug_ctx`; a `maybe_pause` check in the universal `eval_expr` wrapper stops on editor-set gutter breakpoints (keyed by file+line) and on step over/into/out, with last-line de-duping for line-granular stepping (zero overhead when no debug ctx installed). **Server** (`lib/dap/`): `dap_json.ml` (Content-Length framing) + `dap_session.ml` — a `launch`-model DAP server that runs the program on a worker `Thread` and answers requests on the protocol thread, rendezvousing via `Mutex`+`Condition`; handles `initialize`/`launch`/`setBreakpoints`/`configurationDone`/`threads`/`stackTrace`/`scopes`/`variables`/`continue`/`next`/`stepIn`/`stepOut`/`pause`/`evaluate`/`disconnect`; emits `initialized`/`stopped`/`continued`/`output`/`terminated`/`exited`. Call stack reconstructed from the named march-stack + pause location; Locals = the paused frame's env (builtins filtered). **Entry**: `march dap` subcommand in `bin/main.ml` (reuses `load_stdlib` + `run_module`), with the program's stdout redirected to DAP `output` events so the protocol stream stays clean. **Editors**: complete VS Code debug extension (`editors/vscode-march-debug/`, exports validated via mocked `vscode` host) **and** functional Zed client (Rust `get_dap_binary`/`dap_request_kind`/`dap_config_to_scenario` in `zed-march/src/lib.rs`, wasm rebuilt). Program stdout is flushed before termination so it reliably streams to DAP `output` events. **Tests**: `test/dap/test_dap.ml` — 5 end-to-end cases (breakpoint+stack+locals+continue, step-into a function, output events, panic-still-terminates, multiple breakpoints). v2 backlog (engine already supports the first): reverse debugging (`stepBack`/`reverseContinue`), conditional/hit-count breakpoints, watch, structured-value expansion, actor-as-thread.
