- ✅ **Compiler robustness: an unreadable sibling directory crashed `--compile`/`--check` with an uncaught `Sys_error` (`lib/resolver/resolver.ml`, `bin/main.ml`, `test/test_codegen.ml`, 2026-07-04).** Found while running the differential oracle for real (Task 1 of the differential-oracle work; design at `specs/2026-07-04-differential-oracle-design.md`). The compiler auto-discovers sibling `.march` modules in the entry file's OWN source directory (`resolve_imports` plus the early-CAS sibling hash both walk it via `March_resolver.Resolver.collect_lib_files`). That recursive walk classified a subdirectory with `Sys.is_directory` (which stats fine on a permission-denied dir → `true`), recursed into it, and then called `Sys.readdir` on it **with no exception guard** — so a permission-denied sibling directory raised `Sys_error` uncaught to `bin/main.ml`'s top level, killing the compile (exit 2, no output binary) on an otherwise well-typed program. The trigger is real on stock macOS: `$TMPDIR` (`/var/folders/.../T/`) contains a Spotlight-managed `TemporaryItems` directory that is `Operation not permitted`, so any well-typed program placed directly in `$TMPDIR` failed to compile. Fixed by guarding the recursive `Sys.readdir` in `collect_lib_files` (`try … with Sys_error _ -> [||]` → an unreadable directory is treated as empty and skipped, never aborts the walk). Hardened the parallel unguarded walk `march_files_in` in `bin/main.ml` (the `--check <dir>` path — same latent bug, plus its `Sys.is_directory` is now exception-safe) and the `march test` auto-discovery `Sys.readdir "test"` (permission-denied `test/` now skipped like a missing one). The two other `Sys.readdir` sites (`cache_dir`, `runtime_dir`) were already guarded; the remaining `Sys.is_directory`-in-predicate sites are each short-circuited by a preceding `Sys.file_exists` and never readdir, so they can't hit this class. Regression: new `compiler_robustness` group in `test/test_codegen.ml` (`test_unreadable_sibling_dir_does_not_crash_check`) — a well-typed entry beside a 0000-perm sibling dir must `--check` at exit 0 (`--check` shares the exact crashing early-CAS/resolver walk with `--compile` but needs no clang, so it runs everywhere; perms restored via `Fun.protect`). RED→GREEN verified (unfixed binary: `Sys_error(... TemporaryItems ...)` EXIT:2 → fixed: EXIT:0). **Note:** this was independently worked around in the oracle harness itself (`test/test_properties.ml` isolates each generated program in its own dedicated temp dir), but the compiler must not crash on it — that is what this fixes. Six-runner gates: **392 compiler / 230 eval / 381 codegen (+1 new) / stdlib / 53 stdlib_march / 29 snapshots**; the 14 `adversarial-regressions` (stdlib `Unknown module IO/BigInt`) and 1 `llvm_ir_validity_gate` (distributed-program TIR-typing) failures in this worktree were verified **pre-existing on the base commit** (identical failures with the fix reverted) — unrelated to this change and out of scope.
