- ✅ **macOS nightly CI build intermittently failed on `test/native/node_call_loopback.march` — `tcp_connect: connection refused` on a freshly-`listen()`ed loopback socket (2026-07-21).** The macOS-only `Build (macOS)` step failed rarely (passed 2026-07-07, failed 2026-07-20/07-21) with the client-side `Socket.connect("127.0.0.1", port)` refused immediately after the SAME process had already synchronously completed `tcp_listen(port)` (bind+listen, no async gap) — a real TCP race was ruled out (kernel accept-backlog is live the instant `listen()` returns, independent of whether `accept()` has been called), confirmed by 30 clean local runs plus a concurrent-stress run on this exact macOS/arm64 hardware that reproduced only genuine port collisions (running duplicate copies of the same binary), never a same-process refusal. Traced the July-10 scheduler foreign-wake rewrite (`67452c89`) as a candidate and ruled it out — this test's connect/accept are both plain blocking syscalls on the single green thread that also runs `main`, never touching the foreign-thread wake path. Root cause is external: `actions/runner-images#10924` (macOS 15 runners gained a new, OS-level Local Network TCC permission layer with no way to pre-grant consent in a headless CI session, closed WON'T-FIX by GitHub) and its macOS-15-specific TCP-connect-refused duplicate `actions/runner-images#11901` document exactly this class of intermittent same-machine TCP failure on `macos-15`/`macos-15-arm64` runners. Two changes: (1) `runtime/march_http.c` `march_tcp_connect` no longer hardcodes `"tcp_connect: connection refused"` on any `connect()` failure — it now reports `strerror(errno)`, so a recurrence will show the real cause (e.g. `EHOSTUNREACH`/`EPERM` vs. genuine `ECONNREFUSED`) instead of a misleading fixed string; (2) `test/native/node_call_loopback.march` wraps the test's initial connect in `connect_with_retry` (bounded same-process retry, 5 attempts) since March has no `sleep` builtin to back off with — an immediate retry is the workaround reported to clear this class of runner flake. Verified: new binary matches `node_call_loopback.expected` byte-for-byte across 15 runs; full `scripts/run-tests.sh -q` green (779 tests); no golden/test asserts on the old literal error string (`test/stdlib/test_socket.march`'s "connection refused returns Err" only checks `Err(_)`).
