A NAMED field (`Cons(h, t)`) gets rebound downstream (`bind_trivial_pat`) to its real type via `Lower_state.ty_of_span` — the typechecker's own tracked unification variable for that pattern occurrence — which then flows through `mono.ml`'s substitution normally (`subst_branch` substitutes every `br_var`, but only a REAL tracked tyvar, not the `TVar "_"` sentinel `Mono.has_tvar` deliberately excludes, actually resolves). A WILDCARD field is never rebound, so its synthetic var keeps `TVar "_"` forever; `Rc_types.needs_rc (TVar "_")` conservatively answers `true` ("assume heap-carrying"), so Perceus emits a `dec_rc` on it. Together, a discarded field now flows through `mono.ml`'s existing substitution machinery exactly like a named one — `needs_rc` sees the real, concrete (post-mono) field type, and Perceus stops emitting the spurious `dec_rc`/`inc_rc` in the first place.
