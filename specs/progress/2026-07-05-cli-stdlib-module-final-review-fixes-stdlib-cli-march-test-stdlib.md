- ✅ **`Cli` stdlib module — final-review fixes (`stdlib/cli.march`, `test/stdlib/test_cli.march`, 2026-07-05).** Whole-branch review of the completed 4-task `Cli` plan raised four findings, all fixed: (1) *dead ADT variant* — `CliError.InvalidValue(String, String)` was defined and rendered by `error_message` but never constructed by anything (`get_int` swallows a parse failure into `None`, not a `CliError`); deleted the variant and its `error_message` arm and the corresponding test assertion, since `CliError` should only carry variants `parse` can actually produce (`UnknownFlag`/`MissingValue`/`MissingRequired`) — matches the shipped fail-safe/`Option`-returning accessor design, not a `Result`-returning one. (2) *no end-to-end composition test* — added `describe "Cli end-to-end composition"` in `test/stdlib/test_cli.march`: one spec list (`sample_specs()`) drives both `Cli.parse` (read back via `get_string_or`/`get_bool`/`get_int`/`positional` on the same parsed result) and `Cli.help_text`, proving the module's central "one spec list, two consumers" design claim. (3) *negative-number positional misclassified as unknown flag* — `flag_name` treated any `-`-prefixed token as flag-shaped, so `Cli.parse(specs, ["-5"])` wrongly returned `Err(UnknownFlag("5"))`; added private `single_dash_is_negative_number_or_bare` (uses `Char.is_digit` on the character after a single dash) so a lone `-<digit>` (or bare `-`) now returns `None` from `flag_name` (treated as positional), while any `--`-prefixed token (even `--5`) is unaffected and still flag-shaped. New test: `Cli.parse([], ["-5"])` succeeds with `"-5"` in `positional`. (4) *cheap behavior-pinning tests* — added a test asserting a flag passed twice (`["--port","1","--port","2"]`) keeps the FIRST value (`"1"`, current `parse_loop` accumulate-then-reverse semantics, unchanged) and a test asserting empty argv against a spec list with a required flag returns `Err(MissingRequired(...))`. **Verification:** `dune build --root .` clean (removing the `InvalidValue` variant left no dangling references — exhaustiveness checker had nothing to flag since the `error_message` arm was removed in the same edit); `./_build/default/bin/main.exe test test/stdlib/test_cli.march` — all 18 named tests pass (24 doctest failures remain, identical pre-existing `expr_eof`-single-expression gap from Tasks 1–2, none newly introduced); `scripts/run-tests.sh -q` — 773 stdlib-quick tests + compiler/eval/codegen all green, no regressions. Grepped the whole repo for other `Cli`/`InvalidValue` references — none found outside `stdlib/cli.march` and `test/stdlib/test_cli.march` (brand-new module, nothing else depends on it yet).
