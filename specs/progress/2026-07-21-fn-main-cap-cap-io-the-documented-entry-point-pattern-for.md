- ✅ **`fn main(cap : Cap(IO)) : ()` — the documented entry-point pattern for receiving the initial IO capability (`specs/lang/capabilities.md`, "Putting it together") — was broken on BOTH backends; now actually works, plus a desugar-time arity/type check rejects any other `main` shape with a clear diagnostic (`lib/desugar/desugar.ml`, `lib/eval/eval.ml`, `lib/tir/llvm_toplevel.ml`, 2026-07-21).** Found auditing `docs/cookbook/capabilities.md` against `specs/lang/capabilities.md` (the authoritative reference it cross-references): the tutorial's own canonical `Main` module example (`fn main(cap : Cap(IO)) : ()`) never worked. **Interpreted:** `Eval.run_module` called every `main` with zero arguments regardless of declared arity (`apply v []`) — a 1-parameter `main` became an unapplied partial closure and silently never ran (no crash, no output, exit looked successful). **Compiled:** `march_spawn_main`'s runtime trampoline (`runtime/march_runtime.c`'s `main_fn_green_thread`) invokes the compiled entry point through a bare 0-argument function pointer; a 1-parameter `main` was still emitted with a real `ptr` parameter in its LLVM signature (`Cap(IO)` erases to a generic `TCon`, which `llvm_ty` maps to `ptr`), so the runtime called it through a mismatched-arity function pointer — undefined behavior at the ABI level, observed as a SIGBUS. Neither backend had ever special-cased `main`'s arity at all; a wrong-arity `main` (e.g. `fn main(x : Int)`) was silently accepted and would have hit the same two failure modes. **Decision: implement the documented pattern for real** (not just diagnose-and-redirect to `root_cap`) — `Cap(IO)` is fully runtime-erased (`null` in LLVM, `VUnit` in the interpreter per "Runtime behaviour"), so wiring it up is cheap, and the reference already assumes it throughout ("The initial `Cap(IO)` is provided implicitly by the runtime to `main()` — there is no `root_cap()` call in user code"). **Fix, three sites:** (1) `Desugar.check_main_signature` (new, called from `desugar_module` alongside the existing `check_app_main_exclusivity`) validates `main`'s first clause has either zero parameters or exactly one parameter whose declared type is syntactically `Cap(IO)`, else a hard `Err.error` naming the found arity and showing both valid forms — this is a pure AST-level check (no type inference needed, since the annotation is already explicit) and doubles as the "reject wrong arity with a clear diagnostic" safety net for any signature this fix doesn't special-case. (2) `Eval.run_module`'s main-dispatch reads the entry module's own `main` `DFn` from `m.mod_decls` to get its arity directly (top-level functions bind to a `VBuiltin` recursion wrapper, not a bare `VClosure`, so arity can't be read off the bound value) and calls with `[VUnit]` when arity is 1, matching `root_cap`'s own `VUnit` representation, or `[]` when 0. (3) `Llvm_toplevel.emit_module`'s native/WASI `@main` emission looks up the real `main` `fn_def`'s parameter count; when it's 1, instead of changing `march_spawn_main`'s runtime ABI, it emits a thin private 0-arg adapter (`@march_main_entry_thunk`) that calls the real mangled main with a literal `ptr null` (the erased root capability) and passes the adapter's address to `march_spawn_main` — the WASM-island `_start` path (browser components, a different non-IO-capability entry convention) and the JS backend (which tolerates the arity mismatch naturally — extra/missing JS args are simply `undefined`, no crash) were both left untouched as out of scope. **Tests:** `test/test_eval.ml`'s new `main_entry_point` group — `main(cap : Cap(IO))` actually executes its body (verified via `Eval.test_capture_buf`, the existing internal stdout-capture hook, not OS-level fd redirection), 0-arity `main` is unregressed, and a wrong-arity `main(x : Int)` is rejected at desugar time (`has_errors`). New native compiled golden `test/native/main_cap_io.{march,expected}` + `test/dune` rule, manually verified to compile and run without a SIGBUS, printing the expected output — pins the codegen thunk. **`specs/lang/capabilities.md` needed no changes**: the pattern it already documents is now accurate; no other doc touched this pattern.
