Added `Json.get_field(kvs, key) : Option(JsonValue)` to `stdlib/json.march` (a linear scan over the raw `List((String, JsonValue))` an `Object(kvs)` match already bound, rather than re-matching the `JsonValue` wrapper per field via the existing `Json.get`), with its own test in `test/stdlib/test_json.march`. **Unknown fields are ignored for free (Decision 2), unchanged from before:** the decoder looks up only the fields it names and never enumerates `kvs`. **Byproduct fix, not this task's target:** the old nested-field fallback (`match from_json(raw) do Ok(v) -> v | Err(e) -> panic(e) end`) UNCONDITIONALLY PANICKED on any nested decode failure (Task 1's finding 2) — the new generator's equivalent is a normal `Err`, never a panic. **What this task explicitly did NOT fix, confirmed still present:** Task 1's finding 1, the `from_json` cross-type dispatch bug (every `derive Json for T` unconditionally rebinds the bare `from_json` name in the module env regardless of record/variant kind, `lib/eval/eval.ml` ~9674-9681) — a record's nested-field recursive `from_json(fv)` call still resolves to whichever type derived Json most recently in the WHOLE module (always the outer type itself, since it must derive after the field type it references), never the field's own type. A fresh minimal repro (`test/stdlib/test_json_typed.march`'s new `PathInner`/`PathOuter` pair) confirms: the failure is now a well-formed, path-bearing `Err` (no panic) but describes the OUTER type's own (wrong) view of the inner object, not the inner type's true failure — an isolated single-chain probe (no sibling types) independently confirmed at final review that `decode_error_under`'s composition is itself structurally correct and does fire; the misattribution is solely the pre-existing dispatch bug. `test/stdlib/test_derive_json.march` and `test_derive_json_multi.march`'s existing `Err(e) -> println("Error: " ++ e)`-shaped sites were migrated to `Json.decode_error_to_string(e)`; `test_island_bridges.march` needed no change (its generated bridge code pattern-matches errors with a wildcard, never destructuring the error payload as a `String`).
