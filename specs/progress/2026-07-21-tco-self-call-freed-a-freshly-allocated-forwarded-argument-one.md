- ✅ **TCO self-call freed a freshly-allocated forwarded argument one instruction before reusing it — FIXED (`lib/tir/llvm_emit.ml`, 2026-07-21).** `stdlib/toml.march`'s `string_to_int_digits` (a `String.split`/`String.join` accumulator recursion — `str_to_int(String.join(rest, ""), acc*10+digit_val(c))`) silently miscompiled: `Toml.get_int(_, "port")` on `"port = 9000"` returned `9` (first digit only) compiled while the interpreter (which never runs the Perceus/TCO TIR pipeline) got `9000` right — no crash, no error, just a wrong answer. **Root cause:** Perceus classifies `str_to_int`'s first parameter as borrowed (its only use is `string_split(s, "")`, itself a borrowed-position call), so a self-tail-call whose forwarded arg is dead afterward gets a caller-side post-call `EDecRC` — correct for real (non-TCO) recursion, where that DecRC only fires once the whole nested call has fully returned, by which point nothing below still needs the reference. The TCO loop-rewrite (`llvm_emit.ml`'s two self-TCO interception cases, ~line 680 `ELet`-wrapped and ~line 730 no-temp `ESeq`) ran that DecRC EAGERLY, immediately before storing the very same value into the parameter slot for the next iteration — freeing a freshly-allocated, uncompensated value (refcount 1, no prior `IncRC`, unlike a `Cons(_, t)`-style field extracted from a still-borrowed container, which DOES get a compensating `IncRC` and so survives the same eager-decrement pattern by accident) one instruction before it was reused, corrupting every iteration after the first. **Fix:** both TCO dec-chain executors now skip any `EDecRC`/`EAtomicDecRC`/`EIncRC`/`EAtomicIncRC` whose target variable is itself one of the tail-call's forwarded `args` — that reference is being handed off into the next iteration's slot, not released. Verified against a minimal standalone repro (no stdlib dependency) reproducing 9000→9 compiled/9000 interpreted, confirmed BROKEN pre-fix and FIXED post-fix by toggling `lib/tir/llvm_emit.ml` alone; the previously-working `Cons(_, t)`-style list-traversal TCO pattern (`test/native/*` and the codegen suite) is unaffected — confirmed via a second standalone repro. **Two other compiled-only bugs surfaced in the same docs audit (`task_54ced6d5` string_to_float/Option(Float) segfault, `task_eabe2334` Csv.read_all/each_row_with_header returns 0 rows) were checked and do NOT share this root cause** — `Csv.collect_loop`'s accumulator is forwarded via a constructor allocation (`Cons(fields, acc)`), not an `EApp` call, so it never reaches Perceus's borrowed-arg post-call-Dec logic at all (verified: a `Cons`-accumulator repro shaped like `collect_loop` was NOT broken pre-fix). Both were independently root-caused and fixed on `main` by a separate session while this branch was in flight — see the `string_to_float` and `Csv` niche-repr type-qualification entries elsewhere in this section; neither is a TCO/Perceus bug.
