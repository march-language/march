- ✅ **Named record types render by name in `pp_ty` (nominal-name recovery for LSP)** — Record types are structural in the typechecker (`TRecord of (string * ty) list`, no nominal name), so a declared `type R = { … }` used in an annotation or returned from a fn was rendered by `Tc.pp_ty` as `{ a : Int, b : Int }` instead of `R`. Fix is **rendering-only, zero unification-semantics change** (so no risk to the 82 `TRecord` construction/match sites across typecheck + TIR + codegen): a module-level index `_record_names` in `lib/typecheck/typecheck.ml` maps a record's *field-name signature* (sorted, comma-joined field names) → declared name, populated via `register_record_name` at all 5 `TDRecord` declaration sites (bare + qualified names). `pp_ty`'s `TRecord` case calls `recover_record_name` and prefers the name when unambiguous. Ambiguity (two distinct records with identical field sets) poisons the signature → falls back to structural `{ … }`; an unqualified name is preferred over a qualified alias of the same simple name. Downstream LSP wins (all route through `Tc.pp_ty`): hover now shows `Int -> R`, inlay hints show `R`, and the **"Add type annotation"** code action now offers named-record returns/bindings — the `annotatable_ty_str` guard in `lsp/lib/analysis.ml` (skips types containing `{`) now lets named records through automatically since they no longer render with braces (truly unnameable records still skipped). +3 LSP tests, 1 stale test updated (`test_no_annotation_for_record_return` → `test_annotation_for_named_record_return`). 1442 main-suite tests + 228 LSP tests pass. Caveat: the LSP's `AnnFnReturn` action inserts `-> T ` but March return syntax is `: T` — pre-existing bug, unrelated to this change (fails for `Int` too); flagged separately. With the correct `: R` form the recovered annotation parses cleanly.
