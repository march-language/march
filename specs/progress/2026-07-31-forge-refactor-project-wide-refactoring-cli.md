- ✅ **`forge refactor` — project-wide refactoring CLI** — A new parser-based refactoring engine (`lib/refactor/`, library `march_refactor`) plus `forge refactor` subcommands (`forge/lib/cmd_refactor.ml`, registered in `forge/bin/main.ml`). The engine discovers every `.march` file under the project, parses the raw AST (so it edits real constructs and never touches strings/comments), produces byte-offset edits applied in descending order, and **re-parses every edited file before writing** so a transform never leaves source that does not parse. A `site`-tagged name visitor (`iter_names`) powers `--kind fn|type|ctor|module|field|var|any` filtering. Commands: **rename** (`OLD NEW`, project-wide incl. qualified `Mod.x`; `--pattern` regex with `\1` backrefs; `--dry-run`), **fix** (turns lint naming findings — camelCase functions — into project-wide snake_case renames), **move** (`DECL DEST.march`, relocates a top-level declaration, creating `DEST` with a module wrapper if new), and **replace** (`'f($a,$b)' 'g($b,$a)'` structural codemod: parses pattern/template with `$metavariables`, matches call-shaped expressions, binds metavars to argument source and instantiates the template). All commands support `--dry-run`. Tests: `test/refactor/test_refactor.ml` — 7 cases (cross-file rename, string-safety, regex bulk, dry-run-writes-nothing, naming fix, move-to-new-file, call-shape codemod). Known v1 limitation: rename is name-based, not scope-resolved (a local shadowing the target is also renamed — use `--kind`). Plan: `specs/plans/2026-06-14-forge-refactor-plan.md`.
