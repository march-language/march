- ✅ **Fix parallel task result tagging + `task_await_unwrap` + scheduler LIFO livelock** — Three bugs causing wrong parallel results and deadlock in recursive parallel tasks. **(1) Result tagging** (`runtime/march_runtime.c`): `march_thunk_trampoline` now stores `(raw << 1) | 1` (tagged) in `task[3]` instead of raw i64; the `task_await` path goes through `mk_ok(result)` → `Ok(n)` pattern-match which loads the field as `ptr` (TVar→"ptr" in `llvm_ty`) and applies conditional `ashr 1` untag — without tagging, integers were halved. Added `march_task_await_value` that returns the tagged raw value directly (no `Ok` wrapper). **(2) `task_await_unwrap` codegen** (`lib/tir/llvm_emit.ml`): was reading field index 0 (proc ptr, offset 16) with no spin-wait; now calls `march_task_await_value`, coerces tagged ptr→i64 via conditional ashr, and for ptr-typed inner results applies bare `inttoptr`. **(3) Scheduler LIFO livelock** (`runtime/march_scheduler.c`): added `last_yielded` flag — when the previous task yielded (PROC_READY), try to steal from other workers before re-running it. Without this, all workers could spin on their local yielded tasks while the leaf tasks (at steal ends of other deques) never got scheduled. Verified: `par_fib(N, 3)` N=7–20 correct; prime counting `par(k)` matches sequential.
