- ✅ **`==` operator gave the WRONG answer (silent, not a crash) compiled on a `Newtype`-repr type with a heap payload (`lib/tir/llvm_eq.ml`, `test/test_codegen.ml`, `test/test_properties.ml`, 2026-07-04).** Found by the differential oracle (Task 4 / Phase 2b) while scoping the derived-method generators; distinct from the named-method fix `6cc676fc` (that fixed the NAMED `eq()`/`compare()` path via desugar span-uniquification + `emit_case` Newtype TVar-recovery; this is the `==` OPERATOR path). For `type W = W(String)` (Newtype repr — single ctor, single field — so the value IS its raw payload, no wrapper cell), compiled `W("x") == W("x")` returned `false` while the interpreter correctly gave `true`. **Root cause:** `ensure_adt_eq_fn` special-cased the Niche (Option-shaped) repr but never consulted `Repr.repr_of_ty` for `Newtype`, so a single-ctor single-field `TCon` fell to the generic Boxed ctor-table strategy, which reads a "ctor tag" at `payload_ptr + 8` and a "field" at `payload_ptr + 16`. For a Newtype the "payload_ptr" IS the raw payload (the String's own heap cell / a Boxed ADT cell), so those offsets land inside the payload's layout and the comparison is garbage. Confirmed by `--emit-llvm`: pre-fix `__march_eq_W` took the full boxed tag-load path; post-fix it is `%ok = call i64 @march_string_eq(ptr %a, ptr %b)  ret i64 %ok`. Affects any heap payload (verified: a Newtype over a Boxed 2-field ADT returned `true` for two DISTINCT values pre-fix); an Int/Bool-payload Newtype is a tagged scalar (`i64`, not `ptr`) and never enters `ensure_adt_eq_fn` (the `==`-lowering site gates on `ty_a = "ptr"`), so it was always correct. **Fix:** a `Repr.Newtype payload` arm in `ensure_adt_eq_fn` (checked before niche detection — the shapes are mutually exclusive, and `repr_of_ty` already routes Float-payload single-ctor types to Boxed) that compares the unwrapped operands directly per the payload's repr: `march_string_eq` for String, `fcmp` for a generic-Float payload, tagged-bits `icmp` for `payload_needs_tag` scalars, recursive `ensure_adt_eq_fn` (called on the raw operands) for a nested heap ADT/tuple/record, and `march_poly_eq` as the erased-`TVar`-payload fallback — no tag/field offset load. Generic newtypes get the concrete payload via the same `type_params` substitution the Boxed arm uses. Interpreter semantics unchanged. **Regression:** 4 compiled parity tests in `test/test_codegen.ml`'s `newtype_derived_method_crash` suite (String-payload `==`/`!=` — RED pre-fix; Int-payload control — green before and after; Boxed-ADT-payload `==` exercising the recursive arm — RED pre-fix; a generic `type Wrap(a) = Wrap(a)` at String+Int exercising the `type_params` substitution branch — the only test that drives a non-identity subst). Differential-oracle `gen_derived_method_newtype_string_module` (`test/test_properties.ml`), previously scoped to named `eq()`/`compare()` only to stay in the working subset, was widened to also exercise the `==` operator (oracle index 12 green, 50/50 matched interp = compiled). **Compiler builds clean; `newtype_derived_method_crash` 10/10 green; newtype-string oracle 50/50.**
