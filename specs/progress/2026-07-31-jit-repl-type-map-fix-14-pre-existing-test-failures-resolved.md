- ✅ **JIT REPL type_map fix — 14 pre-existing test failures resolved** — Root cause: `run_expr`/`run_decl`/`precompile_stdlib` in `lib/jit/repl_jit.ml` received empty `type_map` from tests, causing `ty_of_span` to return `TVar "_"` for all variable references during TIR lowering. With `TVar "_"`, `build_subst` in mono returned `[]` for polymorphic calls (e.g., `List.reverse` inside `range_step`), preventing specialization. The unspecialized function was absent from `tm_fns` → not in `top_level` → defun treated it as a free variable → spurious closure capture → invalid LLVM IR (load from non-existent alloca) → clang error. Fix: `run_expr`, `run_decl`, and `precompile_stdlib` now compute `type_map` internally via `March_typecheck.Typecheck.check_module m` (ignoring the passed `~type_map`), ensuring all expression spans have proper types before TIR lowering. Fixed 10 `repl_jit_regression` + 3 `repl_compiler_parity` + 1 `jit_eval_simple_expr` boolean-display failure = 14 tests. Also reverted debug code from `compile_fragment` that copied failing .ll files to `/tmp/march_debug/`.
