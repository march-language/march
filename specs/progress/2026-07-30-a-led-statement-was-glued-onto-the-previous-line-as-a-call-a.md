Codegen was faithful: `--dump-tir` at the `tir-lower` stage already showed the callee's body as `a()`. Inside a block the token filter swallows newlines, so `let _ = a` followed by a line holding only `()` reached menhir as `a` `(` `)` adjacent and took the call rule — the *parameter was being invoked*. The interpreter confirmed it independently (passing `fn -> IO.puts("CALLED")` printed `CALLED`; passing a String raised "applied non-function value"), which is what collapsed a two-fault codegen theory into a one-line parse fact. The reported trigger matrix follows directly: the discard is what leaves a value-ending token at the end of one line and the literal `()` is what puts a `(` at the start of the next, so removing either fixes it, a `None`/`0`/`IO.puts(…)` tail has no leading `(`, and a zero-arg callee has no discard. **Not** cross-module (a same-module callee reproduces identically) and **not** an RC bug. **Fix:** the newline-separates-statements rule was already specified for `f(1)`⏎`(g(2))` (grammar §7.3, witness `parse/p24`) but was enforced only for the curried-call `)`⏎`(` shape — the *classification* of the paren ignored the newline.
