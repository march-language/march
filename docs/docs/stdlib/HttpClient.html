HttpClient

HttpClient: high-level composable HTTP client with step pipeline.

This is Layer 3 of March's HTTP library. It provides a Req-style three-phase pipeline (request steps, response steps, error steps) built on top of HttpTransport.

Usage: let client = HttpClient.new_client() |> HttpClient.add_request_step("auth", HttpClient.Steps.bearer_auth("my-token")) |> HttpClient.with_redirects(5) let resp = HttpClient.get(client, "http://api.example.com/users")

fnhandle_redirectshandle_redirects(req, resp, max, count)#

Follow redirects for resp, the answer to req. Returns Ok(resp) unchanged when max == 0, when resp is not a 3xx, or when it has no Location header; Err(TooManyRedirects(count)) once count >= max. Otherwise re-issues the request as a body-less GET (whatever the original method and redirect code) over a new connection and recurses. An absolute Location that crosses origins drops credential headers; a relative one keeps all headers and replaces only the path.

Examples

march> let req = Result.unwrap(Http.get("http://example.com/users?page=2"))
march> let sreq = Http.set_body(req, "")
march> HttpClient.handle_redirects(sreq, Http.Response(Http.Status(302), [Http.Header("Location", "/x")], ""), 2, 2)
Err(TooManyRedirects(2))
march> let req = Result.unwrap(Http.get("http://example.com/users?page=2"))
march> let sreq = Http.set_body(req, "")
march> HttpClient.handle_redirects(sreq, Http.Response(Http.Status(302), [], ""), 3, 0) |> Result.map(fn r -> Http.response_status_code(r))
Ok(302)

fnrunrun(client, req)#

Run a request through the client's full step pipeline:

  1. Run request steps left-to-right; the first Err short-circuits.
  2. Send with HttpTransport.request (a new connection per attempt),
retrying up to `max_retries` extra times on transport errors
(the configured backoff is currently not applied between attempts).
  1. Follow redirects if with_redirects set a non-zero limit.
  2. Run response steps left-to-right.
  3. Any Err from steps 1-4 is fed to the error steps in order; the first
`Recover(resp)` turns it into `Ok(resp)`, otherwise the last error is
returned. Transport errors arrive wrapped in `HttpTransportError`.

Examples

let req = Result.unwrap(Http.get("http://api.example.com/users"))
match HttpClient.run(client, Http.set_body(req, "")) do
  Ok(resp) -> Http.response_body(resp)
  Err(e) -> "request failed"
end
fnrun_error_stepsrun_error_steps(steps, req, err)#

Offer err to each ErrorStepEntry in order. The first Recover(resp) wins and gives Ok(resp); a Fail(e2) replaces the error for the next step. With no step recovering, returns Err of the last error.

Examples

march> let req = Result.unwrap(Http.get("http://example.com/users?page=2"))
march> HttpClient.run_error_steps([], req, HttpClient.TooManyRedirects(3))
Err(TooManyRedirects(3))
march> let req = Result.unwrap(Http.get("http://example.com/users?page=2"))
march> HttpClient.run_error_steps([HttpClient.ErrorStepEntry("x", fn (_, _) -> HttpClient.Recover(42))], req, HttpClient.TooManyRedirects(3))
Ok(42)
fnrun_on_fdrun_on_fd(fd, req_steps, resp_steps, err_steps, max_redir, max_retries, req)#

Run req through the pipeline on an already-open connection fd. This is the engine behind the do_request callback of with_connection.

Same phases as run, except that the request is sent with transport_keepalive(fd, req, max_retries + 1): on a send/receive failure the connection is closed and a fresh one opened. Redirects still go over new connections (handle_redirects). Returns Ok(response) or the result of the error steps.

fnstep_base_urlstep_base_url(base)#

Returns a request step that re-targets a request at base ++ path: the scheme, host, port and path come from parsing that string, while the method, query, headers and body are kept from the request. Fails with StepError("step_base_url", ...) if the combined URL does not parse.

Examples

march> let req = Result.unwrap(Http.get("http://example.com/users?page=2"))
march> let base = HttpClient.step_base_url("https://api.example.com:8443/v1")

march> let req = Result.unwrap(Http.get("http://example.com/users?page=2"))
march> let bad = HttpClient.step_base_url("nope")
march> Result.is_err(bad(req))
true

fnstream_getstream_get(client, url, on_chunk)#

Stream a GET response body. Calls on_chunk(chunk_string) for each chunk as it arrives over the wire. Returns Ok((status, headers, ())); the values returned by on_chunk are discarded (HttpTransport streams for side effects only).

Only the client's request steps are applied; response steps, error steps, redirects and retries are not. An invalid URL gives Err(StepError("url", ...)); a failing request step's Err is returned as is.

Examples

HttpClient.stream_get(client, "http://example.com/bigfile", fn chunk ->
  println("got " ++ int_to_string(string_length(chunk)) ++ " bytes"))

march> HttpClient.stream_get(HttpClient.new_client(), "bad", fn c -> c)
Err(StepError("url", "invalid url: bad"))
fntransport_keepalivetransport_keepalive(fd, req, retries_left)#

Send req on the open connection fd. Returns Ok((fd, resp)) on success. On failure, closes fd and, while retries_left > 0, reconnects and tries again (each reconnect consumes two from retries_left); otherwise returns Err(Closed), discarding the original transport error. After a reconnect the returned fd is the new one.

fntransport_with_retrytransport_with_retry(req, retries_left)#

Send req with HttpTransport.request (a fresh connection each time), retrying immediately up to retries_left more times on any transport error. Returns the last error if every attempt fails.

fnwith_connectionwith_connection(client, url, callback)#

Open a keep-alive connection and run a function with it. The function receives a do_request callback that sends requests on the shared connection. Connection is closed when done.

Returns Ok(result) where result is whatever the callback returned (each do_request(req) itself returns Result(Response, HttpError)), Err(StepError("url", ...)) if url does not parse, or Err(HttpTransportError(e)) if the connection cannot be opened. Only the scheme, host and port of url are used to connect; each request carries its own path. If the callback panics the connection is not closed.

Examples

HttpClient.with_connection(client, "http://api.example.com", fn do_request ->
  let users = Result.unwrap(Http.get("http://api.example.com/users"))
  let posts = Result.unwrap(Http.get("http://api.example.com/posts"))
  let r1 = do_request(Http.set_body(users, ""))
  let r2 = do_request(Http.set_body(posts, ""))
  (r1, r2))

march> HttpClient.with_connection(HttpClient.new_client(), "bad", fn d -> 1)
Err(StepError("url", "invalid url: bad"))
