ClusterNode

ClusterNode: one running cluster node -- it joins from seed addresses, runs SWIM continuously over one persistent authenticated connection pair per peer, and tells subscribers when a peer is suspected, dead or back.

Design: specs/progress/2026-09-18-cluster-node-service.md. The parts it assembles were already here (Membership/Swim/SwimDriver, NetKernel's handshake, PeerReader, NodeQueue); what was missing was a node that stays up and uses them together.

Shape: a PURE core (core_*, CnState -> ... -> (CnState, List(CnEffect)), unit-tested under the eval harness, which cannot run sockets) inside ONE actor (ClusterNodeActor) that owns the state and performs the effects, plus a few tasks around it:

acceptor   blocking tcp_accept loop; each connection is handshaked in its
           own task (deadline-bounded) and reported as `Accepted`
dialer     one task per attempt: connect_timeout + handshake, control
           then data, reported as `Dialed` / `DialFailed`
readers    one per connection (PeerReader.serve): control frames go to
           the actor as `CtlFrame`; end of stream is `LinkClosed(id, gen)`
ticker     `Tick` every tick_ms; the SWIM period, the redial backoff and
           the stale-dial expiry all run off it
(the readers, the ticker and the acceptor move to a new code epoch
after a hot deploy: see "moving to a new code epoch" below)
CtlWriter  one per peer: EVERY write to a control socket goes through it
           (two writers on one socket interleave frames)

Connections. One control + one data connection per peer, reused by everything. Two nodes dialling each other at once each end up with two pairs; both keep the pair dialled by the LOWER node_id (a symmetric rule, no message needed). Each pair has a generation; a close from a replaced generation is ignored. A closed connection is a HINT: the member goes Suspect and is redialled at once; a redial REFUSED (nothing listening) is definite and makes it Dead. When SWIM declares a node Dead the node shuts both its connections. Healing: SWIM never probes a Dead member, so the node redials every Dead member's advertised address on a backoff; when a redial lands, MEMBERS_SYNC in both directions lets each side refute what the other believed.

Names (the registry replica). The node holds a GlobalRegistry replica: a local register is pushed at once to every linked peer (REGISTRY_SYNC_RESP with the changed leaves), every new link exchanges the whole registry, and a 30 s anti-entropy round (REGISTRY_SYNC_REQ with the root hash) repairs what a push missed. A registration's clock is the name's current clock with our slot bumped, so a takeover after seeing a binding is causally newer and never falls to the tiebreak. lookup sees only VISIBLE bindings: one whose holder is Dead here, or whose holder has restarted since (a stale creation), is hidden -- not tombstoned; it reappears if the holder rejoins with the same creation. The owner tombstones its own stale-creation bindings when it learns of them. A global name is AP, not a lock: during a partition both sides can hold one; after the heal the CRDT picks one winner everywhere, and the loser's watchers get Lost.

Everything the node knows about members and names is also mirrored into Vaults (members, addr_of, lookup), so readers need no round trip to the actor.

The node is a capability: start(io, cfg) returns a Cap(ClusterNode.Live) whose dictionary (ClusterOps) every public operation calls through, and a test can attach(io, ops) its own (D35; see "the capability" below).

A running node is a Cap(ClusterNode.Live) (D35 of specs/plans/2026-09-21-distributed-authority-and-deploys-plan.md), on the model of Cap(Session.Live): start mints it over the node's CnHandle record with the real dictionary (ops_of), and every public operation below dispatches through cap_dict. One field per operation; global_pid and await_members are derived (from node_id/creation and from members). node_id is this node's id; next_id(key) is a per-node counter (SessionAP numbers its sessions with it).

fnconfigconfig(name : String, listen_port : Int, advertise : String, seeds : List(String),#

A configuration with the defaults: SWIM period 1 s, ack timeout 500 ms, suspect timeout 3 s, 2 indirect helpers, tick 100 ms, redial backoff

  1. [advertise] ""

means 127.0.0.1:<listen_port>. The SWIM timings trade detection speed for false suspicions on a loaded host (a 300 ms ack timeout suspected healthy peers on a busy CI runner); override swim / period_ms with a record update to tune them. The environment can move the three SWIM defaults without a rebuild: MARCH_SWIM_PERIOD_MS, MARCH_SWIM_ACK_MS and MARCH_SWIM_SUSPECT_MS (each a positive integer; anything else keeps the default). A record update still wins over them.

A name unregistered anywhere in the cluster leaves a tombstone in every replica of the registry; it is dropped tombstone_grace_ms after it was first seen (default 3 hours, MARCH_REGISTRY_TOMBSTONE_GRACE_MS). Keep it well above the longest partition the cluster should heal from: a partition longer than that can bring back a binding whose holder is gone, which the node service then hides and its owner unregisters again.

fnconfig_from_envconfig_from_env() : Result(CnConfig, String)#

Configuration from the environment: MARCH_NODE_NAME, MARCH_NODE_PORT, MARCH_NODE_ADVERTISE (default 127.0.0.1:<port>), MARCH_CLUSTER_NODES (seeds, host:port,...), MARCH_CLUSTER_SECRET, MARCH_NODE_CREATION (default: the current time in ms, which grows across restarts on one host).

Certificate mode: with MARCH_NODE_CERT set, the node authenticates with a certificate instead of the secret, and MARCH_NODE_KEY and MARCH_CLUSTER_OPERATOR_PUBKEY must be set too (each may name a file holding the value). MARCH_CLUSTER_SECRET is then ignored: both set means certificate mode. Without MARCH_NODE_CERT the node runs in shared-secret mode, as before (MARCH_NODE_KEY alone is an error, not a silent fallback). MARCH_CLUSTER_REVOCATIONS (certificate mode; tokens or a file of them) seeds the node's revocation list. When MARCH_NODE_CERT names a file, the node re-reads it (and MARCH_NODE_KEY's file) every MARCH_NODE_CERT_POLL_MS (default 10000) and replaces its certificate live when they change (replace_cert; cert_files).

fncontrol_tagscontrol_tags() : List(Int) do [0, 1, 2, 3, 5, 6, 7, 8, 10, 11, 12, 13, 14, 15, 16] end#

fnregisterregister(c : Cap(ClusterNode.Live), name : String, pid) : Result((), RegisterError)#

Register [name] -> [pid] (a process on this node) cluster-wide. fnreplace_certreplace_cert(c : Cap(ClusterNode.Live), cert_text : String, key_hex : String) : Result(NodeCert.Cert, String)#

Replace this node's certificate while it runs (certificate mode; distributed-deploys step 12b). [cert_text] is the new certificate in its text form (forge cluster cert's .cert file); [key_hex] is its node key (hex, as in MARCH_NODE_KEY), or "" to keep the current key (a renewal made with forge cluster cert --node-key). It must verify under the operator key now, name this node and that key, and not be revoked; otherwise Err, and the certificate in use is kept. The certificate and key already in use are Ok and change nothing (no update is sent, no event reported).

New handshakes present it at once. Links already up are not redialled: each linked peer is sent the new certificate over the link, with a proof that this node holds its key, checks it as a handshake would, and holds it for that link from then on -- so the link, and every session on it, stays up past the old certificate's expiry. A peer too old to know the update drops the link when the old certificate expires, and the redial then handshakes under the new one. Reported to on_security_event as CertReplaced (or CertRefused). config_from_env nodes also do this on their own when the MARCH_NODE_CERT file changes (see CnConfig).
