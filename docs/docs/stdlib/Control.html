Control

Control: the pure core of the in-cluster control plane (distributed-deploys build step 12a). Design: specs/plans/2026-09-28-dd-step12-control-plane-design.md, sections 3, 4, 7 and 8, decisions D37-D41.

The control plane holds no root keys (D37). forge writes and signs a RELEASE: a sequence number, the digest of its parent, the environment, the topology digest, the builds it ships, and an ordered list of steps with host selectors and gates. The leader only executes it:

  • parse / serialize read and write the release's text form (section 4);
  `check` validates it, `digest` / `verify` / `sign` cover its identity and
  its operator signature, and `accept` is the leader's compare-and-set on
  `parent`.
* `pass` is the executor, level-triggered and pure: its inputs are the
  newest release held, the membership (which node is in which pool), what
  each Agent last reported, the nodes with an order outstanding, and the
  time. It finds the first step whose selected nodes do not yet report the
  step's end state and orders the next nodes the step allows. Nothing else
  is carried between passes, so a new leader resumes a half-finished
  rollout from observation alone. A failed step or gate HALTS the release;
  the executor never rolls back (a rollback is a new release).
* `Leader` wraps `pass` in the few facts a leader keeps in memory: the
  reports (`Obs`, with the leader-clock time each node became healthy, so a
  gate window restarts on a new leader, section 4), orders in flight, and a
  sticky halt.
* `agent_apply` is the Agent's side of one `StepOrder`, over an `AgentOps`
  dictionary: the node's reload server and CAS are reached through it. Until
  the `reload_request` builtin exists (design section 6) the dictionary is
  the seam tests and the real Agent plug into.
* The payloads of the control protocols (section 7): `AgentReport`,
  `StepOrder`, `StepResult`, `CtlChunk`, and the `ControlOps` dictionary a
  leader's `Ctl` session is driven by. The `Ctl` and `CtlFetch`
  declarations themselves live in test/session/control_peers.march for
  now. A protocol may live in a stdlib module since 2026-10-03
  (specs/progress/2026-10-03-endpoints-protocol-in-nested-module.md); the
  move is specs/todos/2026-09-28-dd-step12a-control-wiring.md.

The leader itself is count = 1 placement over SWIM with no strict lease (D40): two leaders during a partition each drive their side toward the newest release they hold, and nodes refuse anything older (12-pre).

One rollout step. pools is the pools it targets (["*"] for every pool), batch how many of its nodes may have an order outstanding at once (0: no limit).

A build the release ships: the base binary's hash and the patch manifest's hash.

typeCtlLineCtlLine = { step : Int, text : String }#

An operator-signed request line the Agent relays to its node's reload server for a step (the SEQ ... wrapper of 12-pre). The node verifies it; the control plane only carries it.

typeCtlCertCtlCert = { node : String, cert : String }#

A certificate item (step 12b): an operator-signed node certificate, in NodeCert's text form, for the node named [node]. The release is signed by the deploy key and the certificate by the operator key, and the node checks both (D37: a compromised leader can forge neither). The control plane issues nothing (D39): forge cluster cert --deliver writes these.

typeCtlReleaseCtlRelease = {#

A release (design section 4). signature is the operator's ed25519 signature, hex, over signed_text; the document writes it as sig.

typeCtlMemberCtlMember = { node : String, pools : List(String) }#

A node in the membership, with the pools it runs.

typeCtlVersionCtlVersion = { build : String, manifest : String }#

A build a node runs, by the manifest hash it has active.

typeCtlFailureCtlFailure = { seq : Int, step : Int, why : String }#

The last step a node failed: the release, the step, and why (the reload server's answer).

typeAgentReportAgentReport = {#

What an Agent reports (design section 6): the newest release seq the node holds, the builds it runs (versions_text), its topology digest, the highest epoch it has drained, whether it is healthy, and its last failed step (failed_seq 0: none). detail is the node's raw facts as text (its pins, its hot slots, its status file: offers, live sessions per protocol fingerprint, drain progress), for forge to show; the executor never reads it. pools is the pools the node runs, space-separated (the leader's membership: the executor needs node -> pools). A version whose build is * is an artifact the node runs that it cannot name a build for (the reload server knows patch artifacts, not the release's build names); reports_state accepts it for any build. certs is the node's certificate state (certs_text): the serial of the certificate it presents and the id of every revocation it knows, what a do:certs step is done by (step 12b).

typeStepOrderStepOrder = {#

An order for one node to take one step (design section 7): the release and step, the action (show_action), the end state it must report (want: a manifest hash, the topology digest, or the drain epoch), the artifact hashes it needs (space-separated), and the signed lines to relay (newline-separated). Hashes, never bytes.

typeStepResultStepResult = { seq : Int, step : Int, node : String, ok : Bool, detail : String }#

The Agent's answer to a StepOrder.

typeCtlObsCtlObs = { report : AgentReport, healthy_since : Option(Int) }#

A leader's observation of a node: its last report, and the leader-clock time since which it has been healthy in that state.

typeCtlDecisionCtlDecision = RolloutApply(Int, List(StepOrder)) | RolloutWait(Int, String) | RolloutHalted(Int, String, String) | RolloutComplete | RolloutBehind(Int)#

One pass's verdict.

Apply(step, orders)     step `step` is the first not done; send these
                        orders (possibly none, when every remaining node
                        already has one in flight or the batch is full).
Wait(step, why)         step `step` is done on its nodes and its gate
                        has not passed yet.
Halted(step, node, why) the release stops here and is reported. The
                        executor never rolls back.
Complete                every step is done and every gate passed.
Behind(seq)             a node holds a newer release than this one; the
                        leader must fetch it before executing anything.
typeCtlLeaderCtlLeader = { release : Option(CtlRelease), obs : List(CtlObs), inflight : List(String), halted : Option(CtlDecision) }#

What a leader holds: the newest release, its observations, the nodes with an order outstanding, and a halt, which sticks for the release. None of it is handed over: a new leader starts from leader_new(), the newest release it can find, and the agents' next reports.

typeAgentOpsAgentOps = { report : () -> AgentReport, has : String -> Bool, request : String -> String }#

How an Agent reaches its node. report reads the node's state, has answers CAS_CHECK for a hash, and request runs one signed request line through the reload server and returns its answer (OK ... or ERR ...). The real Agent builds this over the reload_request builtin (design section 6, not built yet); tests build it over a simulated node.

typeCertOpsCertOps = {#

How an Agent reaches its node's certificate state. [name] is this node's name, [deploy_key] the deploy public key releases verify under, [serial] the serial of the certificate it presents now ("" when none), [replace] takes a certificate's text form (ClusterNode.replace_cert, keeping the node's key) and [revoke] a revocation token (ClusterNode.revoke, which gossips it on). [floor] is the newest release seq this node has taken anything from: an older release is refused, so a replayed release cannot put back a certificate a later one replaced.

typeCtlChunkCtlChunk = { offset : Int, data : String, last : Bool }#

A chunk of an artifact: its offset, the bytes as hex, and whether it is the last.

typeCtlNextCtlNext = NextOrder(StepOrder) | NextPoll | NextBye(String)#

What to do next in one agent's Ctl session: send an order, poll for a report, or end the session.

typeControlOpsControlOps = { report : AgentReport -> (), stepped : StepResult -> (), next : String -> CtlNext, head : () -> Int }#

What the leader's side of one agent's session asks of the executor. report takes a report (the hello, and every poll's answer), stepped an order's result, next(node) says what to do next with that node's session, and head() is the newest release seq the leader holds.

fnacceptaccept(head : Option(CtlRelease), r : CtlRelease) : Result((), String)#

The leader's compare-and-set (design section 9): may [r] replace [head], the newest release held? The first release is accepted whatever its parent. The held release itself is accepted again (a retry). Otherwise r.seq must be higher and r.parent must be digest(head): the parent chain is enforced by the one writer that sees every release (section 5).

fnagent_applyagent_apply(ops : AgentOps, o : StepOrder) : StepResult do agent_apply_ticked(ops, o, 200) end#

RolloutApply one order on this node. Idempotent: a node that already reports the order's end state answers ok without touching the reload server, so an order a new leader sends again is harmless. Missing artifacts or a refused line answer not-ok with the reason, which halts the release. A topology step the reload server took is given a few placement ticks for the node to report it (agent_apply_within).

fnagent_apply_certsagent_apply_certs(c : CertOps, o : StepOrder) : StepResult#

Apply a do:certs order on this node (step 12b): check the release it carries (the deploy key's signature, that it is the release the order names, not older than one this node took from), then take the certificate item for THIS node, if there is one (apply_cert; items for other nodes are not this node's to apply), then every revocation (ClusterNode.revoke keeps a known one once, so a revocation already gossiped here is a no-op). Idempotent: a certificate already in use and a revocation already known change nothing. Any refusal answers not-ok with the reason, which halts the release.

fnpasspass(r : CtlRelease, members : List(CtlMember), obs : List(CtlObs), inflight : List(String), now : Int) : CtlDecision#

The executor's pass (design section 4), a pure function of the release, the membership, the observations, the nodes with an order in flight, and the leader's clock. Steps run strictly in order: a step's orders go out only once every earlier step is done on its nodes and its gate has passed, and a node is ordered only while it does not report the step's end state and has no order in flight. So no step is skipped and none is applied twice.

[certs] is the node's certificate state (certs_text). has is the artifact's presence in the CAS (a base: in the release is informational: the base image is not an artifact).

fnreload_reportreload_report(name : String, pools : String, status : String, applied : Bool, failure : String, certs : String) : AgentReport#
