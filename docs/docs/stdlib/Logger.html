Logger

Logger module: structured logging with levels, scoped context, and pluggable appenders.

Log levels (ascending severity): Debug < Info < Warn < Error. The global level filter is set with set_level/1; messages below the current level are silently discarded.

v2 adds rich field values and scoped context:

Logger.with_field("user_id", Logger.i(42))
Logger.with_field("ms",      Logger.f(12.5))
Logger.info("request done")

The structured fields propagate to every subsequent log call until the field stack is popped. Use with_scope for automatic cleanup:

Logger.with_scope([Logger.LogField("request_id", Logger.s("abc"))],
  fn _ -> handle_request())

With no appender registered, output goes to stderr in the format: [LEVEL] message {key=value, key2=value2}

v1 API (still supported): Logger.set_level(Logger.Info) Logger.with_context("request_id", "abc123") -- equivalent to with_field("...", LStr(...)) Logger.info("handling request") Logger.warn("slow query") Logger.error("db connection lost") Logger.log_with(Logger.Info, "user signed in", [("user", "alice")])

Logging calls write output, so their docs show plain code; the level helpers, value constructors, entry accessors and formatters are pure and carry REPL examples.

Types

typeLevelLevel = Debug | Info | Warn | Error#
typeLogValueLogValue =#

Rich value type so structured formatters (JSON, logfmt) preserve the original type instead of stringifying everything.

typeLogFieldLogField = LogField(String, LogValue)#
typeLogEntryLogEntry = LogEntry(Level, String, Int, String, List(LogField))#

A log entry built and passed to every registered appender. Fields are in stack order — most recently pushed at the head.

typeAppenderAppender = Appender(String, LogEntry -> Unit)#

An appender consumes log entries and writes them somewhere. The string is a name used by remove_appender. Multiple appenders fire newest registration first (re-registering a name moves it to the front).

typeAppenderCallAppenderCall = AppenderCall(String, String, Int, String, List(LogField))#

What the runtime hands a registered callback: the entry with its level still spelled as the dispatched string ("INFO", ...). Both backends pass this, and deliver builds the LogEntry in March, because the compiled runtime cannot build a Level value itself: the compiler picks its constructor tags, and they are not 0..3 when another type is also named Level. The runtime builds this cell with tag 0, which holds only while no other type is named AppenderCall (a colliding name gets global tags). It is a constructor rather than a tuple because destructuring a tuple and moving its fields on leaks them compiled (specs/todos/2026-09-28-compiled-tuple-destructure-leaks-moved-fields.md).

fnformat_jsonformat_json(e : LogEntry) : String#

Single-line JSON formatter, OpenTelemetry-friendly.

Example output: {"ts":1681400000000,"level":"info","msg":"login","src":"MyApp", "trace_id":"…","span_id":"…","attributes":{"user_id":42}}

The reserved field names trace_id, span_id, and parent_span_id appear at the top level of the JSON object so log shippers that speak OTLP can pluck them directly; everything else lands in the attributes sub-object (omitted when empty). Fields are de-duplicated by key, keeping the most recent push (the first occurrence); src is included only when the source is non-empty.

Examples

march> Logger.format_json(Logger.LogEntry(Logger.Info, "login", 1000, "", [Logger.LogField("trace_id", Logger.s("t1")), Logger.LogField("n", Logger.i(2)), Logger.LogField("n", Logger.i(1))]))
"{\"ts\":1000,\"level\":\"info\",\"msg\":\"login\",\"trace_id\":\"t1\",\"attributes\":{\"n\":2}}"
fnformat_logfmtformat_logfmt(e : LogEntry) : String#

logfmt-style formatter (Heroku / Grafana convention): level=info ts=1681400000000 msg="hello world" k=v The message is always quoted (inner " escaped as \"); src= is added when the source is non-empty; string field values are quoted only when they contain a space or a ".

Examples

march> Logger.format_logfmt(Logger.LogEntry(Logger.Warn, "slow query", 1000, "Db", [Logger.LogField("user", Logger.s("ann smith")), Logger.LogField("ms", Logger.i(42))]))
"level=warn ts=1000 msg=\"slow query\" src=Db user=\"ann smith\" ms=42"
fnformat_textformat_text(e : LogEntry) : String#

Default text formatter. Mirrors the v1 output: [LEVEL] message {key=value, key2=value2} Fields appear in stack order, duplicates included; string values are not quoted. The braces are omitted when there are no fields; the timestamp and source are not shown.

Examples

march> Logger.format_text(Logger.LogEntry(Logger.Info, "login ok", 0, "", [Logger.LogField("user", Logger.s("ann")), Logger.LogField("n", Logger.i(3))]))
"[INFO] login ok {user=ann, n=3}"
march> Logger.format_text(Logger.LogEntry(Logger.Error, "boom", 0, "", []))
"[ERROR] boom"
