Topology

Topology: the runtime side of a topology app (build step 3 of the distributed-deploys plan, specs/plans/2026-09-21-distributed-authority-and-deploys-plan.md, sections 4.1, 4.2 and II.3 / II.6 "Placement at runtime").

In a topology app main is generated (march --topology, lib/desugar/desugar_topology.ml). It starts the ClusterNode, runs each pool's hook under hook (a watchdog: a hook must return promptly), and hands this module one Role per served role. From then on the NODE owns its offers (D16): place opens the offers the topology places on it and re-evaluates on every membership change; drain_on_signal closes them on SIGTERM/SIGINT and lets running sessions finish; supervise_offers re-offers a role whose offer (or hosting actor) died, and keeps main alive.

Placement rules (4.2), evaluated by every node for itself, with no control plane: everywhere() offered on every node that serves the role (D18); on_label(label) offered when this node's labels (MARCH_NODE_LABELS, a comma-separated list set by the launcher) include it; count(n) offered on n of the eligible live nodes, chosen by rendezvous hashing: every node ranks the candidates by hash(role, node_id) and offers when it is in the top n (D19); count_on(l, n) count(n) among the nodes carrying label l. "Eligible" for a Count role means: a live member (or this node) that serves the role and carries its label. Other nodes' pools and labels are not in the membership table, so each eligible node registers a cluster name, topo:<role>/<node_id>, and the ranking reads those names back; a dead node's names become invisible with its membership. A node that REJOINS counts only after MARCH_PLACEMENT_SETTLE_MS (default 15000), so a flapping node does not pull a role back and forth (hysteresis). count(1) is not a lock: during a partition each side may offer, as with any global name.

The hash is SHA-256 (Crypto.sha256), not the plan's BLAKE3: the runtime's BLAKE3 is not exposed to March code, and the placement only needs a hash that every node computes identically.

Losing a role is a drain, not a cut: SessionNode.close_offer refuses new invitations and lets the sessions already running finish.

Re-reading the topology (D16, build step 8). place installs a SIGHUP watcher: on SIGHUP the node re-reads MARCH_TOPOLOGY_FILE (the digest, .forge/topology.json, which the reconciler rewrites before signalling) and applies what changed for the roles its build contains: a new placement, a role this process's pools no longer serve (its offer is closed: a drain), a new capacity (the offer is closed and reopened at the new size). The next evaluation opens and closes offers as for a membership change; nothing restarts. A role newly served that this build has no code for is reported, not offered: that needs a rebuild. The node reports what it applied and the offers it holds to MARCH_TOPOLOGY_STATUS (forge topology status reads it). The reconciler never opens or closes an offer itself.

typeTopoPlacementTopoPlacement = PlaceEverywhere | PlaceOn(String) | PlaceCount(Int) | PlaceCountOn(String, Int) | PlaceNowhere#

Constructor names are prefixed: a bare Count collided with DataFrame's nullary Count aggregate in user code that writes it unqualified. Type names are prefixed too (TopoPlacement, TopoRole, ...): March has one global type namespace, and a bare Placement broke a user program that declares its own (test/session/cluster_placement). PlaceNowhere: not served by this process's pools (after a reload moved the role to another pool).

[capacity]: the size it was opened at (0: fixed by the build). [stop]: what ends whatever served it once its closed offer has drained (a hosted role's actor exits then, 6.1; a function role has nothing to stop).

fnactor_roleactor_role(name : String, place : TopoPlacement, mk : () -> Pid(a),#

A role bound to an actor (actor = "M.A" in [roles], D23): one actor per offer, spawned by [mk] (the generated fn () -> spawn(M.A, env)) and handed to [open] (the generated <P>_Run.offer_hosted_<R> call whose start, deliver and cancel callbacks forward to it). fndrain_on_signaldrain_on_signal(node : Cap(ClusterNode.Live), soft_ms : Int, hard_ms : Int) : ()#

On SIGTERM or SIGINT: close every offer of [node] (new invitations are refused) and refuse every new initiate on it (Err(Left("draining"))), drain every code epoch the process runs (running sessions end at their next loop boundary, D27, and actors take the epoch drain's deadlines), then exit 0 once no session is running. At [soft_ms] a drain still waiting is reported; at [hard_ms] the process exits 1, naming how many sessions it cut. A second signal escapes the watcher and stops the process at once.

fnmay_openmay_open(p : TopoPlacement, others : Int, now : Int, started : Int, synced : Bool,#

Whether this node may OPEN ranked role [p] it now ranks for (it is not offering it yet), at [now]: the settle rule its peers apply to it, applied by the node itself. A node that started at [started] and has not yet merged a peer's registry ([synced] false) knows no other node's marker, so it opens nothing ranked until it has, or until [settle_ms] have passed (seeds unreachable: a lone node still takes its roles). fnplaceplace(node : Cap(ClusterNode.Live), roles : List(TopoRole)) : ()#

Open the offers the topology places on [node], one per entry of [roles], and keep them placed: a task re-evaluates every MARCH_PLACEMENT_TICK_MS (default 200 ms) against the current membership, opening a role this node now ranks for and closing (draining) one it no longer does. Membership events are recorded as they arrive; a node that rejoins counts after the settling period. This node applies that period to itself too (may_open): it opens no ranked role before its first registry sync (bounded by MARCH_PLACEMENT_SETTLE_MS), and while a peer counts it as rejoined it leaves a ranked role to the nodes already offering it. Returns once the first evaluation has opened the offers it may open now (a ranked one held back opens on a later tick).

fnreofferreoffer(node : Cap(ClusterNode.Live)) : () do reoffer_with(node, state_of(node)) end#

Re-open each of [node]'s open offers with the code now running (distributed-deploys build step 9): an offer whose protocol fingerprint changed is opened again under the new one (a hosted role with a fresh actor) and the old offer is closed; its sessions finish on the old version and a hosting actor exits once they have (6.1). An offer whose fingerprint did not change stays as it is (the new offer's name is already taken). The placement loop runs this itself after a deploy; call it directly only from a test.
