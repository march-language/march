Http

Http module: pure HTTP protocol types, constructors, and transforms.

This is Layer 1 of March's HTTP library. It contains no I/O — only data types and functions for building and inspecting HTTP requests and responses. Libraries that work with HTTP types depend on this alone.

Types

typeMethodMethod = Get | Post | Put | Patch | Delete | Head | Options | Trace | Connect | Other(String)#

An HTTP request method. The nine standard methods are nullary constructors; Other(name) carries any extension method (PROPFIND, MKCOL, ...) verbatim. Render one for the wire with method_to_string.

typeSchemeScheme = SchemeHttp | SchemeHttps#

The URL scheme a request targets: SchemeHttp (http://) or SchemeHttps (https://).

typeStatusStatus = Status(Int)#

An HTTP status code. Status(n) wraps any integer, so non-standard codes such as Status(418) are representable. Read it with status_code, build the common ones with status_ok, status_not_found, ...; classify with is_success, is_redirect, is_client_error, ...

typeHeaderHeader = Header(String, String)#

One header field: Header(name, value). Names keep the case they were created with; lookups (get_header, get_request_header) compare names case-insensitively. Header lists are plain List(Header) and may hold the same name more than once.

typeUrlErrorUrlError = InvalidScheme(String) | MissingHost | InvalidPort(String) | MalformedUrl(String)#

Why parse_url rejected a URL:

  • InvalidScheme(url): the URL starts with neither http:// nor https://.
  • MissingHost: nothing between the scheme and the first /, : or end.
  • InvalidPort(host_and_port): the text after : is not an integer.
  • MalformedUrl(url): reserved for other malformed input; parse_url does not currently produce it.
typeRequestRequest(body) = Request(Method, Scheme, String, Option(Int), String, Option(String), List(Header), body)#

An HTTP request, generic over its body type: Request(method, scheme, host, port, path, query, headers, body).

port is None when the URL named none (use the scheme's default), query is the raw text after ? without the ?, and body is whatever the caller stores there: Unit for a request built by get/parse_url, a String or Bytes for one built by post. Prefer the accessors (method, host, path, ...) and the set_* transforms over matching on the constructor: its field order is an implementation detail.

typeResponseResponse(body) = Response(Status, List(Header), body)#

An HTTP response, generic over its body type: Response(status, headers, body). Read it with response_status, response_status_code, response_headers, response_body, and get_header.

fnencode_queryencode_query(params : List((String, String))) : String#

Join (key, value) pairs into a query string k1=v1&k2=v2, in order.

Keys and values are inserted VERBATIM: nothing is percent-encoded, so a value containing &, =, #, a space or non-ASCII text produces a different query than intended. Use Uri.encode_query when the pairs are not already encoded.

march> Http.encode_query([])

fnparse_urlparse_url(url : String) : Result(Request(Unit), UrlError)#

Parse an absolute http:// or https:// URL into a GET request with a Unit body and no headers.

The URL is split into host, optional :port, path (default "/") and the raw query after ?. Nothing is percent-decoded and nothing past the split is validated: a #fragment stays part of the path or query, user:pass@ is not recognised, and an IPv6 literal ([::1]) is not supported. The port must be an integer but is not range-checked.

Errors: InvalidScheme for any other scheme, MissingHost for an empty host, InvalidPort for a non-numeric port.

Examples

march> match Http.parse_url("https://api.example.com:8443/v1/users?page=2") do Ok(r) -> Http.host(r) | Err(_) -> "" end
"api.example.com"
march> match Http.parse_url("https://api.example.com:8443/v1/users?page=2") do Ok(r) -> Http.query(r) == Some("page=2") | Err(_) -> false end
true
march> Http.parse_url("ftp://example.com") == Err(InvalidScheme("ftp://example.com"))
true

fnset_headerset_header(req : Request(b), name : String, value : String) : Request(b)#

Prepend a header to req. The name and value are sanitized: NUL, CR, and LF bytes are removed to block CRLF-injection attacks even when the inputs come from untrusted sources (a name or value may become empty). An existing header of the same name is not removed; the new one shadows it for get_request_header.

Examples

march> let req = Result.unwrap(Http.get("http://example.com:8080/a/b?x=1"))
march> Http.get_request_header(Http.set_header(req, "Accept", "text/html"), "accept")
Some("text/html")
march> let req = Result.unwrap(Http.get("http://example.com:8080/a/b?x=1"))
march> Http.headers(Http.set_header(req, "X-Evil", "a\r\nSet-Cookie: x"))
[Header("X-Evil", "aSet-Cookie: x")]
