SessionNode

SessionNode: the Session.Ops network transport. A protocol's @[endpoints] roles run on two or more nodes, one connection per pair (distributed actors, step 4 of specs/progress/2026-09-15-remote-actor-dispatch.md; multiparty routing: specs/progress/2026-09-16-session-node-multiparty-routing.md).

The transport is protocol-independent: Session.Ops speaks in endpoint ids (Int) and encoded messages (Bytes, the generated <P>_Msg.encode), so nothing here names a protocol's constructors and nothing needs generating. Roles are numbered 1..n by the generator (<P>_Msg.role_<R>()) and register returns the role as the endpoint id, so an endpoint id IS its role: emit's to names the remote role, and that is what picks the connection.

Two nodes:

let p = SessionNode.open(conn, "node-a", false, fn ep -> ())   -- after connect_split / accept_split
let s = Session.attach(io, SessionNode.ops(p))
... drive the role to its first suspension ...
SessionNode.serve(p)          -- deliveries, until every peer's endpoint closes
SessionNode.finish(p)

Three or more: one party, then one join per peer. The side that ACCEPTS learns the peer's role from its hello (a listener does not know which role will connect next); the side that connects names it.

let p0 = SessionNode.party(Relay_Msg.role_B(), "node-b", fn ep -> ())
let p1 = SessionNode.accept_from(p0, conn_from_a)
let p  = SessionNode.connect_to(p1, Relay_Msg.role_C(), conn_to_c)

Connect rule, so no configuration and no deadlock: for roles i < j, i listens and j connects.

On the wire, per peer connection (the control/data split): data ACTOR_MSG "SessionNode.Deliver" [to, from, msg], through a NodeQueue (credit-based flow control); "SessionNode.Bye" when an endpoint closes. D27 drains add a fourth Deliver element (1: the sender's epoch is draining, sent only while it is), "SessionNode.Undelivered" [to, from, msg] (a message of [to]'s that [from] drained without consuming, going back) and "SessionNode.Drained" [role] (that role's endpoint drained; its Bye follows once the peer's own end has arrived). control "SessionNode.Hello" [role, pid] (the ACCEPTING side announces first), CREDIT, and a final Bye.

Receiving: a delivery is sent to this node's endpoint actor, whose turn runs the continuation suspend installed. ONE actor per party, whatever the number of peers, so a node's resumptions (and prints) run in mailbox order. "Consumed" for credit is "in the mailbox".

Ordering: each connection is FIFO, but messages from DIFFERENT peers race. A role that receives from A and then from B can see B's delivery first, so suspend takes the role the continuation expects and a delivery from anyone else is parked until the continuation that wants it is installed (pending). suspend's expected role is 0 for "any", which is what a same-thread transport and a two-party session pass.

Failure (specs/todos/2026-09-18-choreography-failure-handling.md, after Maty's affine sessions): a role that fails is CANCELLED. Its node sends a SessionNode.Cancel frame on each data connection, behind everything it already sent, and a dropped connection counts as one at that point in the stream. Messages to a cancelled role are discarded. A local endpoint fails only when its continuation waits on a role that can send nothing more and nothing from that role is still queued; its cancel handler then runs and it is cancelled in turn, which is how failure cascades. Every one of these events goes through the endpoint actor's mailbox, behind the deliveries that preceded it, so the "handle what was already sent" rule holds by construction. A heartbeat on each data connection catches a peer that stops without closing.

The role runner (run, at the end of this file) does all of the above from a role, its peer set and a role->address table, in the order that cannot deadlock; the generated <P>_Run.run_<Role> is its typed front. run_hosted is the same party driving a role hosted in an actor (the generated event API) -- <P>_Run.host_<Role>. Design: specs/progress/2026-09-16-role-runner.md and specs/progress/2026-09-17-actor-hosted-runner.md.

The whole session on this node. handlers holds the installed continuation per local endpoint and waiting the role each expects; pending holds deliveries that arrived before their continuation. meta carries the send seq, the closed flag and the host-gone flag. forward (key "f") is set only for a HOSTED party (run_hosted): a delivery for an awaiting endpoint then goes to the user's actor through it, instead of the installed handler running here, and the actor resumes the endpoint itself (the generated event API).

Failure state: gone maps a peer role that can send nothing more to why ("closed" for a normal close, else the cancellation cause); cancel_hs holds the cancel handler installed with the current continuation (Session.on_cancel); crash_hs the crash continuation installed with it (Session.on_crash), under the endpoint AND the role it is for (crash_key); forward_cancel (key "c") is the hosted party's way to tell its actor that its endpoint was cancelled and forward_crash (key "x") its way to tell it that a role it waits on crashed, so the actor takes the crash branch itself (the crash arrives on the delivery route, as Session.crash_payload, and the generated resume turns it into a Crashed_… event); heard counts heartbeat ticks since a peer's last frame. Our own endpoint's end is in meta: "done" once it closed or was cancelled, and for a cancellation "kind" (see cancel_endpoint), "cancel_role", and why's "cancel_cause".

typeRunErrorRunError = Cancelled(Int, String) | Protocol(Int, String) | HostGone(Int) | Left(String) | Listen(Int, String) | Accept(String) | Connect(Int, String) | NoOffer(Int, String) | AlreadyOffered(Int) | Unauthorized(Int, String)#

Why run ended other than by the protocol reaching its end. A session is not resumable: a peer that is gone ends it for everyone, and run returns rather than hanging on it. What to do next (run again: a fresh party and fresh connections) is the caller's decision.

  • Cancelled(role, cause): this role's endpoint was cancelled because
it was waiting on `role`, which can send nothing more, and nothing
from it was queued. `cause` is the chain back to where the failure
began ("role 3: connection lost"). A peer that fails AFTER this role
no longer needs it does not cancel it: `run` returns `Ok`.
  • Protocol(role, why): that peer sent what cannot be delivered -- a
message the generated code could not decode or one its state cannot
receive (`Session.fail`). Our endpoint is cancelled and the peers are
told.
  • HostGone(ep): a hosted party's actor is gone (crashed or
restarted); its parked session state died with it. The peers are sent
a Cancel.
  • Left(why): this role called leave.
  • Listen(port, why) / Accept(why) / Connect(role, why): wiring.
  • NoOffer(role, why): initiate found no access point that would
take [role] (none registered, all full, all refused, or no answer).
  • AlreadyOffered(role): this node already offers [role] of that protocol.
  • Unauthorized(role, why): certificate mode (step 11b), and this node's
own certificate does not let it offer [role].

typeOfferOffer = { node : Cap(ClusterNode.Live), proto : String, fingerprint : String,#

An offer: what an invitation needs to be answered and its session run. [start] runs one session under a sid, abandoned while still forming once its argument says so. [flags] and [strs] are tables SHARED by every offer of the process, keyed under the offer's [id] (its actor's pid): flags "c<id>" (closing: 1, retiring: 2) and "w<id>/<sid>" for a session its initiator withdrew, strs "r<id>" its route key. fndeliverdeliver(p : Party, ep : Int, from : Int, msg : Bytes) : Int#

Deliver [msg] from role [from] to local endpoint [ep]: run the continuation installed on [ep] with it, then drain whatever parked messages the new continuation is now willing to take. Returns [ep].

A delivery nobody expects yet (no continuation installed, the installed one waits on a different role, or an older message from the same sender is still parked) is parked, not dropped. fninitiateinitiate(io : Cap(IO), node : Cap(ClusterNode.Live), proto : String, fingerprint : String,#

Start one session of protocol [proto] in role [my_role] on the cluster node [node], filling every role in [others] (all the other roles) from the access points that offer it (offer_role). Mints a fresh session id (this node, its creation, a counter: never reused, so a restarted or partitioned node cannot be addressed by an old session), invites one offer per role -- an offer on this node first, then the others -- moving to the next offer on a refusal or no answer, all within the setup time (MARCH_SESSION_CONNECT_MS, 20 s). Only offers whose version may form a session with this one are invited (build step 9): the same fingerprint, an older one [compat] (the generated <P>_Msg.compat_by_role()) accepts for every role at this fingerprint, or an unknown one that decides for itself; a session holds at most two fingerprints. Then runs [body] as run_cluster does. Err(NoOffer(role, why)) if a role could not be filled; the offers that had accepted are withdrawn. The generated <P>_Run.initiate_<Role> supplies the protocol, its role-name table [roles], the role, peers and other roles.

In certificate mode (step 11b) an offer whose node's certificate does not name "Proto.Role:offer" is skipped before any invitation and listed in NoOffer's reasons; each offer checks this node's certificate names "Proto.Role:initiate" for [my_role] and refuses otherwise; and once formed, every role's endpoint must be on a node certified for that role.

fnrunrun(io : Cap(IO), my_role : Int, peers : List(Int), node_id : String, secret : String,#

Run role [my_role] of a session on this node: listen if any peer is above it, connect to every peer below it (ascending, with retry), accept every peer above it, check the party against [peers] (<P>_Msg.peers_<R>()), attach, run [body] to its first suspension, serve, and tear down. [addrs] must hold this role's own entry iff it accepts anyone and an entry for every peer it dials; a missing one panics by role before any socket opens. [node_id] names this node in the handshake and [secret] is the cluster secret every node shares; with MARCH_NODE_CERT set the node runs in certificate mode instead (ClusterNode.auth_from_env, the variables a cluster node reads), and each peer's certificate must let it play the role it announces in [proto] (named by [roles], <P>_Msg.role_names()), else setup fails with Connect/Accept "role P.R is played by <node>: not authorized for P.R". [fingerprint] is the protocol's own (<P>_Msg.fingerprint()): it rides the hello, and a peer whose own differs -- or that is too old to send one at all -- is refused at setup with a Connect/Accept error rather than discovered mid-session as an undecodable message (2026-09-21). "" asks for no check. The generated <P>_Run.run_<Role> supplies the role, its peers, the fingerprint and the typed entry state.

Ok(Session.Finished) when every peer's endpoint closed, Ok(Session.Drained(n)) when the session was ended at a loop boundary by a drain (D27; [n] of this role's messages came back undelivered); else the RunError that ended the session, after the party has been torn down.

A peer is gone when it closes or is cancelled, or when its node's data connection ends -- SWIM declared the node dead ("node <name> dead: <cause>") or the connection was lost. [fingerprint] is the protocol's (<P>_Msg.role_fingerprint(role)): each role registers it beside its endpoint, and a peer that registered a different one, or none (a node built before the check), is refused with Err(Connect(role, why)) before the session forms, as the direct runner refuses it at the hello. fnrun_hostedrun_hosted(io : Cap(IO), my_role : Int, peers : List(Int), node_id : String, secret : String,#

run, with the role HOSTED IN AN ACTOR [host] (its pid as an Int, pid_to_int): the generated event API (Parked_<Role> in the actor's state, await_*/resume) instead of a body. [start] runs once the party is connected, with the session capability: send it to the actor, whose start handler registers and parks. [deliver] is called for every delivery the actor's parked endpoint awaits -- (s, from, msg, ep), what its resume handler takes: send them on. Deliveries are one per suspension, in mailbox order, and one that arrives before the host has re-parked is held for it.

The host is monitored: its Down (a crash, a kill, a supervisor's restart) cancels its role with Err(HostGone(ep)), and the peers are sent a Cancel (they are cancelled in turn only if they were waiting on it). A restarted actor starts Idle and cannot continue a session its predecessor parked; run again for a new one. run_hosted_or also tells the actor itself. The generated <P>_Run.host_<Role> supplies the role and its peers.

fnrun_hosted_orrun_hosted_or(io : Cap(IO), my_role : Int, peers : List(Int), node_id : String, secret : String,#

run_hosted, telling the actor when its endpoint is cancelled: [cancel] gets (s, role, cause, ep) -- the role it was waiting on and why that role is gone. Send it to the actor, whose handler stores the generated <P>_<Role>.cancel(state.parked) (a Closed parked value) and may update the rest of its state; it cannot communicate in the cancelled session.

fnserveserve(p : Party) : Unit#

serve_outcome, panicking if our endpoint was cancelled; the transport's original contract.

fnserve_outcomeserve_outcome(p : Party) : List((Int, String))#

Read deliveries from every peer until each connection has ended: the peer closed, was cancelled, or went away. A peer's failure no longer ends the session for this node at once: it cancels our endpoint only if our endpoint is waiting on that peer with nothing from it queued (Maty's rule; see the module comment), and cancellation then spreads to our other peers as a Cancel frame. Nil if our endpoint ended normally, else (role, cause) for its cancellation. Every resumption runs in this node's endpoint actor, so call it after driving the local role to its first suspension. serve panics on a cancellation; run returns it.
