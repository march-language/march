ChannelServer

ChannelServer module: runtime helpers for Phoenix-style channel processes.

This module provides the building blocks for implementing channel processes using March's actor system. The actual actor declarations must be provided by the application (actors cannot be spawned from closures in March).

A channel process is an actor that:

  1. Receives a ChannelJoin message with topic/params.
  2. Calls the handler's join/3 callback.
  3. On success, subscribes to PubSub for the topic.
  4. Loops receiving ChannelMailbox messages and dispatching to callbacks.
  5. On ChannelLeave, unsubscribes from PubSub and calls leave/3.

Example actor using these helpers (sketch: cfg is a ChannelConfig built with make_config, handle_in the application's callback; the module has no init/handle_in/leave wrappers of its own):

actor MyChannelProcess do
  state = ...

  on ChannelIn(ref, event, payload) ->
    ChannelServer.apply_result(cfg, handle_in(ref, event, payload, state), ref)

  on ChannelBroadcast(topic, event, payload) ->
    ChannelServer.handle_broadcast(cfg, event, payload)
    state

  on ChannelLeave(reason) ->
    ChannelServer.do_leave(cfg, state, reason)
    state
end

PubSub shard actors are similarly declared by the framework user:

actor PubSubShard do
  state = PubSub.new_state()

  on PubSubSubscribe(topic, pid) ->
    PubSub.subscribe_state(state, topic, pid)

  on PubSubUnsubscribe(topic, pid) ->
    PubSub.unsubscribe_state(state, topic, pid)

  on PubSubBroadcast(topic, excl, event, payload) ->
    PubSub.broadcast_to(PubSub.get_subscribers(state, topic), excl, event, payload)
    state
end

Functions

fnapply_resultapply_result(cfg, result, ref)#

Apply a HandleResult: if Reply, send the reply to the transport; return the new state. For Stop, call do_leave. Returns the new channel state. A Reply(status, payload, st) is pushed to the transport as ChannelPush("phx_reply", serialize(reply_msg(join_ref, ref, topic, status, payload))). Stop runs do_leave but sends the client no phx_close or phx_error. Must be called from within an actor handler (requires actor runtime).

let state2 = ChannelServer.apply_result(cfg, Channel.reply("ok", "{}", state), ref)

fndo_joindo_join(cfg, topic, params_json)#

Perform the join handshake. Calls join_fn(topic, params_json, socket); on Ok(state) subscribes the calling process (self()) to topic in the config's shard and returns JoinOk(state), on Err(reason) returns JoinErr(reason) without subscribing. Sends no reply to the client. Must be called from within an actor handler (requires actor runtime).

match ChannelServer.do_join(cfg, "room:lobby", "{}") do
  ChannelServer.JoinOk(st) -> st
  ChannelServer.JoinErr(why) -> ...
end
fndo_leavedo_leave(cfg, st, reason_str)#

Perform the leave teardown. Unsubscribes the calling process from the socket's topic in the config's shard, then returns leave_fn(reason_str, st, socket). Must be called from within an actor handler (requires actor runtime).

ChannelServer.do_leave(cfg, state, "user_left")

fnselect_shardselect_shard(shards, topic)#

Select the shard pid for topic from a list of shard pids. Uses PubSub.topic_shard for consistent routing (the same topic always picks the same index for the same list length on the same platform). Panics (division by zero) if shards is empty.
