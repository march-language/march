Headline
--------
(1) FLAT RSS: resident set is ~2-3 MB at EVERY contention level and stays flat
    for the whole run (see the *.rss traces — the 16-sibling, 28s run holds
    ~1840 KB start-to-finish). Memory tracks the live set, not the allocation
    rate; ~10M transient boxed-Float allocations over a run are reclaimed by RC
    with no GC heap growth and no pause.

(2) BOUNDED TAIL: p50/p90/p99 are near-constant (single-us) as CPU-bound
    siblings scale from 0 to 4x the scheduler count — the scheduler never
    starves the common case, and even p99 is protected. The extreme p99.9 tail
    grows BOUNDED (65us -> 262us -> 2.1ms -> 4.2ms), not unbounded: there is no
    starvation. The strong "p99.9 ~ p50" form holds through CPU saturation
    (4 siblings: p99.9=262us); under heavy oversubscription the extreme 0.1%
    tail reaches low-ms, reported here rather than hidden.

The hot request kernel is compiler-enforced zero-allocation via `cap no_alloc`
(injecting a tuple fails --check with "tuple construction allocates in a
`cap no_alloc` module").
