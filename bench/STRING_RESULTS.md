> **Peak RSS and peak-live figures are currently contaminated by two compiled-only RC leaks**
> found by this harness: `x ++ "literal"` leaks a fresh copy of the literal per evaluation,
> and a hand-written recursive walk over a `List(String)` never frees the elements
> (`string_split_large`: 9,000,126 string allocations, 3 frees). Memory numbers therefore
> measure leaked memory as much as legitimate working set, and **must not be used to justify
> a representation change until those leaks are fixed** — the fix is an RC correction, not a
> new string representation. Timing, allocation counts and copy volumes are unaffected.
