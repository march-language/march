Session

DEPRECATED: This module has moved to the Bastion framework package. Add bastion as a dependency in your forge.toml and import Session from there. This stdlib copy will be removed in a future march release.

Session module: cookie-backed and Vault-backed session middleware.

Provides two session backends:

:cookie — The full session is stored as a signed, base64-encoded payload in a browser cookie. No server-side state is required. Suitable for small sessions (< ~4 KB of data).

:vault — Only a random session ID is stored in the browser cookie. The actual session data lives in a Vault table under that ID. Suitable for larger or sensitive sessions.

Typical pipeline:

conn |> Session.load(:cookie) -- load / create session from request cookie |> CSRF.ensure_token() -- CSRF token usable alongside session |> MyApp.Router.route() |> Session.save() -- write session back to Set-Cookie header

Session data is a flat key->value store where values are Strings. Flash messages are a special sub-store: they are written in one request and auto-cleared the next time they are read.

Cookie signing uses HMAC-SHA256 with the `secret_key_base` from Config. Tampered or missing cookies start a fresh session.

Functions

fnloadload(conn, backend)

Load or create a session from the request cookie.

`backend` is `:cookie` (session data in a signed browser cookie) or `:vault` (session data stored in Vault; only an opaque session ID travels in the cookie).

conn |> Session.load(:cookie) |> MyApp.Router.route() |> Session.save()

On the first visit a fresh empty session is created. On subsequent visits the session is loaded and the cookie signature is verified. A tampered or missing cookie silently starts a fresh session.

The `:vault` backend stores session data in the `session_store` Vault table, keyed by a 32-byte random session ID. This is appropriate when session data is large or must never leave the server.

conn |> Session.load(:vault) |> MyApp.Router.route() |> Session.save()

fnsavesave(conn)

Persist the current session back to a `Set-Cookie` response header.

For the `:cookie` backend: serialises the session data, signs it with HMAC-SHA256, and sets the `Set-Cookie` response header.

For the `:vault` backend: writes the session data to Vault and sets a `Set-Cookie` header containing only the session ID.

Call this *after* the request handler and *before* (or immediately after) `HttpServer.send_resp`.

conn |> Session.load(:cookie) |> MyApp.Router.route() |> Session.save()

Flash entries that were read during this request are automatically removed before saving.

fnsave_with_optssave_with_opts(conn, opts)

Like `Session.save/1` but accepts cookie options.

`opts` is a `List((String, String))`. Recognised keys:

- `"path"` — cookie path (default `"/"`) - `"max_age"` — max-age in seconds as a string (omit for session cookie) - `"same_site"` — `"Lax"`, `"Strict"`, or `"None"` (default `"Lax"`) - `"http_only"` — `"false"` to disable HttpOnly (default: enabled) - `"secure"` — `"true"` to add the Secure flag

conn |> Session.save_with_opts([("max_age", "86400"), ("secure", "true")])

fngetget(conn, key)

Get a value from the session by key. Returns `Some(value)` or `None`.

let user_id = Session.get(conn, "user_id") -- Some("42") or None

Flash message keys are stored with a `_flash_` prefix; use `Session.get_flash/2` to read them.

fnputput(conn, key, value)

Set a value in the session. Values must be Strings.

conn = conn |> Session.put("user_id", "42") conn = conn |> Session.put("role", "admin")

Changes are in-memory until `Session.save/1` is called.

fndeletedelete(conn, key)

Remove a key from the session. No-op if the key does not exist.

conn = conn |> Session.delete("user_id")

fnclearclear(conn)

Clear all session data, including flash messages.

conn = conn |> Session.clear()

fnput_flashput_flash(conn, key, value)

Write a flash message under `key`. Flash messages survive exactly one request after being written — they are removed the next time they are read via `Session.get_flash/2`.

Typical post-redirect-get usage:

-- In the POST handler (before redirect): conn |> Session.put_flash("notice", "Profile updated.") |> Session.save()

-- In the next GET handler (after redirect): match Session.get_flash(conn, "notice") do (conn1, Some(msg)) -> render_notice(conn1, msg) (conn1, None) -> render(conn1) end

fnget_flashget_flash(conn, key)

Read a flash message and mark it for removal on the next `Session.save/1`.

Returns `(updated_conn, Some(message))` if the key exists, or `(conn, None)` if absent.

match Session.get_flash(conn, "notice") do (conn1, Some(msg)) -> render_notice(conn1, msg) (conn1, None) -> render(conn1) end

fninitializedinitialized(conn)

True if `Session.load/2` has been called on this Conn.

if Session.initialized(conn) do ... end

fnallall(conn)

Return all session data as a `List((String, String))`.

Includes flash keys (prefixed `_flash_`). Useful for debugging.

let all = Session.all(conn)
